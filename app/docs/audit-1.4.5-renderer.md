## 1. 업무 보드 — 전부 그리고 전부 다시 그림 (BoardPage.tsx)
- 확인: `BoardPage`는 `tasks` 전체를 구독하고(46행), 칸마다 `filter→sort`로 카드를 만들어 **완료 칸도 제한 없이** 전부 그린다(169행). 카드 컴포넌트 `TaskCard`는 `memo`가 없다.
- 확인: 메인이 보내는 현황은 매번 새 객체로 통째로 들어오므로(`store.ts setSnapshot`), 카드가 1개만 바뀌어도 모든 카드가 다시 그려진다. 강백엔 점검 1번(2초마다 재전송)을 고치기 전에는 가만히 있어도 반복될 수 있다.
- 확인: 칸 안 카드마다 `tasks.find`(부모 찾기)가 있어 카드 수가 N이면 N×N에 가깝다(138~143행). 655건이면 약 43만 번 비교.
- 제안(겉모습 동일):
  1. `TaskCard`를 `memo`로 감싸고, 카드가 받는 값(task 객체)이 안 바뀌면 건너뛰게 한다. 단, 메인이 매번 새 객체를 주면 효과가 없으므로 **스냅샷에서 안 바뀐 task는 이전 객체를 재사용**하는 처리를 `setSnapshot`에 한 곳 넣는다(id·updatedAt 비교).
  2. 부모 찾기는 `Map` 한 번 만들어 쓴다.
  3. 완료 칸은 `content-visibility:auto`(StaffPanel 로그줄에 이미 쓰는 방식 재사용)로 화면 밖 카드의 배치·그리기를 건너뛴다. 가상 스크롤 같은 새 구조는 넣지 않는다 — 화면이 달라질 위험이 있고 이 규모에서 과하다.
- 장점: 변경이 보드 파일 + 스냅샷 한 곳에 머문다. 단점: 이전 객체 재사용 규칙이 추가돼 "왜 같은 객체인가"를 주석으로 남겨야 한다.
- 검증: (전) React DevTools Profiler로 카드 갱신 1건 때 렌더된 TaskCard 수 기록 → (후) 변경 카드 수만큼인지. 단위 테스트: "안 바뀐 task는 같은 참조" 1개.
- 추천: **고침**. 위험 중간인 이유는 이전 객체 재사용이 잘못되면 화면이 갱신 안 되는 버그가 되기 때문(updatedAt만 믿지 말고 내용 비교 필요).

## 2. 단체방 긴 대화 (ChatPage.tsx)
- 확인: 대화는 최대 500건까지 메모리에 둔다(`store.ts CHAT_MAX`). 화면은 `lines.map`으로 전부 그린다(419행). `Bubble`에는 `memo`가 있다. 직원 찾기가 줄마다 `staff.find`(O(직원수))다(`sender`).
- 확인: 직원 로그 목록(StaffPanel)은 이미 `content-visibility`와 `memo`로 최적화돼 있다 — 단체방만 빠져 있다.
- 추정: `Bubble`에 넘기는 `mentions`·`pendingApproval` 참조가 스냅샷마다 바뀌면 `memo`가 무력화된다. `mentions`는 `useMemo`지만 `hired` 키가 직원 변동에 흔들리는지 실측 필요.
- 제안: (a) 줄 래퍼에 StaffPanel과 같은 `content-visibility:auto` 클래스 적용, (b) 직원 찾기를 이미 있는 `staffById` 계열 `Map`으로, (c) `Bubble`에 넘기는 값 참조 안정성 확인 후 필요한 곳만 `useMemo`. 새 컴포넌트·가상 스크롤은 만들지 않는다.
- 주의: `content-visibility`는 스크롤 점프(최하단 자동 이동·검색 하이라이트·답장 인용 이동)에 영향을 줄 수 있어 **그 세 동작 확인이 필수**다.
- 추천: **작게 고침**(a·b만). 효과는 실측 후 판단하고, 눈에 띄는 차이가 없으면 되돌린다(기획서 원칙).

## 3. 카드마다 직원 목록 구독 (BoardPage `TaskCard` 414·206행 등)
- 확인: 카드마다 `useOffice(useShallow(s => s.staff.filter(...)))`와 `tasks.filter(parentId)`를 따로 실행한다. 카드 655개면 구독 655개가 스냅샷마다 각자 계산한다.
- 제안: 직원 목록은 보드 위에서 한 번 계산해 내려주거나, 카드 안 선택자를 `id`만 보는 가벼운 값으로 줄인다. 하위 카드는 1번의 `Map`(부모→자식)로 한 번에.
- 추천: 1번과 같은 작업에서 처리.

## 4. 화면이 안 보일 때도 도는 반복 작업
- 확인(이미 잘 된 곳): `status.ts`(숨김 때 멈춤), `motionPlayer.ts`(숨김 때 건너뜀), PetCharacter(숨김 감지).
- 확인(숨김 처리 없음): `PlanUsageCard.tsx:37` 1분마다, `Tutorial.tsx:307` 1초마다(튜토리얼 중에만), `CoachTour.tsx:115` 300ms마다(둘러보기 중에만), `OfficeMap.tsx:34` 밤낮 확인, `officeStage.ts:337` 배치 타이머, `OfficeMap.tsx:234` 그리기 루프(rAF).
- 판단: 1초·300ms는 해당 화면이 열려 있을 때만 켜지므로 낭비가 작다. 실제로 의미 있는 후보는 `useStaffRecord.ts:31`(외부 직원 기록 새로고침 주기), `useConnectData.ts` 3개(연결 화면 열린 동안), `PetPanel.tsx:992`의 새로고침. 이들이 창이 숨겨진 동안에도 도는지는 **코드만으론 확정 못 함(추정)**.
- 제안: 공통 헬퍼 `status.ts`의 "보일 때만 반복" 패턴을 `useVisibleInterval`로 한 번 빼서 위 3~4곳에만 적용. 새 추상화는 이 3~4곳이라는 구체적 사용처가 있어서만 만든다.
- 측정: 활동 상태 보기로 창 숨긴 뒤 CPU %, 또는 Chrome 도구 Performance에서 타이머 호출 수.
- 추천: **useStaffRecord·PetPanel만** 고침. 나머지는 눈에 띄는 효과가 없어 건드리지 않음.

## 5. 큰 자산
- 확인(크기): 폰트 Galmuri 3개 합 약 1.2MB(woff2 이미 압축), 번들 최대 조각 `decor` 1.4MB(Phaser 포함, 사무실 화면을 열 때만 읽음), 메인 `index` 1.06MB, `AppUpdate` 0.5MB.
- 확인: `main.tsx`가 `import()`로 App·반려동물 창을 늦게 읽고, 사무실 화면(Phaser)은 별도 조각이다. 시작 때 Phaser를 먼저 읽는 증거는 못 찾았다.
- 확인 못 함: 조각을 실제로 몇 개 먼저 읽는지(시작 시간 실측 필요). 폰트는 `font-display` 설정과 미리 읽기 여부 미확인.
- 추천: **보류**. 이미지 파일(png/jpg) 100KB 이상은 소스에 없었다.

## 6. 설치 파일의 안 쓰는 패키지
- 확인: dependencies 16개 모두 소스에서 쓰임(gifenc·qrcode-generator·remark-*·radix·cva·tailwind-merge 각 1곳 이상). 안 쓰는 패키지는 못 찾았다.
- 확인: 맥 설치본 `app.asar` 18MB, 나머지 대부분은 `codex` 260MB·`claude` 실행 파일(asar 밖 263MB)로 기능에 필요하다. `out` 폴더 11GB는 개발 PC의 빌드 찌꺼기이며 배포물이 아니다(정리는 디스크 정리 문제).
- 확인 못 함: 번들 안에서 패키지별 실제 점유(시각화 도구 미사용). `zod`·`react-markdown`이 메인/화면 양쪽에 중복 포함되는지는 미확인.
- 추천: **건드리지 않음**. 줄일 여지는 codex 포함 방식뿐인데, 기능 영향이 커 이번 범위 밖.

## 제외한 것
- 겉모습·기능이 바뀌는 것(보드 칸 접기·"더 보기" 버튼으로 카드 수 줄이기, 오래된 대화 자르기 UI 등). 이런 변경은 효과가 커도 이번 범위에서 뺐다. 대표님 판단이 필요하면 별도 제안으로.

## 2단계 추천 범위 (대표 미확인)
1+3(보드) → 2(단체방, 작게) → 4(두 곳). 약 1.5일. 7번은 선택.
선행 조건: 강백엔 점검 1번(스냅샷 통째 재전송)을 먼저 고치면 화면 쪽 이득이 더 커진다.
이들 모두 **전/후 렌더 횟수를 먼저 재서**, 차이가 없으면 되돌린다.

## 측정 방법(2단계 착수 시)
1. 개발 모드로 켜고 React DevTools Profiler: 카드 1건 갱신 때 렌더된 컴포넌트 수.
2. 단체방 500건 상태에서 스크롤 중 프레임(Performance 탭).
3. 창을 숨긴 뒤 1분간 타이머 호출 수.
