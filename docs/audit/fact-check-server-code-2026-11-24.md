# 1단계 사실 확인 — 공개 서버 + 이 맥 코드 (2026-11-24, 정리드)

> 표의 "확인" = 직접 조회·코드 열람으로 확인. "미확인" = 이번에 볼 수 없었음. "추정" = 근거는 있으나 직접 보지 못함.

## 먼저 알아야 할 점 (회의 전제와 다름)
회의 우선순위 ①은 **두 프로젝트를 하나로 섞어** 적었습니다.

| 회의에 나온 것 | 실제로 있는 곳 |
|---|---|
| 공개 멀티 서버, 멀티 접속, 크리스마스 노출 | **관악산 게임**(웹, `~/gwanak-hiking`, 사이트 engchoon.github.io/ai-office-world) |
| 맥·윈도우 빌드, APK, versioning.md | **AI Office 앱**(`~/flitto/poc/claude-office`) |

- 관악산 게임에는 APK·맥·윈도우 빌드가 없습니다(순수 웹). 확인
- AI Office 앱에는 여러 사람이 인터넷으로 붙는 공개 서버가 없습니다. 각 PC가 자기 서버를 띄우고 휴대폰·다른 PC만 붙습니다. 확인
- 그래서 "공개 서버 버전 = 맥·윈도우·APK 버전" 비교는 성립하지 않습니다. 대상 정리가 필요합니다(대표 확인 요청).

### 대표 결정 (11-24, 결재 질문으로 직접 답함)
- 대상: **둘로 나눠 진행** — 관악산 게임 = 공개 서버 동기화·크리스마스·멀티 접속 점검 / AI Office 앱 = 맥·윈도우·APK 버전 일치 점검. 판정도 따로.
- 공개 서버: **`/version`을 넣은 뒤 대표가 그 맥에서 git pull 후 다시 켬**. 그 전까지 공개 서버 판정은 blocked(옛 코드).

## (2) 이 맥 코드
| 항목 | 관악산 게임 | AI Office 앱 | 상태 |
|---|---|---|---|
| 기존 요청 반영 | 정상 앞 계단 제거 코드 주석·처리 있음, 일시정지 UI 없음(소리 멈춤은 탭 숨김용만) | 이번 범위의 특정 요청 목록 없음 | 코드 검색으로 확인, **화면 캡처 대조는 안 함** |
| APK 구조 | 없음(웹) | Kotlin 셸 + WebView. PC 화면을 원격으로 띄우지 않고 **APK 안에 넣은 모바일 화면**을 열고, 셸이 PC를 호출. QR·12자리 코드, LAN·외부·Tailscale, 인증서 고정 | 확인 |
| 안드로이드 알림 현황 | — | FCM 없음(주석 "2단계"). **15분마다 PC에 묻는 방식**, 수십 분 늦을 수 있음. 실시간 스트림은 화면 볼 때만 | 확인 |
| 계절·이벤트 정의 | 계절 기준 `src/season.js` 1곳. 하지만 계절 목록을 다시 적은 곳 3곳, 체험 목록 3곳(허브·프로토콜·ui-frame). 서버는 프로토콜 파일을 같이 씀. **크리스마스는 날짜 제한 없이 상시 열림** | 시즌 `economy.ts` 1곳(크리스마스 12-01~12-31 상점 품목). 중복 없음 | 확인 |
| 버전 표시 영역 | 화면에 버전 없음. 의견 보내기 창 「빌드」 줄(빌드 날짜)만. package.json 0.1.0은 안 씀 | PC: 업데이트 페이지·새 소식·사이드바 배지(package.json 한 곳에서). 폰: 설정 화면에 PC·앱 버전. `/version`은 없고 `/v1/status`의 `serverVersion` | 확인 |

## 회의안에 미치는 영향 (정리드 의견, 대표 미확인)
- "버전을 빌드 때 한 곳에서 주입·화면은 읽기만"은 **AI Office 앱은 이미 그렇게 돼 있음**. 관악산 게임은 빌드 날짜만 있어 새로 정해야 함.
- 공유 정의 파일 보류 조건("정의 중복 확인 시")은 **관악산 게임에서 이미 충족**(계절·체험 목록 중복). 한쪽만 바뀐 전례는 아직 못 찾음.
- 안드로이드 알림 난이도 재평가: 지금 15분 확인 방식이 있어 "늦은 알림"은 재활용 가능, "즉시 알림"은 FCM 새로 붙여야 해 난이도 높음.
- 크리스마스 노출 점검은 관악산 게임이라면 날짜와 무관(상시). 다만 공개 서버가 옛 코드라 최신 크리스마스 변경분 반영 여부는 서버 재시작 전엔 판정 불가.
