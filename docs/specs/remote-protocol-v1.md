# 원격 프로토콜 v1 규격

> 작성: 김버전(버전관리) · 2026-10-22 · 상위 업무 "회의 결과: 클로드 오피스 안드로이드 앱 개발" 2/9단계
> 기준: `docs/specs/android-mvp.md`(2026-10-22 갱신본) 5절·8절. 필드는 `app/src/shared/types.ts`에서 골랐다. **코드는 고치지 않았다.**
> 읽는 사람: 정리드(PC 서버 구현), 임안드(앱 구현), 한리뷰(보안 리뷰), 오큐에이(검증). 이 문서가 PC와 앱이 함께 보는 **계약**이다. 기획서와 다르면 이 문서를 먼저 고치고 구현을 맞춘다.

## 1. 한눈에
| 항목 | 값 |
|---|---|
| 전송 | HTTPS(자체 서명 인증서, TLS 1.2 이상). 평문 HTTP는 응답하지 않는다 |
| 형식 | JSON, UTF-8, `Content-Type: application/json; charset=utf-8` |
| 경로 | 항상 `/v1/…`. 아래 4종 외는 모두 404 |
| 인증 | `Authorization: Bearer <token>` (7절) |
| 시각 | 에포크 밀리초 정수(`types.ts`와 같음). 필드 이름 끝은 `At` |
| id | 문자열이며 **앱은 내용을 해석하지 않는다**(만들거나 자르지 않고 받은 그대로 돌려준다) |
| 기본 상태 | 원격 기능은 **기본 꺼짐**. 꺼져 있으면 포트가 닫혀 있어 연결 자체가 안 된다(응답 코드 없음) |

엔드포인트 4종
| # | 메서드·경로 | 기능 |
|---|---|---|
| 1 | `GET /v1/status` | 상태 조회(연결 확인 겸용) |
| 2 | `GET /v1/decisions` | 대기 결정 목록 |
| 3 | `POST /v1/decisions/{id}` | 결정 응답(결재 승인·반려, 질문 답변, 기획 확인) |
| 4 | `POST /v1/instructions` | 지시 전송 |

## 2. 버전 표기와 호환 규칙
### 2-1. 표기
- 프로토콜 버전은 **정수 `1`**. 세 곳에 쓴다: 경로 `/v1/`, 모든 응답 본문의 `protocolVersion`, QR의 `v`.
- 데스크톱·안드로이드 버전(SemVer)과는 **별개**다(9절).

### 2-2. v1을 유지하는 변경 (하위 호환)
- 응답·요청·QR에 **선택 필드 추가**, 새 오류 코드 추가, 새 `kind`·`status` 값 추가, 새 엔드포인트 추가.
- 위 변경은 버전을 올리지 않는다. 그래서 양쪽 모두 아래를 지켜야 한다.

### 2-3. 모르는 것은 무시한다
| 받는 쪽 | 규칙 |
|---|---|
| 앱(응답·QR을 받음) | **모르는 필드는 무시.** 모르는 `status`는 "알 수 없음"으로 표시. 모르는 결정 `kind`는 "PC에서 확인해 주세요"로 표시하고 응답 버튼을 숨김. 모르는 오류 `error` 값은 HTTP 상태 코드로 처리 |
| PC 서버(요청을 받음) | **모르는 요청 필드는 무시.** 필요한 필드가 없거나 타입이 틀리면 `400 invalid_request` |

### 2-4. 버전이 맞지 않을 때
v2 이상이 생긴 뒤의 규칙이다(v1 서버·앱만 있는 지금은 지켜 두기만 한다).
| 상황 | 응답·동작 |
|---|---|
| 앱이 `/v2/…`를 부르는데 서버는 v1만 지원 | `426 protocol_unsupported`, 본문에 `supported: [1]`. 앱이 v1을 쓸 수 있으면 `/v1/`로 다시 요청, 못 쓰면 "PC의 Claude Office를 업데이트하세요" |
| 앱이 `/v1/…`를 부르는데 서버가 v1을 더는 지원하지 않음 | `426 protocol_unsupported`, `supported: [2]` 등. 앱은 "앱을 업데이트하세요" |
| QR의 `v`가 앱이 아는 최댓값보다 큼 | 앱은 **연결 시도 없이** "앱 업데이트 필요"를 안내 |
| 응답의 `protocolVersion`이 앱이 아는 값보다 큼 | 앱은 응답을 쓰지 않고 "앱 업데이트 필요" |
- `426`은 **인증보다 먼저** 판단한다(토큰 없이도 업데이트 안내를 줄 수 있게). 이때 비밀 정보는 담지 않는다.
- 판단 순서(서버): ① TLS → ② 경로의 버전(426) → ③ 잠금 확인(`auth_locked`) → ④ 인증 → ⑤ 경로·메서드(404·405) → ⑥ 본문 검증(413·415·400) → ⑦ 처리.

### 2-5. v2로 올리는 경우 (하위 호환이 깨질 때만)
필드 삭제·의미 변경·필수 필드 추가·`id` 규칙 변경. v2를 낼 때 서버는 한동안 v1과 v2를 함께 제공한다.

## 3. 공통 형식
### 3-1. 성공 응답
모든 성공 본문 최상위에 `protocolVersion`(정수)과 `serverTime`(PC 시각)이 들어간다. 앱은 `serverTime`으로 시계 차이를 보정해 "N분 전"을 표시한다.

### 3-2. 오류 응답
```json
{
  "protocolVersion": 1,
  "error": "auth_locked",
  "message": "인증 실패가 많아 잠시 잠겼어요",
  "retryAt": 1790000000000
}
```
- `error`: 아래 8절의 코드. **앱 로직은 `error`(없으면 HTTP 상태)로만 분기**한다.
- `message`: 사람이 읽는 한국어 설명. 화면에 그대로 써도 되지만 로직에 쓰지 않는다. 토큰·경로·내부 오류 문장은 넣지 않는다.
- `retryAt`: `auth_locked`에만. 에포크 밀리초.
- `retryAfterSec`: `429`·`503`에만. 응답 헤더 `Retry-After`(초)와 같은 값.

### 3-3. 크기 제한
요청 본문 최대 16KB. 지시 글자 수 1~4000자. 결정 응답의 `feedback` 최대 2000자. 질문 답 하나 최대 1000자.

본문이 16KB를 넘을 때는 두 갈래다.
| 요청 | 서버 동작 | 앱이 받는 것 |
|---|---|---|
| `Content-Length`로 16KB 넘는 길이를 밝힘 | 본문을 **읽지 않고** `413 payload_too_large`(JSON)를 보낸 뒤 `Connection: close`로 연결을 닫는다 | 413 응답 |
| 길이를 밝히지 않고(`Transfer-Encoding: chunked`) 보내다 16KB를 넘김 | 더 받지 않고 **소켓을 바로 끊는다**(응답 없음) | 연결 끊김 오류 |
- 앱은 지시 글자 수를 미리 검사하므로 정상 사용에서는 둘 다 나오지 않는다.

### 3-3-1. 연결 한도
| 항목 | 값 | 넘으면 |
|---|---|---|
| 한 주소(IP)에서 동시에 열 수 있는 연결 | **8개** | 9번째부터는 TLS 전에 바로 끊는다 |
| 서버 전체 동시 연결 | **64개** | 운영체제가 받지 않는다(연결 끊김) |
| TLS 핸드셰이크 | **5초** 안에 끝내야 함 | 끊는다 |
| 요청 헤더 / 요청 전체 | 10초 / 15초 | 끊는다 |
- 한 곳이 연결을 잔뜩 붙들어도 다른 곳의 휴대폰은 계속 붙을 수 있게 하려는 한도다. 앱은 요청마다 연결을 새로 열거나 짧게 유지하면 된다. v2 앱은 이벤트 스트림(SSE) 1~2개에 동시 호출 여러 개를 열므로 8개로 둔다(앱도 한 PC로 가는 동시 요청 수를 줄여 8개를 넘지 않게 한다 — `maxRequestsPerHost`).

### 3-4. 숫자 자료형
JSON 숫자는 모두 **0 이상의 정수**다(소수 없음). 받는 쪽이 쓸 자료형과 범위는 아래와 같다. 범위를 넘는 값은 서버가 보내지 않는다.

| 필드 | 자료형 | 범위 | 앱(Kotlin) |
|---|---|---|---|
| `protocolVersion`, QR `v` | 32비트 정수 | 1 이상 | `Int` |
| `avatar` | 32비트 정수 | **0 이상 7,776,024 미만** (아바타 번호 24개 + 생김새 조합 7,776,000개). 2^31−1을 넘지 않는다 | `Int` |
| `port` | 32비트 정수 | 1024~65535 | `Int` |
| `pendingDecisions`, `summary.*`, `total` | 32비트 정수 | 0 이상 | `Int` |
| `serverTime`, `statusSince`, `createdAt`, `retryAt` | **64비트 정수** | 에포크 밀리초. 0 이상 2^53 미만 | `Long` |
| `retryAfterSec` | 32비트 정수 | 1 이상 | `Int` |

- `avatar`는 생김새 번호다. 사무실 밖에서 데려온 직원은 원래 세션 해시(최대 2^32 근처)를 번호로 쓰지만, 서버가 **같은 생김새의 가장 작은 번호**로 바꿔 보낸다(그림은 같다). 앱은 이 값을 그리기에만 쓰고 직원을 구별하는 데 쓰지 않는다(구별은 `id`).
- 앞으로 32비트 필드의 범위를 넓혀야 하면 새 필드를 추가한다(2-2절). 기존 필드의 자료형은 바꾸지 않는다.

## 4. 인증 헤더
```
Authorization: Bearer <token>
```
- 토큰은 **URL·쿼리·로그·알림 본문에 넣지 않는다.** 서버는 헤더에서만 읽는다.
- 토큰 형식: 무작위 32바이트를 base64url로 쓴 43자(패딩 없음).
- 서버는 토큰 **해시**만 저장하고 **상수 시간**으로 비교한다.
- 헤더가 없거나 `Bearer`가 아니거나 토큰이 틀리면 `401 unauthorized`. 이 중 **실패 횟수에 세는 것은 "`Bearer <base64url>` 형식은 맞는데 토큰이 틀린" 요청뿐**이다(7절). 헤더가 없거나 형식이 틀린 요청은 세지 않는다 — 토큰을 맞혀 보는 시도만 막고, 엉뚱한 스캐너가 주인을 잠그지 못하게.
- 쿠키·세션은 쓰지 않는다. 요청마다 헤더를 보낸다.

## 5. 엔드포인트
공통: 아래 요청·응답 예시의 `…`는 생략 표시일 뿐 실제 값이 아니다.

### 5-1. `GET /v1/status` — 상태 조회
연결 확인에도 쓴다(QR로 처음 붙을 때 이 호출이 성공하면 연결 완료). 본문 없음.

응답 `200`
```json
{
  "protocolVersion": 1,
  "serverTime": 1790000000000,
  "serverVersion": "0.8.0",
  "staff": [
    {
      "id": "…",
      "name": "정리드",
      "role": "팀장",
      "avatar": 3,
      "status": "working",
      "activity": "회의 결과 카드 정리 중",
      "statusSince": 1789999000000,
      "pendingDecisions": 1
    }
  ],
  "summary": { "working": 1, "waiting": 1, "error": 0, "idle": 4, "offline": 0 }
}
```
| 필드 | 타입 | 원본(`types.ts`) | 설명 |
|---|---|---|---|
| `serverVersion` | string | 앱 버전 | 데스크톱 버전(표시·호환 안내용) |
| `staff[].id` | string | `Staff.id` | |
| `staff[].name` | string | `Staff.name` | |
| `staff[].role` | string | `Staff.role` | 직무 |
| `staff[].avatar` | integer (32비트, 0 이상 7,776,024 미만 — 3-4절) | `Staff.avatar`를 같은 생김새의 가장 작은 번호로 바꾼 값 | 아바타 번호(꾸미기 값은 보내지 않음) |
| `staff[].status` | string | `StaffStatus` | `idle`·`working`·`waiting`·`offline`·`error`. `waiting` = 확인 필요 |
| `staff[].activity` | string | `Staff.activity`를 서버가 줄인 값 | 지금 하는 일. 세 가지 중 하나만 온다: 도구를 쓰는 중이면 **`<도구 이름> 실행 중`**(예: `Bash 실행 중`, MCP 도구는 끝 이름 — 명령 전문·파일 경로 같은 인자는 보내지 않는다), 오류 상태면 **`오류가 났어요`**, 그 밖의 글(직원이 쓴 문장·내부 안내)은 내용 없이 **`작업 중`**. 하는 일이 없으면 빈 문자열 |
| `staff[].statusSince` | integer (64비트, 에포크 밀리초) | `Staff.statusSince` | "12분째" 계산용 |
| `staff[].pendingDecisions` | integer | `Staff.approvals.length` + 이 직원의 대기 중 기획 확인 수 | 결정 대기 수 |
| `summary` | object | 위 목록에서 계산 | 상태별 인원 |
- **고용 직원(`kind: 'hired'`)만** 담는다. 외부 직원(`external`)은 담지 않는다.

### 5-2. `GET /v1/decisions` — 대기 결정 목록
본문 없음. 응답 `200`
```json
{
  "protocolVersion": 1,
  "serverTime": 1790000000000,
  "total": 2,
  "decisions": [
    {
      "id": "…",
      "kind": "approval",
      "staffId": "…",
      "staffName": "한리뷰",
      "summary": "파일 수정: docs/specs/x.md",
      "toolName": "Edit",
      "createdAt": 1789999500000
    },
    {
      "id": "…",
      "kind": "question",
      "staffId": "…",
      "staffName": "이디자",
      "summary": "어떤 색으로 할까요?",
      "questions": [
        {
          "question": "어떤 색으로 할까요?",
          "header": "색상",
          "options": [{ "label": "파랑", "description": "차분해요" }],
          "multiSelect": false
        }
      ],
      "createdAt": 1789999600000
    }
  ]
}
```
공통 필드
| 필드 | 타입 | 원본 | 설명 |
|---|---|---|---|
| `id` | string | 결재 id 또는 기획 카드 id를 서버가 감싼 값 | **불투명.** 종류가 달라도 겹치지 않는다. 결정 응답 경로에 그대로 쓴다 |
| `kind` | string | — | `approval`·`question`·`plan`. 모르는 값이 오면 2-3절대로 처리 |
| `staffId`·`staffName` | string | `Approval.staffId`, `Staff.name` | |
| `summary` | string | `Approval.summary` | 최대 2000자로 자른다. 명령·파일 경로가 들어갈 수 있다 → **화면에만 쓰고 로그·알림 본문에는 쓰지 않는다**(기획서 D8) |
| `isTruncated` | boolean | — | **잘렸을 때만** `true`로 들어간다(`approval`·`question`은 `summary`가 2000자를 넘을 때, `plan`은 `spec`이 10000자를 넘을 때). 앱은 "일부만 보여요 — PC에서 전체를 확인해 주세요"를 표시한다. 잘린 `approval`은 원격에서 **승인할 수 없다**(5-3). **`question`의 `isTruncated`는 `summary`만 잘렸다는 뜻이며 답변은 막지 않는다**(질문 문장과 선택지는 `questions[]`에 자르지 않고 담는다) |
| `createdAt` | integer | `Approval.createdAt`, 기획은 `TaskPlan.proposedAt` | |

종류별 추가 필드
| kind | 추가 필드 | 원본 |
|---|---|---|
| `approval` | `toolName`(string) | `Approval.toolName`(질문이 아닌 결재) |
| `question` | `questions[]`: `question`·`header`·`options[]{label,description}`·`multiSelect` | `Approval.questions`(`StaffQuestion`) |
| `plan` | `title`(string, `Task.title`), `spec`(string, `TaskPlan.spec`, 최대 10000자), `subtasks[]`: `title`·`detail`·`assigneeName`, `isTruncated`(boolean, 자른 경우만) | `Task`·`TaskPlan`·`PlanSubtask`. `plan.status`가 `waiting`(대표 확인 대기)인 카드만 담는다 |
- 정렬: `createdAt` **오름차순**(오래 기다린 것이 먼저). 최대 100건이고 `total`은 전체 개수다.
- 앱은 마지막으로 알린 결정 `id`를 저장해 비교한다(백그라운드 조회 알림 중복 방지).
- v1에서 **담지 않는 결정**: 회의 중 결정(`answerMeetingDecision`), 프로세스 "내 확인" 단계(`reviewRun`). 나중에 새 `kind`로 추가해도 v1이 유지된다(2-2절).

### 5-3. `POST /v1/decisions/{id}` — 결정 응답
요청 본문은 결정 `kind`에 따라 다르다. `action`이 그 `kind`와 맞지 않으면 `400 invalid_action`.

| kind | 요청 본문 | PC 쪽 동작(기존 기능) |
|---|---|---|
| `approval` | `{ "action": "approve" }` 또는 `{ "action": "reject" }` | `decide(id, allow)` |
| `question` | `{ "action": "answer", "answers": { "<질문 문장>": "<답>" } }` — 여러 개를 고르면 답을 쉼표로 잇는다 | `answerQuestion(id, answers)` |
| `question` | `{ "action": "skip" }` — 답하지 않고 넘김 | `decide(id, false)` |
| `plan` | `{ "action": "approve", "feedback": "…" }` 또는 `{ "action": "reject", "feedback": "…" }` (`feedback` 선택) | `reviewPlan(taskId, isApproved, feedback)` |
- `answers`의 키는 목록에서 받은 `questions[].question` 문장 **그대로**여야 한다. 모르는 키가 있으면 `400 invalid_request`.
- **요약이 잘린 결재(`isTruncated: true`인 `approval`)는 `approve`를 받지 않는다** → `400 review_on_pc`("PC에서 전체를 확인해 주세요"). 휴대폰에서 다 보지 못한 명령을 승인하지 않게 하려는 것이다. `reject`는 안전하므로 받는다. 앱은 승인 버튼을 숨기거나 누르면 이 안내를 보인다.
- 선택지에 없는 답(직접 쓴 답)은 허용한다(데스크톱과 같음).

성공 `200`
```json
{
  "protocolVersion": 1,
  "serverTime": 1790000000000,
  "decisionId": "…",
  "result": "approved"
}
```
`result`: `approved`·`rejected`·`answered`·`skipped`.
- **이미 처리됐거나 사라진 `id`는 모두 `409 already_decided`**(PC에서 먼저 처리, 직원이 멈춤, 앱 재시작 등 이유를 구분하지 않는다). 앱은 "이미 처리됐어요"를 보이고 목록을 새로 읽는다.
- 네트워크가 끊겨 재시도했는데 첫 요청이 이미 반영됐다면 `409`가 온다. 앱은 이를 오류로 보이지 않고 목록만 새로고침한다.
- 서버는 이 처리를 기록에 "📱 휴대폰에서"로 표시한다.

### 5-4. `POST /v1/instructions` — 지시 전송
```json
{ "staffId": "…", "text": "오늘 회의 결과를 정리해 주세요" }
```
| 필드 | 타입 | 설명 |
|---|---|---|
| `staffId` | string | 5-1의 `staff[].id`. 고용 직원만 가능 |
| `text` | string | 1~4000자(공백만 있으면 400) |
- 첨부는 없다. 직원이 일하는 중이어도 받는다(PC의 `instruct`와 같이 하던 일이 끝난 뒤 이어서 처리). "바로 멈추고 먼저 듣기"는 v1에서 제공하지 않는다.
- **예약:** 단체방으로 보내기(`"target": "chat"`)는 기획서 D2가 확정될 때 선택 필드로 추가한다. 그 전에 오면 `400 invalid_request`.

성공 `202`
```json
{
  "protocolVersion": 1,
  "serverTime": 1790000000000,
  "accepted": true,
  "staffId": "…"
}
```
- `202`는 "접수했다"는 뜻이다. 직원이 실제로 처리하는 결과는 `GET /v1/status`의 상태·활동으로 본다.
- `staffId`가 없는 직원이거나 외부 직원이면 `404 staff_not_found`.
- 서버는 이 지시를 기록에 "📱 휴대폰에서"로 표시한다.

## 6. 노출하지 않는 것
| 구분 | v1에서 제공하지 않음 | 서버 동작 |
|---|---|---|
| 파일 | 파일 읽기·쓰기·첨부·열기·선택, 작업 폴더 탐색 | 경로 자체가 없음(404) |
| 실행 | 임의 명령·도구 실행, 쉘 | 없음. 지시는 직원에게 글을 전하는 것뿐 |
| 인사 | 직원 고용·퇴사·이름·직무 변경, 팀·랩 편집 | 없음 |
| 설정 | 장비·권한·결재 방식·예산·참고 문서·알림·원격 설정 | 없음(원격 켜기·끄기·QR 재발급은 PC 화면에서만) |
| 검토 | 커밋·PR, 변경 파일 보기 | 없음 |
| 기타 | 단체방·채팅 내용 조회, 업무 보드, 회의 결정, 매뉴얼, 상점·꾸미기, 삭제 | 없음 |
| 실시간 | WebSocket·이벤트 스트림 | 없음(조회만, 15분 주기) |

응답에서 **구조적으로 뺀 필드**(`types.ts` 기준)
- `Staff`: `cwd`·`ownCwd`·`cwdSource`(작업 폴더 경로), `systemPrompt`(지침), `refDocs`(문서 경로), `costUsd`·`tokensIn`·`tokensOut`(비용), `sessionId`·`pid`, `equipment`, `approvalMode`, `model`, `teamId`·`labIds`, `stats`, `deskIndex`·`hiredAt`·`meetingId`·`todayDone`.
- `Approval`: 뺀 필드 없음(`id`·`staffId`·`toolName`·`summary`·`createdAt`·`questions`를 5-2에 담는다. 다만 `summary`는 화면 표시용). `Task`: `assigneeId`·`teamId`·`labId`·`attachments`·`result`·`detail`·`parentId`·`childIds`·`absorbedIds`(기획 카드는 5-2의 `plan` 필드만).
- 이 필드들은 앞으로도 v1 응답에 넣지 않는다. 넣으려면 새 규격 개정과 보안 리뷰를 거친다.
- 다만 `summary`·`activity`·`spec`은 직원이 쓴 글이라 **경로나 명령이 섞일 수 있다.** 화면 표시용으로만 쓰고 로그·알림 본문·크래시 리포트에 넣지 않는다.

## 7. 오류 코드표
`error` 값과 HTTP 상태의 조합은 아래만 쓴다. "횟수"는 인증 실패 제한(IP별 5회/10분 → 그 IP 15분 잠금)에 세는지 여부다. 전체 합산 20회/10분은 **잠그지 않고 PC에 알리기만** 한다(누구나 여러 주소로 주인을 잠가 버릴 수 있어서).

| HTTP | `error` | 언제 | 횟수 | 앱 동작 |
|---|---|---|---|---|
| 400 | `invalid_request` | JSON이 아니거나 필드 누락·타입 오류, 글자 수 범위 밖, 모르는 `answers` 키, 예약 필드(`target`) 사용 | 안 셈 | 사용자 입력 확인 안내. 같은 내용 재시도 안 함 |
| 400 | `invalid_action` | `action`이 결정 `kind`와 맞지 않음 | 안 셈 | 목록을 새로 읽고 다시 시도 |
| 400 | `review_on_pc` | 요약이 잘린 결재(`isTruncated`)를 승인하려 함 | 안 셈 | "PC에서 전체를 확인해 주세요". 반려는 가능 |
| 401 | `unauthorized` | 토큰이 없거나 형식이 틀리거나 일치하지 않음(폐기 목록에도 없음) | **형식이 맞는 틀린 토큰만 셈** (헤더 없음·`Bearer` 아님·형식 틀림은 안 셈) | "다시 연결이 필요해요" |
| 401 | `token_revoked` | 이미 폐기된 토큰(PC에서 QR을 다시 만듦) | 안 셈 | 저장 토큰 삭제, **재시도·백그라운드 조회 중단**, "새 QR로 다시 연결하세요" |
| 401 | `auth_locked` | 실패가 많아 잠김(요청한 토큰이 맞아도 잠김 중이면 이 응답) | 안 셈 | `retryAt`까지 요청하지 않고 카운트다운 화면. 응답에 `retryAt` 필수 |
| 404 | `not_found` | 4종 외 경로 | 안 셈 | 앱 버그로 보고 로그 없이 오류 화면 |
| 404 | `staff_not_found` | 지시 대상이 없거나 외부 직원 | 안 셈 | "직원을 찾을 수 없어요" 후 상태 새로고침 |
| 405 | `method_not_allowed` | 경로는 맞지만 메서드가 다름. `Allow` 헤더 포함 | 안 셈 | 앱 버그 |
| 409 | `already_decided` | 이미 처리됐거나 사라진 결정 `id` | 안 셈 | "이미 처리됐어요" 후 목록 새로고침 |
| 413 | `payload_too_large` | 요청 본문 16KB 초과 | 안 셈 | 글을 줄이도록 안내 |
| 415 | `unsupported_media_type` | POST인데 `Content-Type`이 JSON이 아님 | 안 셈 | 앱 버그 |
| 426 | `protocol_unsupported` | 서버가 그 프로토콜 버전을 지원하지 않음. `supported`(정수 배열) 포함 | 안 셈 | 2-4절 |
| 429 | `rate_limited` | 정상 인증된 요청이 너무 잦음(토큰당 분당 120회 초과). `retryAfterSec`·`Retry-After` 포함 | 안 셈 | `retryAfterSec` 뒤에 재시도 |
| 500 | `internal_error` | 서버 내부 오류. 내용은 응답에 담지 않음 | 안 셈 | "PC에서 문제가 생겼어요", 잠시 후 재시도 |
| 503 | `office_unavailable` | 앱이 막 켜지는 중이거나 끝나는 중이라 처리할 수 없음. `retryAfterSec` 포함 | 안 셈 | `retryAfterSec` 뒤에 재시도 |
| (응답 없음) | — | 원격 꺼짐 / PC 절전 / 공유기 포트 닫힘 / 네트워크 끊김 | — | 가능한 범위에서 구분해 화면 표시(기획서 3절 5번) |
| (TLS 실패) | — | 인증서 지문(`spki`)이 QR과 다름 | — | **인증서 불일치 화면.** 연결하지 않고 무시 버튼 없음 |

규칙
- `auth_locked`의 `retryAt`은 **그 잠금이 풀리는 시각**이다. 잠금은 IP별만 있다(전체 한도는 PC 알림만).
- 서버가 실패를 기억하는 IP와 잠근 IP는 **각각 최대 5000개**이고, 10분 지난 기록·풀린 잠금은 쓸어낸다. 잠금이 5000개를 넘으면 가장 먼저 잠근(가장 먼저 풀릴) 것부터 버린다(많은 주소로 메모리를 채우지 못하게).
- PC 알림(IP 잠금·전체 한도)은 **종류마다 10분에 한 번**만 띄우고, 그 사이 일은 다음 알림 본문에 횟수로 합친다(실패가 1000번이어도 알림은 1번).
- 잠금 중에는 맞는 토큰으로도 `auth_locked`를 준다. 이 응답이 토큰이 맞는지 알려 주는 통로가 되지 않게 한다.
- `token_revoked`는 폐기 목록(해시)에 있는 토큰에만 준다. 폐기 목록은 최근 20개만 보관하고, 더 오래된 토큰은 `unauthorized`로 보인다. `unauthorized`는 기획서 5-3절 표에 없던 **일반 인증 실패**로, 토큰을 맞혀 보는 시도를 제한하려고 추가했다.
- 오류 본문에는 토큰·지문·경로·내부 문장을 넣지 않는다.

## 8. QR 내용 형식
QR에는 아래 JSON(UTF-8)을 **그대로** 넣는다.
```json
{
  "v": 1,
  "host": "203.0.113.10",
  "port": 47900,
  "token": "…43자 base64url…",
  "spki": "sha256/…44자 base64…",
  "lan": "192.168.0.24",
  "ts": true,
  "firebase": { "projectId": "…", "appId": "…", "senderId": "…" }
}
```
| 필드 | 필수 | 타입·규칙 |
|---|---|---|
| `v` | 필수 | 정수. 프로토콜 버전 |
| `host` | 필수 | 외부 접속 주소. IPv4·IPv6 숫자 주소 또는 DDNS 이름. 1~255자, 공백·`/`·`:`(IPv6 제외) 없음 |
| `port` | 필수 | 정수 1024~65535. 기본값은 기획서 D4에서 확정 |
| `token` | 필수 | 4절의 토큰 원문. base64url 43자 |
| `spki` | 필수 | 서버 인증서 **공개키(SPKI) DER의 SHA-256**을 base64로 쓴 값 앞에 `sha256/`를 붙임. 정규식 `^sha256/[A-Za-z0-9+/]{43}=$` |
| `lan` | **선택** | 이 PC의 **같은 와이파이 주소**(사설 IPv4 — 10.x·172.16~31.x·192.168.x). `host`와 **다를 때만** 들어간다(공유기 자동 설정으로 외부 주소를 알았거나 DDNS 이름을 넣은 경우). 사설 IPv4 모양이 아니면 앱은 무시한다 |
| `ts` | **선택** | `true`일 때만 들어간다. **`host`가 Tailscale 주소(100.64.0.0/10 IPv4)**라는 뜻이며, 휴대폰의 Tailscale이 켜져 있어야 붙는다. `ts`가 있으면 `lan`·`lo`는 넣지 않는다(이 모드의 서버는 100.64/10이 아닌 주소의 연결을 TLS 전에 끊는다). 모르는 앱은 무시한다. 상세: `docs/specs/tailscale-mode.md` |
| `firebase` | **선택·예약** | `projectId`·`appId`·`senderId`가 모두 문자열이면 유효, 하나라도 아니면 통째로 무시. **1.0.0 앱은 읽기만 하고 쓰지 않는다**(없어도 됨). 푸시는 2단계 |
- **Tailscale 모드(`ts:true`)의 서버는 상대 주소가 100.64.0.0/10이 아니면 TLS를 시작하기 전에 소켓을 끊는다.** 이 거절은 인증 실패 횟수·잠금에 세지 않는다. 토큰·SPKI 고정은 다른 모드와 같다. UPnP는 쓰지 않는다.
- 앱은 **모르는 필드를 무시**한다(2-3절). 필수 필드가 없거나 JSON이 아니면 "Claude Office QR이 아니에요"를 안내한다.
- **`lan`이 있으면 앱은 먼저 `https://<lan>:<port>`로 짧게(약 2초) 붙어 보고, 실패하면 `host`로 간다.** 같은 와이파이의 휴대폰이 외부 주소로 붙으려면 공유기가 밖으로 나갔다 되돌아 들어오기(헤어핀 NAT)를 해 줘야 하는데, 못 하는 공유기가 많기 때문이다(이중 공유기 집도 같다). 두 주소 모두 **같은 `spki` 지문으로 고정**하므로 보안 수준은 같다(어느 주소로 붙든 지문이 다르면 연결하지 않는다). 성공한 주소를 다음에도 먼저 써도 된다.
- 앱은 연결할 때 `https://<host>:<port>/v1/status`에 붙고, TLS 핸드셰이크에서 서버 인증서의 SPKI 지문이 `spki`와 같은지 확인한다. 다르면 연결을 끊는다. 시스템 CA·사용자 설치 CA는 신뢰하지 않는다.
- QR은 **화면에만 표시**하고 파일·클립보드·로그로 남기지 않는다. 토큰이 들어 있으므로 QR을 본 사람은 연결할 수 있다.
- 권고(구현 시 정리드·한리뷰가 확정): QR 표시 화면은 일정 시간(예: 5분) 뒤 가린다. 가려도 토큰은 그대로이며, 다시 보려면 재발급(아래 9절)만 가능하다(토큰 원문은 저장하지 않기 때문).

## 9. 토큰 재발급 규칙
| 항목 | 규칙 |
|---|---|
| 처음 발급 | 원격 기능을 **처음 켤 때** 토큰·인증서 키쌍을 만든다 |
| 재발급 방법 | PC 설정의 **"QR 다시 만들기"** 버튼뿐(앱·원격에서는 불가). 확인 창에 "연결된 휴대폰이 모두 끊겨요"를 보인다 |
| 재발급 효과 | ① 새 토큰을 만들고 ② **이전 토큰을 즉시 폐기**(해시를 폐기 목록에 넣음) ③ 인증 실패 횟수·잠금을 초기화(PC 앞의 소유자가 직접 한 조작이므로) ④ 새 QR 표시 |
| 폐기된 토큰으로 요청 | `401 token_revoked`(실패 횟수에 세지 않음) |
| 끄기·켜기 | 원격을 껐다 켜도 토큰은 **유지**한다. 끄면 포트와 UPnP 매핑을 닫고, 켜면 같은 토큰으로 다시 연다 |
| 인증서 키 교체 | `spki`가 바뀌므로 **QR을 다시 만들어야** 하고 토큰도 함께 새로 발급한다(QR 한 장 = 토큰 하나 + 지문 하나) |
| 저장 | 서버는 활성 토큰의 SHA-256 해시와 폐기 목록(최근 20개 해시)만 저장한다. 토큰 원문은 QR이 화면에 있는 동안 메모리에만 둔다 |
| 여러 폰 | 1.0.0은 토큰 **하나를 공유**한다(기획서 D3). 재발급하면 모든 폰이 끊긴다 |
| 앱이 `token_revoked`를 받으면 | Keystore의 토큰을 삭제하고 요청·백그라운드 조회를 멈춘 뒤 알림 **1회** "다시 연결이 필요해요", 새 QR을 스캔하면 새로 연결 |
- 인증 실패 제한: IP별 5회/10분 → 해당 IP 15분 잠금. 전체 합산 20회/10분 → **PC 알림만**(잠그지 않음). 세는 것은 형식이 맞는 틀린 토큰뿐. 수치는 서버 상수 한 곳(`app/src/main/remote/auth.ts`).

호환 표(첫 릴리스)
| 데스크톱 | 안드로이드 | 프로토콜 |

| 0.8.0 이상 | 1.0.x | v1 |
