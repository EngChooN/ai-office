# 베타 공개 + 긱뉴스 "Show GN" 준비 기획서

작성: 김기획(PO) · 기준 버전 0.14.2 · 상태: 초안(대표 검토 전)
표기: **[확인 필요]** = 근거가 없어 제안만 한 값. 확정 전 대표·담당자 확인.

## 1. 배경·목적
- 소개 페이지(`site/index.html`, GitHub Pages)에서 누구나 이미 내려받을 수 있음 → 이 상태를 공식 **베타**로 선언.
- 필수 범위를 끝낸 직후 긱뉴스 "Show GN"에 올려 피드백·초기 사용자 확보. 소개 페이지가 검색으로도 유입되게 함.
- 게시·배포·버전 번호는 대표 확인 후 대표 지시로만 진행.

## 2. 범위 구분
| 구분 | # | 항목 |
|---|---|---|
| 필수(게시 전) | 1 | 첫 실행 온보딩 확장 |
| 필수 | 2 | 앱 내 피드백 버튼 |
| 필수 | 3 | 소개 페이지 쿠키 없는 방문 집계 |
| 필수 | 4 | 소개 첫 화면 개편(다운로드 버튼·베타 표시·지원 플랫폼 맥/윈도우/안드로이드·알려진 제한 사항·피드백 링크, 한·영·일·중) |
| 필수 | 5 | 소개 페이지 검색엔진 최적화 |
| 추가(베타 기간) | 6 | GIF·이미지 내보내기(로고+주소 워터마크, 확정 비율) — 구현은 필수 이후 |

범위 밖: 별도 도메인 구매, 검색엔진 계정 등록 대행(대표 계정 소유 확인 필요), 광고·SNS 크롭.

## 3. 항목별 완료 기준 (수치)
**1. 온보딩 확장**
- 새 설치 → 온보딩 → Claude Code 설치·로그인 확인 → 예제 업무 1건 결과 확인까지 맥·윈도우 각 1회 이상 막힘 0건.
- 소요 시간 목표: 설치 완료 후 **N분 이내** [확인 필요, 제안 5분].
- 로그인 미완료·미설치 시 안내 문구와 재확인 버튼 동작(경우 2가지 모두).

**2. 피드백 버튼**
- 클릭 1회로 GitHub 새 이슈 화면 열림, 제목/본문에 **앱 버전·OS** 자동 기입 100%(맥·윈도우 각각 확인).
- 앱 내 노출 위치 **N곳** [확인 필요, 제안 1~2곳: 설정·메뉴].
- 개인 경로·API 키 등 민감 정보 포함 0건.

**3. 방문 집계**
- 쿠키·로컬 저장·개인 식별 정보 수집 0건(브라우저 개발자 도구에서 쿠키 0 확인).
- 일/주 방문 수를 대시보드에서 확인 가능. 4개 언어 페이지 모두 집계.
- 도구 선택은 강백엔 비교 후 대표 확인(외부 가입 필요 시).

**4. 소개 첫 화면**
- 스크롤 없이 첫 화면에 다운로드 버튼 1개(기기 맞춤) + 베타 뱃지 + 알려진 제한 사항 링크 + 피드백 링크 노출(데스크톱 1280 폭·모바일 390 폭).
- 4개 언어 모두 동일 배치, 문구 누락 0건.
- 맥·윈도우·안드로이드 표기. Windows 문구는 확인 전 단정 금지.
- 다운로드 버튼 클릭률 목표 **N%** [확인 필요].

**5. 검색엔진 최적화**
- `/robots.txt`, `/sitemap.xml` HTTP 200.
- 4개 언어 주소가 서로 hreflang으로 연결(누락 0).
- JSON-LD(SoftwareApplication) 구글 리치 결과 테스트 오류 0.
- 라이트하우스 SEO 점수 **90 이상** [확인 필요].
- 이미지 alt 누락 0, 첫 화면 LCP **N초 이하** [확인 필요, 제안 2.5초].
- 구글 서치 콘솔·네이버 서치어드바이저 등록 절차 문서화(등록은 대표).
- 게시 후 색인 목표: 구글 **N주 내** 주 키워드 1개 이상 노출 [확인 필요].

**6. GIF·이미지 내보내기(추가)**
- 10초 GIF 용량 **N MB 이하** [확인 필요, 제안 5MB·긱뉴스/SNS 업로드 한도 확인].
- 워터마크(로고+주소) 100% 포함, 비율 확정안 1개 이상.
- 내보내기 소요 **N초 이하** [확인 필요].

**운영 지표(주간 보고)**
- 방문 수·설치(다운로드) 수·1주 재사용률. 베타 첫 주 목표: 방문 **N**, 다운로드 **N**, 재사용률 **N%** [모두 확인 필요].
- 다운로드 수는 `gh`로 릴리즈 에셋 집계(개발 없음).

## 4. 알려진 제한 사항 (초안)
> 코드·QA로 사실 확인 후 확정 [확인 필요]. 사실 확인 안 된 항목은 삭제.
1. 베타 단계라 예고 없이 동작·화면이 바뀔 수 있음.
2. Claude Code 설치·로그인이 선행되어야 직원이 일함. 플랜 사용 한도에 영향받음.
3. GPT(Codex) 직원은 베타 기능.
4. 컴퓨터 조작·화면 캡처는 사용자 승인 필요, 맥에서는 화면 기록·손쉬운 사용 권한 필요.
5. 윈도우 지원 범위·알려진 차이는 QA 결과 반영 [확인 필요].
6. 안드로이드는 PC 앱과 연결해 쓰는 원격 앱(PC 앱 실행 필요, 집 밖 연결은 Tailscale 필요) [확인 필요].
7. 코드 서명 여부에 따라 설치 시 OS 보안 경고가 뜰 수 있음 [확인 필요].
8. 사용 데이터는 기기 내 저장, 방문 집계는 소개 페이지에 한정(앱 내 집계 없음 — §6 결정에 따라 변경 가능).

## 6. '1주 재사용률' 측정 방법 안
정의(제안): 설치 후 7일째 전후(6~8일차)에 앱을 다시 실행해 업무를 1건 이상 지시한 사용자 / 최초 실행 사용자.

| | A. 앱 익명 집계 | B. 설문 |
|---|---|---|
| 방식 | 최초 실행일·재실행 여부만 무작위 ID로 전송 | 앱 내/긱뉴스 글에서 구글 폼 링크 |
| 정확도 | 높음(전수) | 낮음(응답 편향, 응답률 낮음) |
| 개발 | 서버/수집 도구 + 앱 수정 필요, 동의 UI | 없음 |
| 프라이버시 | 내용 수집 없어도 "무수집" 이미지 훼손 위험, 옵트인 필수 | 부담 적음 |
| 일정 | 게시 전 구현 부담 | 즉시 |

**권고:** 베타 기간은 **B(설문)** + 다운로드 수·GitHub 이슈 수로 대체 추정, 정식 출시 전에 **A를 옵트인(기본 꺼짐)** 으로 도입 검토. 최종 선택은 대표 결정 필요.

**제안값 (대표 확인 필요)**
- **GIF 용량 N = 5MB 이하.** 링크드인(5MB)이 가장 빡빡한 확인된 한도이고, 이 값이면 X 15MB·깃허브 10MB·스레드 8MB·디스코드 20MB를 모두 통과합니다. 박패턴 실측(화면 고정 0.36~0.58MB, 최악 약 7.5MB를 자동으로 낮추면 약 3.2MB 추정)으로도 달성 가능합니다.
- **한도를 넘으면** 초당 15장→10장, 폭 800→640 순으로 자동으로 낮춥니다(기술 조사 문서). 5MB를 못 맞출 경우만 안내 문구를 띄웁니다.
- **비율은 16:9 하나로 확정**을 추천합니다. 확인된 한도(X 1280×1080 이하, 스레드 4:5~1.91:1 중 엇갈리는 두 표기 모두 안쪽)를 모두 만족합니다. 폭 800×450이면 X 해상도·프레임 한도(10초·15fps=150프레임, 약 5천만 픽셀)에도 여유가 있습니다. 이디자 시안의 결론과 같습니다.
- **용량 한도로 MP4를 내야 할 곳은 없습니다.** 다만 스레드의 GIF 지원 여부는 불확실하니, 스레드용은 PNG 한 장이나 링크로 안내하는 쪽이 안전합니다.

**남은 확인 사항**
1. 긱뉴스 용량·첨부 방식: 대표님 계정으로 글쓰기 화면에서 확인하거나 /guidelines를 열어 보셔야 합니다. 이 항목이 비어 있어 Show GN용은 아직 근거가 없습니다. 기본 대비책은 GIF를 깃허브 이슈 첨부로 올려 주소를 삽입하는 방식입니다(그 경우 깃허브 10MB 기준).
2. 링크드인 5MB·스레드 8MB는 제3자 출처라 실제 업로드 테스트로 한 번 확인합니다.
3. 정식 공개 전 출처 값이 바뀌었는지 다시 확인합니다(디스코드 한도가 올해 바뀐 사례).

## 7. 진행·의존
온보딩·피드백·집계·첫 화면(동시) → 검색엔진 최적화(첫 화면 개편 후, 같은 파일 충돌 방지) → 필수 범위 QA(바뀐 항목만) → GIF·Show GN 초안 → 대표 검토.

## 8. 열린 질문
1. 쿠키 없는 집계 도구 선정·가입(대표 확인).
2. 서치 콘솔·서치어드바이저 소유 확인(대표 계정).
3. 도메인 유지 여부(`engchoon.github.io/ai-office` 그대로?).
4. 재사용률 측정안 A/B 선택.
5. §3의 모든 **N** 값 확정.
