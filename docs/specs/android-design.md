# 안드로이드 1.0.0 화면 설계 · 모바일 토큰표

> 작성: 이디자(디자인 팀) · 2026-10-22 · 상위 업무 "회의 결과: 클로드 오피스 안드로이드 앱 개발" 4/9단계
> 근거: `docs/specs/android-mvp.md`(2026-10-22 갱신본), `docs/specs/remote-protocol-v1.md`(v1), `app/src/renderer/index.css`(데스크톱 토큰), 데스크톱 화면(대시보드·결재함·직원 패널). **코드는 고치지 않았다.**
> 읽는 사람: 임안드(앱 구현), 정리드(PC 가이드 화면 구현), 김버전(프로토콜 대조 결과), 한리뷰·오큐에이(상태 화면 검증).
> 목업: `docs/specs/android-design/` — `pc-guide.png`, `mobile-main.png`, `mobile-states.png`(원본 HTML과 `mock.css` 같이 둠. 목업의 색은 이 문서 1절 값과 같다).

## 0. 원칙
- **데스크톱을 옮긴다.** 색은 `index.css` 토큰을 그대로(다크), 상태색 규칙(작업 중 초록·확인 필요 노랑·오류 빨강)도 그대로, 카드·배지·버튼 모양도 데스크톱과 같다. 휴대폰 앱은 **항상 업무 모드 모습**(이니셜 원, 레벨·자금·지도 없음).
- **"개발 지식 없이도 알 수 있는가?"** 포트·UPnP·DDNS·토큰 같은 말은 처음 한 번 쉬운 말로 풀고(포트 = "문 번호", 토큰 = "열쇠"), 화면 로직 용어(401·TLS)는 화면에 쓰지 않는다.
- **터치 영역 48dp 이상.** 버튼 높이 48dp, 목록 행 64dp, 라디오 카드 56dp, 아이콘 버튼 48×48dp(아이콘 24dp).
- **끊긴 상태에서는 결정·지시를 받지 않는다.** 마지막 화면은 보여 주되 버튼을 잠근다. 오프라인 대기열 없음(오래된 화면을 보고 늦게 승인되는 위험).
- **명령·경로가 섞인 글(`summary`·`activity`·`spec`)은 화면에만.** 알림·로그에는 넣지 않는다(프로토콜 6절, 기획 D8).

## 1. 모바일 토큰표 (임안드 전달용)

파생 규칙(별도 토큰 없이 계산)
- 상태 배경(배너·아이콘 원): 해당 상태색 **14~15% 불투명도**를 `background` 위에 겹친다. 테두리는 같은 색 40%.
- 배지 테두리: 해당 상태색 50%. 배지 배경은 투명(데스크톱 `Badge variant="outline"`과 같음).
- 비활성: 요소 전체 불투명도 50%.
- 팀 색(이니셜 원): `Team.color`를 **22%** 섞은 배경 + 60% 테두리 + 글자는 `onSurface`(데스크톱 업무 모드 이니셜 원과 같은 규칙). 1.0.0 프로토콜에는 팀 정보가 없으므로(`teamId` 제외 필드) **모든 이니셜 원은 `statusIdle` 22% 배경**으로 그린다. 목업의 파랑·주황·초록은 예시일 뿐이다.

### 1-2. 글자 (sp)
글꼴은 안드로이드 기본(Noto Sans CJK KR). 굵기 500이 표현되어 데스크톱 `font-medium` 위계가 유지된다. 데스크톱보다 한 단계 크게 쓴다.

| 토큰 | 크기 / 줄 높이 / 굵기 | 쓰는 곳 | 데스크톱 대응 |
|---|---|---|---|
| `display` | 40 / 48 / 600, 고정폭 숫자 | 잠김 카운트다운 | — |
| `numeral` | 24 / 30 / 600, 고정폭 숫자 | 요약 숫자 | `text-2xl font-semibold` |
| `titleLarge` | 20 / 28 / 600 | 화면 제목, 상태 화면 제목 | `text-lg font-semibold` |
| `titleMedium` | 16 / 24 / 600 | 카드 제목, 직원 이름, 질문 | `text-sm font-semibold` |
| `bodyLarge` | 15 / 22 / 400 | 본문, 버튼(600) | `text-sm` |

## 2. PC 쪽 첫 연결 가이드 (정리드 구현)
목업: `android-design/pc-guide.png`. 설정 › **휴대폰 연결** 섹션에서 "연결 시작"을 누르면 `Dialog` 한 장 안에서 단계를 넘긴다(데스크톱 토큰·컴포넌트 그대로). 위쪽에 단계 칩 `1 켜기 · 2 포트 · 3 공유기 · 4 주소 · 5 QR`(지난 단계는 초록 ✓, 현재는 주황 테두리).

| 단계 | 내용 | 버튼 |
|---|---|---|
| ① 켜기 | 할 수 있는 일/없는 일 한 줄 + **보안 주의 배너**(아래 문구) + 체크박스 "위 내용을 확인했어요" | `원격 연결 켜기`(체크해야 활성). 바닥 보조 "기본은 꺼져 있어요" |
| ② 포트 | 포트 번호(1024~65535, 기본값은 D4 확정 값), 이 PC 안쪽 주소, 상태 "● 이 PC에서 열 준비가 됐어요". 사용 중이면 빨간 배너 "47900번은 다른 프로그램이 쓰고 있어요. 다른 번호(예: 47901)로 바꿔 주세요." | `이전` / `공유기 설정 시도` |
| ③-a 공유기 성공 | "공유기가 문을 열어 줬어요" + 바깥 주소·열린 길·유지("앱이 켜져 있는 동안 30분마다 새로 고쳐요"). 바깥 주소가 100.64~100.127이면 경고 배너(통신사 공유 주소) | `이전` / `다음` |
| ③-b 공유기 실패 | "공유기가 자동 설정을 받지 않았어요. 직접 한 번만 설정하면 돼요. 같은 와이파이 안에서는 지금도 연결돼요." + 공유기 관리 화면에서 할 일 3단계 + 입력할 값 표(외부 포트·내부 IP·내부 포트·TCP) | `이전` / `다시 확인` / `설정했어요, 다음` |
| ④ 주소(선택) | 주소가 바뀌는 이유 + DDNS("바뀌지 않는 이름") 쓰는 법 + 이름 입력칸("비워 두면 지금 주소 203.0.113.10을 써요") | `이전` / `건너뛰기` / `다음` |
| ⑤ QR | QR(흰 바탕 180px) + 휴대폰에서 할 일 3단계 + 주소 + "4:32 뒤에 QR이 가려져요"(노랑) + **QR 주의 배너**. 휴대폰이 첫 `GET /v1/status`에 성공하면 "연결됐어요"(초록)로 바뀜 | `QR 다시 만들기`(빨간 테두리, 확인창 "연결된 휴대폰이 모두 끊겨요") / `닫기` |

**보안 주의 문구 (① 켜기)**
> **켜기 전에 꼭 읽어 주세요**
> 켜면 이 PC의 문(포트) 하나가 인터넷 쪽으로 열려요. 연결용 QR 코드를 가진 사람은 누구나 이 사무실에 결재하고 지시할 수 있어요.
> · QR 코드를 사진으로 남기거나 다른 사람에게 보내지 마세요.
> · 휴대폰을 잃어버렸다면 바로 "QR 다시 만들기"를 눌러 주세요.
> · 쓰지 않을 때는 꺼 두세요. 끄면 문이 바로 닫혀요.

**QR 주의 문구 (⑤ QR)**
> 이 QR에는 이 사무실의 열쇠가 들어 있어요. 사진·캡처로 남기지 마세요. 휴대폰을 바꾸거나 잃어버렸으면 "QR 다시 만들기"를 눌러 주세요. 연결된 휴대폰이 모두 끊겨요.

**가이드를 마친 뒤 설정 섹션 모습**
- 체크박스 `휴대폰 연결 켜기` + 상태 줄 `● 켜짐 · 바깥 주소 myoffice.iptime.org:47900 · 공유기 자동 설정됨`(실패면 `공유기 직접 설정 필요`, 노랑).
- 버튼 `QR 보기`(⑤만 다시 엶 — 토큰 원문이 메모리에 없으면 **재발급만 가능**하므로 문구를 `QR 다시 만들기`로 바꿔 보인다, 프로토콜 8절 권고) · `가이드 다시 보기`.
- 잠김이 생기면 PC 알림 + 섹션에 `⚠ 연결 시도가 여러 번 실패해 10:56까지 잠겼어요. 내가 한 일이 아니라면 QR을 다시 만들어 주세요.`
- 휴대폰에서 온 결정·지시는 기록·단체방에 `📱 휴대폰에서` 배지(`Badge variant="outline"`, `text-[10px]`).

## 3. 모바일 화면 (임안드 구현)
목업: `android-design/mobile-main.png`(주요 9장), `mobile-states.png`(상태 10장 + 라이트 2장).

### 3-1. 내비게이션
하단 탭 3개: **직원 · 결정 · 설정**. 결정 탭에 대기 수 배지(`statusWaitingFill` + 검정 숫자). 단체방·업무 보드는 1.0.0에 없다(기획 판단 2). 앱을 열 때 기본 탭은 대기 결정이 있으면 **결정**, 없으면 **직원**.

### 3-2. 첫 연결 (목업 1~3)
1. **시작:** 앱 아이콘, "내 PC 사무실에 연결해요", 단계 2줄, `QR 코드 찍기`, 보조 "카메라는 QR을 읽을 때만 써요."
2. **QR 스캔:** 검은 전체 화면, 220dp 사각 가이드, 아래 "PC 화면의 QR 코드를 네모 안에 맞춰 주세요", 왼쪽 위 닫기(48dp).
   - 카메라 권한 거부: StateScreen "QR 코드를 찍으려면 카메라 권한이 필요해요." + `설정에서 허용하기`.
   - QR이 우리 형식이 아님: 스캔 화면 아래에 빨간 줄 "Claude Office QR이 아니에요"(계속 스캔).
   - QR `v`가 앱보다 큼: 연결 시도 없이 상태 H "앱을 업데이트해 주세요".
   - 스캔 성공 → "PC에 연결하고 있어요…"(스피너 + 주소) → `GET /v1/status`.
3. **연결 성공 + 알림 안내:** ✓ 아이콘, "내 PC 사무실에 연결했어요", 주소, 카드 **"알림은 늦게 올 수 있어요"**(아래 4절 문구), `배터리 설정 열기`(주), `나중에 할게요`(텍스트 버튼). 아래 단계 점 3개.

### 3-3. 직원 상태 목록 (목업 4)
- 상단: 제목 "직원" + 오른쪽 갱신 표시(`● 방금 갱신` / `10:35 갱신`). 시각은 `serverTime`으로 보정.
- 요약 타일 4칸: 일하는 중 · 확인 필요 · 오류 · 쉬는 중(`summary`, `offline`은 쉬는 중에 합치지 않고 표시하지 않음 — 목록에서만 회색). 0이면 숫자 `onSurfaceMuted`, 확인 필요 1 이상이면 테두리 `statusWaiting` 70%. 누르면 목록 필터(다시 누르면 해제).
- 목록 행: 이니셜 원(이름 뒤 2글자, 데스크톱 규칙) · 이름(`titleMedium`) · 오른쪽 상태 점+라벨+경과 시간(`statusSince`, "12분째") · 직무(`bodySmall` muted) · 결정 대기 수가 있으면 직무 뒤 `· 결정 1건 대기` · 지금 하는 일(`activity`) 1줄 말줄임.
- 정렬: 확인 필요 → 오류 → 일하는 중 → 쉬는 중 → 오프라인(데스크톱 대시보드와 같음).
- 상태 라벨: `working` 일하는 중 / `waiting` 확인 필요 / `error` 오류 / `idle` 쉬는 중 / `offline` 오프라인 / 모르는 값 "알 수 없음"(`statusIdle`).
- 아래로 당겨 새로고침. 행을 누르면 직원 상세(3-6).

### 3-4. 대기 결정 목록 (목업 5)
- 제목 "기다리는 결정" + `n건`. `total`이 100을 넘으면 맨 아래 "외 n건은 PC에서 확인해 주세요."
- `DecisionCard`: 이니셜 원(28) · 직원 이름 · 종류 배지 · 오른쪽 경과 시간 / 요약 1~3줄(넘치면 "더 보기") / 버튼.

| kind | 배지 | 본문 | 버튼 |
|---|---|---|---|
| `approval` | 결재 | `toolName · summary` | `반려`(outline) · `✓ 승인`(primary, 오른쪽) — **목록에서 바로** |
| `question` | 질문 | 첫 질문 문장 | `답하기 ›` → 3-5 |
| `plan` | 기획 확인 | `title` · 하위 업무 n개 | `기획안 보기 ›` → 3-5 |
| 모르는 값 | 확인 필요(muted) | "PC에서 확인해 주세요" | 버튼 없음(프로토콜 2-3) |

- 정렬: 서버 순서(`createdAt` 오름차순)를 그대로. 새 항목은 아래에 붙어 손가락 밑 카드가 밀리지 않는다.
- 처리 중: 두 버튼 비활성 + 누른 버튼 "처리 중…". 성공하면 카드가 접히며 사라지고 스낵바 `승인했어요` / `반려했어요`.
- **"모두 승인" 없음**(작은 화면에서 내용을 읽지 않고 누를 위험).

### 3-5. 결정 상세
- **질문 (목업 6):** 상단 "이디자의 질문", `header` 배지, 질문(`titleMedium`), 선택지 `ChoiceCard`(`label` + `description`), 마지막 카드 "직접 쓰기"(고르면 입력칸 펼침, 1000자). `multiSelect`면 체크박스, 답은 쉼표로 이음. 질문이 여러 개면 위아래로 이어서 모두 답해야 `답하기` 활성. 하단 고정 `답하기` + 텍스트 버튼 `답하지 않고 넘기기`(→ `skip`, 확인창 "이 질문을 넘길까요? 이디자 님은 답 없이 이어서 일해요.").
- **기획 확인 (목업 7):** 작성자·시각, `title`, `spec`(마크다운 → 단순 서식), 하위 업무 목록(`title — assigneeName`). `isTruncated`면 "기획안이 길어 일부만 보여요. 전체는 PC에서 볼 수 있어요." 의견 입력칸(선택, 2000자, 안내 "반려할 때 이유를 적어 주면 좋아요"). 하단 `반려` · `승인하고 진행`.
- **결재 상세:** 목록에서 "더 보기"로 요약 전체를 펼치는 것으로 충분(별도 화면 없음).

### 3-6. 직원 상세 · 지시 (목업 8)
- 위: 이니셜 원(56) · 이름 · 직무 · 상태+경과. 카드 "지금 하는 일"(`activity` 전체).
- 이 직원의 대기 결정이 있으면 카드 "결정 1건 대기 ›"(→ 결정 탭의 해당 카드).
- 정보 배너(muted): "일하는 중이면 지금 일이 끝난 뒤에 이어서 처리해요."(일하는 중일 때만)
- 아래 고정: 여러 줄 입력칸(placeholder `이디자 님에게 지시하기`, 1~4000자, 오른쪽 아래 `13 / 4000`) + `지시 보내기`(비어 있으면 비활성). 키보드가 입력칸·버튼을 가리지 않게 함께 올라간다.
- 성공(202): 입력칸 비우고 스낵바 `이디자 님에게 전달했어요`. 결과는 상태 목록에서 본다.

### 3-7. 설정 (목업 9)
- 카드 "연결된 PC": 주소 · `● 연결됨 · 마지막 확인 10:35` · `PC 0.8.0 · 앱 1.0.0 · 프로토콜 v1`.
- 카드 "알림": "15분마다 확인해요. 절전 중이면 수십 분 지연될 수 있어요." + 행 `배터리 최적화` → 오른쪽 `켜져 있음 ›`(노랑) / `꺼져 있음`(초록). 누르면 시스템 배터리 최적화 예외 화면(4절).
- `이 PC와 연결 끊기`(빨간 테두리) + 보조 "연결을 끊으면 이 휴대폰에 저장된 열쇠가 지워져요. 다시 쓰려면 QR을 새로 찍어야 해요." 확인창 → Keystore 삭제 → 3-2 시작 화면.

## 4. 배터리 최적화 예외 · "수십 분 지연" 안내
**놓이는 곳:** ① 첫 연결 성공 화면(3-2-3) ② 설정 › 알림 ③ 백그라운드 알림을 처음 보낼 때 1회(알림을 누르면 앱이 열리며 맨 위 배너).

**문구 (연결 성공 카드)**
> **알림은 늦게 올 수 있어요**
> 결재·질문이 생기면 휴대폰이 15분마다 확인해서 알려 드려요. 휴대폰이 절전 중이면 **수십 분 지연될 수 있어요.** 급한 일은 앱을 열면 바로 최신 상태로 보여요.
> 배터리 최적화에서 이 앱을 빼면 조금 더 자주 확인해요.
> [배터리 설정 열기] · 나중에 할게요

- `배터리 설정 열기`는 시스템 "배터리 최적화 무시" 목록 화면(`ACTION_IGNORE_BATTERY_OPTIMIZATION_SETTINGS`)으로 보낸다. **바로 허용을 묻는 창(`REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`)은 쓰지 않는다**(기획 6절 "강제 요청하지 않음", 스토어 정책 부담).
- 이미 예외면 버튼 대신 `✓ 배터리 최적화에서 빠져 있어요`(초록).
- 예외에 넣어도 "즉시"가 아니라는 점을 약속하지 않는다("조금 더 자주").

**백그라운드 알림 (로컬 알림 채널 "결정 대기")**
| 상황 | 제목 | 본문 |
|---|---|---|
| 새 결정 1건 | `확인할 결정이 있어요` | `이디자 님이 기다리고 있어요` |
| 새 결정 여러 건 | `확인할 결정 3건` | `이디자 님 외 2명이 기다리고 있어요` |
| `token_revoked`·`unauthorized` | `다시 연결이 필요해요` | `앱을 열어 새 QR을 찍어 주세요` (1회) |
| `auth_locked` | `연결이 잠시 잠겼어요` | `10:56 이후에 다시 확인해요` (1회) |
| 인증서 불일치 | `연결을 멈췄어요` | `앱을 열어 확인해 주세요` (1회) |
- 본문에 `summary`·`activity`·`spec`·도구 이름은 **넣지 않는다**. 직원 이름은 넣는다(잠금 화면 노출 수준은 **[확인 필요]** — 채널 공개 범위를 `VISIBILITY_PRIVATE`로 두면 잠금 화면에는 "Claude Office 알림 1개"만 보인다. 권장).
- 알림을 누르면 결정 탭으로 연다. 연결이 끊긴 오류 알림은 해당 상태 화면으로 연다.

## 5. 상태 화면 (목업 mobile-states)
두 가지 틀로 나눈다.
- **전체 화면(`StateScreen`)**: 다시 연결하거나 기다려야 하는 경우. 하단 탭은 유지(원격 꺼짐·절전)하거나 숨긴다(토큰·인증서·잠김 — 탭을 눌러도 쓸 수 없으므로).
- **배너(`ConnectionBanner`)**: 잠깐 끊긴 경우. 마지막으로 받은 화면을 흐리게(60%) 보이고 **결정·지시 버튼을 잠근다**. 잠긴 버튼 대신 카드 아래 "PC에 연결되면 할 수 있어요."

| # | 상태 | 틀 | 아이콘(원 색) | 제목 | 설명 | 버튼 |
|---|---|---|---|---|---|---|
| A | 원격 꺼짐 | 전체(탭 유지) | ⏻ (muted) | PC의 휴대폰 연결이 꺼져 있어요 | PC의 Claude Office에서 설정 › 휴대폰 연결을 켜면 다시 연결돼요. · 마지막 연결 10:24 | `다시 시도` |
| B | 절전 · PC 응답 없음 | 전체(탭 유지) | ☾ (muted) | PC에 닿지 않아요 | 이런 경우일 수 있어요. PC가 잠자기 중이거나 꺼져 있어요 / Claude Office가 꺼져 있어요 / 공유기 주소가 바뀌었어요. · 마지막 연결 10:24 · 다음 자동 확인 10:55 | `다시 시도` |

| I' | 직원 0명 | 화면 안 | (muted) | 아직 고용한 직원이 없어요 | 직원 고용은 PC에서 할 수 있어요. | 없음 |
| J | 로딩 | 화면 안 | — | (제목 옆 "불러오는 중…") | 요약 타일 4칸·목록 3행 뼈대(`surfaceMuted`, 깜빡임 없음). **스피너 쓰지 않음.** 2초 이상 걸리면 그대로 유지 | 없음 |
| K | 서버 오류 | 배너(error) | ⨯ | — | PC에서 문제가 생겼어요. 잠시 후 다시 시도할게요. | `다시 시도` |
| L | 앱 오류 | 전체 | ⨯ (error) | 앱에서 문제가 생겼어요 | 앱을 최신 버전으로 업데이트해 주세요. 계속되면 PC에서 확인해 주세요. | `다시 시도` |

- 상태 화면이 떠 있어도 **설정 탭의 "연결 끊기"는 항상 갈 수 있게** 상단 오른쪽에 설정 아이콘 버튼(48dp)을 둔다(D·E·F·G·H).
- 카운트다운(F)은 `retryAt - serverTime 보정 현재`로 계산하고, 앱을 다시 열었을 때도 이어진다(`retryAt` 저장). 0 전에는 **백그라운드 조회도 하지 않는다.**

## 6. 프로토콜 오류 코드 ↔ 화면 대조 (`remote-protocol-v1.md` 7절)
**1:1로 맞는다**는 것은 "앱 로직이 `error`(없으면 HTTP 상태)로 분기했을 때 갈 화면이 하나로 정해진다"는 뜻이다.

| HTTP · `error` | 프로토콜 앱 동작 | 화면 | 백그라운드 조회 |
|---|---|---|---|
| 400 `invalid_request` | 입력 확인 안내, 재시도 안 함 | 입력칸 아래 빨간 줄 "보낼 수 없는 내용이에요. 글자 수를 확인해 주세요."(지시·답·의견) | 영향 없음 |
| 400 `invalid_action` | 목록 새로 읽고 다시 시도 | 스낵바 "결정 내용이 바뀌었어요. 목록을 새로 불러왔어요." + 목록 새로고침 | 영향 없음 |
| 401 `unauthorized` | "다시 연결이 필요해요" | **E** 인증 실패 | **멈춤**(아래 제안 1) |
| 401 `token_revoked` | 토큰 삭제·재시도·조회 중단 | **D** 토큰 폐기 | 멈춤 |
| 401 `auth_locked` + `retryAt` | `retryAt`까지 요청 안 함, 카운트다운 | **F** 잠김 | `retryAt`까지 멈춤 |
| 404 `not_found` | 앱 버그 | **L** 앱 오류 | 영향 없음 |
| 404 `staff_not_found` | "직원을 찾을 수 없어요" 후 새로고침 | 스낵바 "직원을 찾을 수 없어요. 목록을 새로 불러왔어요." → 직원 목록으로 | 영향 없음 |
| 405 `method_not_allowed` | 앱 버그 | **L** | 영향 없음 |
| 409 `already_decided` | "이미 처리됐어요" 후 새로고침 | 카드 자리에 "이미 처리됐어요"(1.5초) → 사라짐. 재시도에서 온 409는 **표시 없이** 새로고침만 | 영향 없음 |
| 413 `payload_too_large` | 글을 줄이도록 안내 | 입력칸 아래 "글이 너무 길어요. 줄여서 보내 주세요." | 영향 없음 |
| 415 `unsupported_media_type` | 앱 버그 | **L** | 영향 없음 |
| 426 `protocol_unsupported` + `supported` | 2-4절 | **H**(`supported`에 앱이 아는 값보다 큰 것만 있으면 "앱 업데이트", 작은 것만 있으면 "PC 업데이트") | 멈춤 |
| 429 `rate_limited` + `retryAfterSec` | 그 뒤 재시도 | 화면 없음(자동 재시도). 사용자가 누른 동작이면 버튼 "잠시 후 다시 보내요…" | 미룸 |
| 500 `internal_error` | "PC에서 문제가 생겼어요", 잠시 후 재시도 | **K** 배너 | 다음 주기에 재시도 |
| 503 `office_unavailable` + `retryAfterSec` | 그 뒤 재시도 | 배너(muted) "PC의 Claude Office가 준비 중이에요." | 미룸 |
| 응답 없음 — 연결 거부 | 구분 가능한 범위에서 | **A** 원격 꺼짐 (제안 2) | 다음 주기 |
| 응답 없음 — 시간 초과 | 〃 | **B** 절전·PC 응답 없음 (제안 2) | 다음 주기 |
| 응답 없음 — 휴대폰 오프라인 | 〃 | **C** 끊김 배너 | 네트워크 조건으로 대기 |
| TLS 지문 불일치 | 인증서 불일치 화면, 무시 버튼 없음 | **G** | 멈춤 |
| QR `v` > 앱 최대 | 연결 시도 없이 업데이트 안내 | **H**(앱) | — |
| 응답 `protocolVersion` > 앱 | 응답 쓰지 않음, 업데이트 안내 | **H**(앱) | 멈춤 |
| 모르는 `error` 값 | HTTP 상태로 처리 | 같은 HTTP 상태의 위 행(401이면 E, 4xx 나머지 L, 5xx K) | 상태별 |

**대조 결과: 모든 코드가 화면 하나에 대응한다.** 다만 프로토콜 문서에 아래 두 가지를 보탤 것을 김버전에게 제안한다(문서는 고치지 않았다).
1. **`unauthorized` 수신 후 앱 동작이 정해져 있지 않다.** 프로토콜은 "다시 연결이 필요해요"만 적었다. 앱이 같은 토큰으로 15분마다 계속 조회하면 실패 횟수가 쌓여 **스스로 IP 잠금**을 부를 수 있다. 제안: `unauthorized`도 `token_revoked`처럼 **자동 조회를 멈추고 토큰은 보관**(사용자가 QR을 다시 찍을 때 교체). 디자인은 이 제안을 전제로 E 화면을 그렸다.
2. **"응답 없음"을 원격 꺼짐과 절전으로 나누는 규칙이 없다.** 과업은 둘을 다른 화면으로 요구하지만, 프로토콜 7절은 "가능한 범위에서 구분"이라고만 한다. 제안 규칙(앱 판단):
   - 휴대폰 자체가 오프라인 → **C**
   - TCP 연결 거부(RST, 즉시 실패) → PC나 공유기는 살아 있고 문이 닫힘 → **A 원격 꺼짐**(앱이 꺼진 경우도 여기에 들어감)
   - 시간 초과(10초) → **B 절전·PC 응답 없음**
   - 공유기가 끊긴 포트를 거부 대신 버리는 기종에서는 원격 꺼짐도 B로 보인다. 그래서 B의 설명은 원인을 단정하지 않고 "이런 경우일 수 있어요" 목록으로 썼다. QA 실기기에서 기종별로 확인 필요.
