# 사무실 개편 — 아이소메트릭 그림체 시안

> 사무실 개편 설계 단계 2/4 · 작성 이디자 · 2026-10-24
> 짝 문서: [office-iso-levels.md](office-iso-levels.md)(레벨 1~20표, 김기획). 단계 구분은 그 표의 층·외관 단계(E1~E7)와 맞췄다.
> 그림 코드: `app/src/renderer/map/iso/isoArt.ts` 하나 (앱·시제품·생성기가 같이 씀, 9절) · 결과: `docs/specs/office-iso-art/`
> 다시 만들기(app 폴더에서): `node --disable-warning=MODULE_TYPELESS_PACKAGE_JSON scripts/iso-art.mts ../docs/specs/office-iso-art`
> 시안 단계의 생성기 `scripts/iso-art.mjs`는 A3에서 지웠다. `A-*`·`B-*`·`sheet-A/B`·`stage-1~5.png`는 시안 기록으로 남겨 둔다.

## 0. 참고 사진에서 가져온 것
대표님 사진 3장(쇼핑몰·옥상 전망대·집 꾸미기)의 공통점: **2:1 마름모 바닥 · 뒤쪽 벽 두 면만 세움 · 밝은 파스텔 · 1px 진한 외곽선 · 왼쪽 위에서 오는 빛(윗면 밝음, 오른쪽 면 가장 어두움) · 머리가 큰 2.5등신 캐릭터**. 시안도 이 여섯 가지를 규칙으로 고정했다.

## 1. 규격

| 항목 | 값 | 비고 |
|---|---|---|
| 픽셀 배율 | **아트 1px = 화면 2px** | 지금 `sprites.ts`의 `PIXEL = 2`와 같다 |
| 칸(마름모) | **아트 32×16 = 화면 64×32** | 2:1. 칸 모서리 선이 1px 계단 2칸씩으로 깨끗하게 떨어진다 |
| 바닥판 두께 | 아트 4px | 바닥 가장자리에 두께가 보인다(사진 2·3) |
| 벽 높이 | **아트 48px = 칸 높이 16 × 3** (화면 96px) | 창(아트 24px)·액자·화이트보드가 들어가는 높이 |
| 벽 두께 | 칸의 0.18 | 벽 윗면(캡)이 흰 띠로 보인다 |
| 벽 | 뒤쪽 두 면만(왼쪽 위·오른쪽 위). 앞쪽 벽은 그리지 않는다 | 가구·직원이 가려지지 않게 |
| 가구 높이 기준 | 책상 상판 12~14 · 의자 좌석 9~12, 등받이 25 · 소파 등 20 | 칸 한 변 ≈ 1m 기준 |
| 직원 | **아트 16×26**(서기, 외곽선 포함) · 앉기 16×22 | 칸 폭의 절반. 지금 직원(16×24)과 같은 폭 |
| 외관 한 층 | 아트 40px | 외관은 안보다 낮춰 층수가 잘 보이게 |

**좌표·돌리기**
- 칸 좌표 (gx, gy, z) → 화면 x = (gx − gy)·16, y = (gx + gy)·8 − z (아트 px).
- 가구는 **칸 단위 상자(부품) 여러 개**로 정의한다. 돌리기는 부품 좌표를 90°씩 돌려서 얻으므로 **4방향을 따로 그리지 않는다**(시안의 책상·의자 4방향이 이 방식). 1×2 가구는 돌리면 2×1 칸을 차지한다.
- 방향 이름: r0 = 사람이 화면 왼쪽 아래(↙)를 봄, r1 = ↖, r2 = ↗, r3 = ↘.
- 그리는 순서: 칸 위 상자끼리 "한 축으로 떨어져 있으면 작은 쪽이 뒤"로 정렬한다. 앉은 직원은 의자를 **좌석/등받이 두 장**으로 나눠 그 사이에 끼운다(지금 `drawChairBack`/`drawChairEmpty`를 나누는 방식과 같음).
- 직원 방향: 앞모습(↙)·뒷모습(↖)만 그리고 좌우 반전으로 ↘·↗을 얻는다 → 4방향.

## 2. 빛·그림자·외곽선 규칙

| 규칙 | A 파스텔 | B 비비드 |
|---|---|---|
| 빛 | 왼쪽 위. 윗면 = 원색, 왼쪽 아래 면 = 그림자색 12%, 오른쪽 아래 면 = 26% | 같은 방향, 18% / 36% (대비 큼) |
| 그림자색 | 원색에 **남색 `#4a4f80`**을 섞는다 — 회색·검정을 섞지 않는다 | `#1c2148` |
| 윗면 하이라이트 | 앞쪽 두 모서리 1px을 흰색 40% | 흰색 50% |
| 외곽선 | **바깥 실루엣만 1px**, 닿은 색을 `#2e2a40` 쪽으로 72% 어둡게(색 있는 외곽선) | **부품마다 1px**, `#1a1726` 단색(검은 테두리 만화풍) |
| 바닥 그림자 | 가구: 차지한 칸보다 0.08칸 넓은 마름모, 남색 18% · 직원: 12×5 타원, 같은 색 | 남색 24% |
| 디더링 | 쓰지 않는다 | 쓰지 않는다 |

- 외곽선 두께는 아트 1px(화면 2px)로 둘 다 같다. 사진의 "굵은 외곽선" 느낌은 화면 2px에서 나온다.
- 그림자를 남색으로 섞는 이유: 앱 배경이 남색(`--background` ≈ `#0d1014`, 카드 `#15181e`)이라 맵 둘레와 이어져 보인다.

## 6. 레벨이 오를 때 좋아지는 단계

김기획 레벨표(2-2절)의 바닥·벽 열을 **재질 5단계(M1~M5)**로 묶었다. 층이 느는 레벨(6·10·14·18)에 재질 단계도 바뀌게 맞춰, "층이 늘면 안도 확 바뀐다"가 보이게 했다. 같은 단계 안의 레벨은 레벨표의 -1·-2·-3 꾸밈(러그·몰딩·창 개수·간판)만 더한다.

| 단계 | 레벨 | 바닥 | 벽 | 외관 (레벨표 E 단계) | 그 안에서 오르는 것 |
|---|---|---|---|---|---|
| **M1** | 1~2 | 콘크리트 | 시멘트 블록 | E1 차고 (셔터) | Lv.2 러그·작은 창·간판 |
| **M2** | 3~5 | 장판 → 타일 | 흰 페인트 (+몰딩 Lv.5) | E2 1층 상가 (줄무늬 차양) | 창 2→3, 조명 간판 |
| **M3** | 6~9 | 카펫 타일 → 원목 마루(Lv.8) | 벽돌 포인트 → 목재 패널(Lv.8) | E3 2층 벽돌 | 화분·벤치 → 캐노피 → 조경 |
| **M4** | 10~13 | 원목 → 헤링본 마루(Lv.12) | 목재 패널 + 루버 | E4 3층 오피스(목재·큰 창) | 옥외 간판 → 주차장 → 정원 |
| **M5** | 14~20 | 테라조 → 대리석 + 금장 줄눈(Lv.18) | 통유리 → 대리석 패널 + 금속 | E5 4층 유리 사옥 → E6 5층 타워(금장 띠) → E7 캠퍼스(Lv.20) | 로고 → 분수 → 옥상 → 야간 조명 |

- 레벨표와 다른 점: 레벨표는 Lv.8에 바닥·벽이 원목으로 바뀌는데, 재질 단계는 층 기준으로 묶어 **M3 안의 변형**으로 두었다. 레벨표를 고칠 필요는 없다.
- 시안의 `stage-*.png`는 각 단계의 대표 재질 하나씩(M1 콘크리트·블록, M2 타일·흰 페인트, M3 카펫·벽돌, M4 헤링본·목재 패널, M5 대리석 금장·통유리). `exterior-*.png`는 E1~E6. **E7 캠퍼스(본관+별관·광장)는 시안에 넣지 않았다** — 건물 여러 채 배치가 박패턴 기술 설계(외관 칸 크기)에 달려 있어 다음 단계로 넘긴다.
- 업무 모드: 재질·외관은 그대로 보인다(게임 요소가 아니라 사무실 모습). 숨길지는 확인 필요.

## 7. 정해 주실 것

1. **그림체: A 파스텔(권장) / B 비비드.**
2. 직원 크기: 칸 폭의 절반(지금과 같은 16px 폭)으로 했다. 사진 1처럼 더 크게(20px 폭) 할지.
3. 재질 단계 5개(M1~M5)를 층 기준으로 묶는 안. 레벨마다 조금씩 바뀌는 레벨표 그대로를 원하면 단계 대신 재질 목록을 늘린다.

## 8. 알아 둘 것 · 넘길 것
- 시안의 가구 부품 수치는 **보여 주기용**이다. 박패턴 기술 설계에서 부품 정의 형식(`{x,y,w,d,z,h,색}`)과 정렬 방식을 확정하면 그대로 옮길 수 있게 썼다.
- 걷기 동작(발 바꾸기 프레임)은 시안에 없다. 지금 `walk1`/`walk2` 방식을 앞·뒤 두 방향에 그대로 적용하면 된다.
- 레벨 전용 가구(레벨표 2-3절)의 그림은 이번 범위 밖. 같은 부품 방식으로 그리면 칸 크기만 정해지면 바로 나온다.

## 9. 구현 (A3, 2026-10-24) — 대표님 확정: A 파스텔 · 직원 폭 칸의 절반 · 바닥·벽 M1~M5

### 9-1. 한 곳으로 합침
- 시안 생성기(`iso-art.mjs`)와 시제품 그림(`isoArt.ts`)에 같은 그리기 코드가 두 벌 있던 것을 **`isoArt.ts` 하나**로 모았다. 정리드(A2)가 바꾼 `item-{itemId}` 방식도 그대로 이어받았다.
- 그리기는 DOM 없이 픽셀 배열(`Cv`)에 하고, 화면에서만 `toCanvas()`로 캔버스를 만든다. 생성기 `scripts/iso-art.mts`는 같은 픽셀을 PNG로 쓴다. 노드에서도 읽히게 `isoArt.ts`는 상대 경로 + `.ts`로 가져온다.
- 칸 크기는 A2 `shared/iso/furniture.ts`의 `FURNITURE`를 따른다. 생성기가 그림 크기와 규격 크기를 비교한다(지금 불일치 0).

## 11. 상점 벽지 15 · 바닥재 14 덮어쓰기 (2026-10-24) — 대표님 결정: 덮어쓰기 유지

### 11-1. 규칙
- 산 벽지·바닥재를 구역에 고르면(`ShopState.surfaces`) 그 자리의 **레벨 기본 재질(M1~M5) 대신** 그린다. 고르지 않았으면 레벨 기본 그대로. 상점 "기본으로"가 해제.
- 칸 사무실의 구역: **업무 구역 = 방 바닥 + 뒤쪽 벽 두 면**(모든 층), **회의실 = 회의실 바닥 + 회의실이 기댄 뒤쪽 벽 구간**(회의실 왼쪽 끝 칸부터 벽 끝까지, 유리 너머로 보임). 회의실 바닥재를 고르지 않으면 지금 연파랑 카펫.
- **휴게실**은 칸 사무실에 구역이 없어 쓰지 않는다. 저장값은 지우지 않고, 칸 사무실 상점에서는 바닥재의 휴게실 버튼을 숨긴다(예전 장면은 그대로 3구역).
- 창: 벽지 위에도 레벨의 창을 그대로 단다. 통유리 단계(Lv.14~17, 창 0) 위에 벽지를 바르면 창 6개(M4 끝과 같음). `wall-glass`(통유리 커튼월)는 창·몰딩 없이 유리 너머 도시.
- 그림은 `isoArt.ts` `SHOP_FLOORS`·`SHOP_WALLS`(키 = 상점 품목 id), 합치는 곳은 `withSurfaces(finishOf(level), surfaces, 회의실 x0)` 하나. 방 텍스처 키에 들어가므로(`finishKey`) 고를 때마다 그 방을 한 번 새로 굽는다.

- 칸 사무실이면 벽지·바닥재 카드에 **3×3 방 모서리 그림**(`drawSurfaceThumb`, 1배로 그려 카드 높이 92px에 맞춤). 바닥재는 흰 페인트 벽, 벽지는 타일 바닥과 함께, 창 없이 무늬만. 예전 장면은 CSS 견본 그대로.
- 벽지·바닥재는 꾸미기 서랍에 넣지 않으므로(김기획 6-1절) 서랍 카드는 없다.

### 11-4. 성능 (폰 390·3배율·CPU 6배, Lv.20·가구 99/층·직원 20, 6-6절과 같은 측정)

### 11-6. 알아 둘 것
- 헤링본 원목(상점)은 넓은 방에서 보면 결보다 체크 무늬처럼 읽힌다(레벨 헤링본과 같은 식). 실제 화면을 보고 손볼 수 있다.
