# 업무 매뉴얼 (스킬) 설계 — 2026-10-21 결정, 미착수

## 용어
- **업무 매뉴얼** = Claude Code 스킬을 사무실식으로 부르는 이름
- **개인 매뉴얼**: 한 사람이 이 일을 어떤 순서로 하나 (fix-qa, commit) → 직원에게 교육
- **프로세스 매뉴얼**: 여러 사람이 누가 어떤 순서로 넘겨받나 (feature-flow) → 팀·랩에 교육

## 결정 사항
| 항목 | 결정 |
|---|---|
| 프로세스 실행 | **앱이 단계를 직접 진행** (단계 = 담당 역할 · 지시 · 넘겨받는 산출물 · 내 확인 여부 · 되돌아가기 규칙) |
| 단계 담당 | **역할(직무)로 지정** → 실행할 때 그 랩·팀에서 해당 직무 직원이 맡음 (다른 랩에서도 재사용) |
| 프로세스 시작 | 업무 보드 카드("프로세스로 진행") · 랩 화면(새 일감) · 지시창(리드에게 프로세스 선택) |
| 단계 사이 확인 | **단계별 설정** — "끝나면 내 확인" 체크한 단계만 멈춤, 나머지는 자동으로 넘김 |
| 저장 위치 | **만들 때마다 고르기** — 프로젝트(`<폴더>/.claude/skills`) / 내 계정(`~/.claude/skills`) |
| 작성 | 양식에 직접 쓰기 + 직원에게 초안 맡기기 |
| 교육 | **교육받은 것만 사용** — 직원 장비의 스킬을 교육 목록으로 제한, 프로필에 📘 배지 |
| 쓰는 법 | 지시창 "📘 매뉴얼" 버튼·`/` 목록에서 고르기 + 직원이 교육받은 매뉴얼을 알아서 꺼내 씀 |
| 연출 | 매뉴얼을 꺼내 쓸 때 책장에 다녀오거나 머리 위 📘 |
| feature-flow | 문서를 읽어 small·medium·large **단계형 프로세스 매뉴얼 3개**로 바꿔 "기능 구현 랩"에 붙임 (원본 md는 그대로) |

## 형식 (안)
- 개인 매뉴얼: 표준 `SKILL.md` (name·description + 본문)
- 프로세스 매뉴얼: `SKILL.md` + frontmatter `kind: process`, 본문에 단계 정의(YAML 블록)
  - step: `id`, `role`, `instruction`, `needsMyCheck`, `onRevise: <되돌아갈 step id>`, `maxLoops`
- 실행 상태(어느 단계까지 왔는지)는 앱 DB에 저장, 보드 카드에 진행도 표시
