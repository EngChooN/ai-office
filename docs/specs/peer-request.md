# 직원끼리 일 주고받기 (도움 요청) 기획서

작성: 김기획 (PM) · 상태: 대표 결정 대기 · 코드 수정 없음

## 한 줄 요약
지금은 팀장·랩 리드만 다른 직원에게 말을 걸 수 있습니다. 팀원도 **"도움 요청"** 으로 다른 직원에게 일을 부탁할 수 있게 하되, 팀장에게 자동으로 알려 주고 단계·횟수 제한을 두는 안을 권합니다.

---

## 1. 지금 무엇이 막히는지

**대표님 사례**
팀장이 김기획에게 기획서를 맡겼습니다. 대표님이 김기획 창에서 결과를 보니 사진이 없어서 "이디자한테 시켜서 사진 추가해"라고 했습니다. 그런데 김기획은 팀장이 아니라서 이디자에게 말을 걸 수 없었고, 일이 거기서 멈췄습니다.

**코드 근거** (`app/src/main/office.ts`)
- `delegatesOf()` (약 2109줄): "팀장이면 팀원, 랩 리드면 랩 멤버"만 돌려줍니다. 팀원이면 빈 목록입니다.
- `delegate` 도구 (약 2175~2178줄): 대상 목록이 비어 있으면 "팀장이 아니다"라는 안내만 하고 끝납니다.
- `propose_plan` 도구 (약 2283~2284줄): 같은 목록을 쓰므로 팀원은 기획안도 올릴 수 없습니다.
- 지시가 전달될 때는 `Origin = { kind: 'delegate', leadId }` 로 표시됩니다. "리드가 맡긴 일"만 가정하고 만든 구조라서, 팀원이 맡긴 일을 나타낼 이름이 따로 없습니다.

**이미 있는 안전장치** (그대로 재사용 가능)
- 자율 진행 여부를 맡긴 일에 이어 줍니다 (`hasAutonomousOrigin`).
- 다른 PC에서 온 일은 연쇄 위임을 막습니다 (`peer.guard.noChain`, `noCopyChain`, `busyPeer`).
- 대상이 다른 일로 점유돼 있으면 거절합니다.
- 맡길 때 채팅에 `@이름 내용`이 남고 활동 기록(log)에 'delegate'가 남습니다.

## 3. 권한 표 (권고안 A 기준)

| 할 수 있는 일 | 팀장·랩 리드 | 팀원 |
|---|---|---|
| 같은 팀·랩 직원에게 바로 맡기기 (`delegate`) | ✅ | ❌ (도움 요청으로 대체) |
| 도움 요청 (`request_help`) | ✅ (필요 없음, delegate 사용) | ✅ 같은 팀·같은 랩 직원에게 |
| 기획안 올리기 (`propose_plan`, 업무 카드 생성) | ✅ | ❌ (카드는 팀장만 만든다) |
| 다른 팀 직원에게 요청 | ✅ (자기 랩 멤버라면) | ⚠️ 같은 랩에 속한 경우만, 아니면 팀장 경유 |
| 다른 PC 직원에게 요청 | ✅ (기존대로) | ❌ (승인 주체가 끊기므로 막아 둠) |
| 결재(승인) 넘기기 | 대표에게 올림 (기존) | 대표에게 올림 (기존과 같음, 요청받은 일의 결재도 대표 몫) |
| 요청 결과 받기 | 보고로 받음 | 부탁한 사람에게 결과 전달 |

**원칙**
- 부탁한 사람이 결과 책임을 집니다. 받은 사람은 일을 하고 "부탁한 사람"에게 보고합니다.
- 카드 생성·기획안은 계속 팀장·랩 리드 전용입니다. 팀원 간 요청은 "작은 부탁"이지 새 프로젝트가 아닙니다.
- 결재 규칙은 바뀌지 않습니다. 받은 일에서 파일 수정·명령 실행이 생기면 받은 사람의 결재 모드대로 대표에게 올라갑니다.
- 자율 진행 중인 일에서 시작된 요청은 자율로 이어집니다 (기존 `isAutonomous` 전달 방식 그대로).

## 4. 무한 떠넘기기·중복·토큰 낭비 막는 장치

| 문제 | 장치 | 기본값 (제안) |
|---|---|---|
| A→B→C→A 떠넘기기 | **깊이 제한**: 도움 요청으로 받은 일에서 또 도움 요청은 1단계까지만 | 최대 2단계 |
| 같은 부탁 반복 | **중복 차단**: 같은 사람이 같은 대상에게 이미 처리 중인 요청이 있으면 거절 | 대상당 1건 |
| 요청 폭주 | **횟수 제한**: 한 직원이 한 업무 안에서 보낼 수 있는 도움 요청 수 | 업무당 3건 |
| 이미 바쁜 직원에게 몰림 | 대상이 처리 중이면 "대기열에 쌓임"으로 알려 주거나 거절 (기존 `busy` 방식) | 대기 1건까지 |
| 팀장이 모르고 진행 | **팀장 자동 알림**: "OO이 △△에게 ~를 부탁함" 한 줄 | 항상 켜짐 |
| 기록 남지 않음 | **업무 보드·활동 기록**: 카드 댓글/기록에 "누가→누구에게, 내용, 결과" 남김 | 항상 켜짐 |
| 빙빙 도는 토큰 낭비 | 부탁 내용은 길이 제한, 결과는 요약만 전달 | 요청문 800자 |
| 다른 PC 연쇄 | 기존 차단 규칙 유지 | — |

팀장이 원하면 특정 팀원의 도움 요청을 끌 수 있는 스위치(팀 설정)를 둘 수 있습니다. (2차 범위)

## 5. 대표 화면에서 어떻게 보이는지

- **채팅·활동 기록**: `김기획 → 이디자: 기획서에 메뉴바 사진 추가해 주세요 (도움 요청)` 처럼 한 줄로 표시. 지금의 `@이름` 표시를 재사용합니다.
- **받은 직원 창**: "김기획 님이 부탁한 일" 이라는 꼬리표가 붙습니다.
- **업무 보드 카드**: 해당 카드의 기록에 "요청 → 결과" 흐름이 남습니다. 카드 없는 일이면 활동 기록에만 남습니다.
- **팀장 창**: 알림 한 줄 (대화를 가로막지 않는 일반 알림).
- **결과**: 이디자가 끝내면 김기획에게 보고가 가고, 김기획이 대표님께 최종 정리해서 보고합니다. 대표님은 처음 말을 건 김기획 창에서 결과를 이어서 봅니다.
- **결재**: 이디자의 작업이 결재를 요구하면 이디자 이름으로 결재함에 올라가고, "김기획 님의 요청" 이라고 출처가 보입니다.

## 6. 권고안

**A. 팀원 도움 요청 허용 + 팀장 자동 공유 + 제한 장치**

이유: 대표님이 겪은 막힘을 바로 풀고, 팀장 승인을 거치지 않아 느려지지 않으며, 깊이·횟수·중복 제한과 알림으로 통제할 수 있습니다. B는 안전하지만 막힘이 팀장 대기로 옮겨질 뿐이고, C는 범위가 좁습니다.

### 작업 범위·크기 (개략)
| 항목 | 내용 | 크기 |
|---|---|---|
| 새 도구 `request_help` | 팀원용. 같은 팀·랩 직원 대상. `delegatesOf`와 별도로 `helpTargetsOf` 추가 | 소 |
| Origin 추가 | `{ kind: 'help'; fromId; depth }` — 출처 표시, 깊이 계산 | 소 |
| 제한 장치 | 깊이·횟수·중복 검사, 요청문 길이 제한 | 중 |
| 팀장 알림 | 요청 발생 시 팀장에게 알림/채팅 한 줄 | 소 |
| 화면 표시 | "도움 요청" 꼬리표, 결재함 출처 표시, 카드 기록 | 중 |
| 문구 4개 언어 | 한/영/일/중 | 소 |
| 검증 | 단위 테스트(제한 장치), 사례 재현(김기획→이디자), 기존 delegate·propose_plan 회귀 | 중 |
| **합계** | 약 3~4일 | |

**제외**: 다른 PC 직원에게 팀원이 요청하는 기능, 팀원의 기획안·카드 생성, 팀별 끄기 스위치(2차).

### 완료 기준
1. 김기획(팀원)이 이디자에게 사진 추가를 부탁하면 이디자가 일하고 결과가 김기획에게 돌아온다.
2. 팀장에게 알림이 가고 대표 화면에 "누가 → 누구에게"가 보인다.
3. 깊이 2 초과, 같은 대상 중복, 업무당 3건 초과는 거절되고 사유가 보인다.
4. 팀원이 `delegate`·`propose_plan`을 쓰면 안내문이 "도움 요청을 쓰세요"로 바뀐다.
5. 기존 팀장 위임·기획안·결재·자율 진행·다른 PC 위임이 그대로 동작한다.

### 대표님이 정할 것
1. 권고안 A로 갈지 (대안: 승인형 B).
2. 팀원이 다른 팀 직원에게도 부탁할 수 있게 할지 (기본: 같은 팀·같은 랩만).
3. 제한값 (깊이 2, 업무당 3건) 괜찮은지.
4. 팀장 알림을 매번 띄울지, 활동 기록에만 남길지 (기본: 활동 기록 + 가벼운 알림).

## 가정·확인 필요
- 확인 필요: `Origin` 추가 시 결재·자율 진행 판정(`resolveAutonomy`)이 새 종류를 올바르게 이어받는지 개발 확인 필요.
- 확인 필요: 요청 결과를 부탁한 사람에게 돌려주는 기존 경로(`o.kind === 'delegate'` 처리, 약 1598줄)를 새 종류로 확장하는 방식.
- 확인 필요: 업무 보드 카드가 없는 일의 기록을 어디에 남길지.
- 가정: 팀원 간 요청의 결재는 기존처럼 대표 몫이다.
- 코드는 읽기만 했고 앱은 실행하지 않았습니다. 줄 번호는 현재 파일 기준이며 바뀔 수 있습니다.
