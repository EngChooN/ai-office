# 비서가 막힌 기능 조사 (secretary-gaps)

## 조사 방법과 한계
- 대상: `office.db`의 `secretary_message` 77건(2026-10-24 13:34 ~ 10-26 18:16). 읽기 전용 복사본으로 조회했어요.
- 구성: 대표 요청(me) 18건, 비서 답변(secretary) 33건(카드 안내 포함), 자동결재 알림(notice) 26건. 알림은 "답하지 못한 질문" 같은 시스템 문구라 비서의 거절이 아니어서 뺐어요.
- 비서 답변 전부를 사람이 읽고 "못 한다/확인하지 못했다/앱에 없다"로 답한 경우를 골랐어요(키워드 검색이 아님).
- **표본이 작아요.** 보관 기간(`KEEP_DAYS`)이 지난 대화는 앱이 지워서 3일치뿐이에요. 빈도는 참고용이고, 더 긴 기간 근거가 필요하면 확인 필요.

## 1. 요청 유형별 정리

| # | 요청 유형 | 대표 요청 예 (메시지 id) | 빈도 | 막힌 이유 | 필요한 메서드 | 기획서 범위 |
|---|---|---|---|---|---|---|

기타: "이 사무실과 무관한 질문엔 답하지 않는다"는 의도된 제한이라 막힌 기능으로 세지 않았어요.

## 2. 우선순위 제안
1. G1·G2는 이미 기획서 5번·2번이라 이번에 채워요.
2. 범위 밖 중 효과가 큰 순서: G3(멈춘 직원 진단, 대표가 가장 오래 매달린 사례) → G5 → G6 → G4.
3. G3은 읽기 메서드 하나로 풀 수 있어서 이번 배포에 끼울지 대표 확인이 필요해요(범위 확대).

## 3. 범위 밖 요청에 붙일 "대신 할 방법" 안내 문구 (한국어)
비서가 못 하는 이유를 한 줄로 말하고, 화면 링크(`#view=...`)로 바로 갈 길을 알려 줘요. 4개 언어 키는 구현 때 `secretary.gap.*`로 둬요.

| 유형 | 안내 문구 |
|---|---|
| G3 진단 | 지금은 직원이 멈춘 건지 오래 생각하는 건지 제가 구분하지 못해요. [사무실](#view=map)에서 직원을 눌러 최근 기록을 보시거나, [단체방](#view=chat)에서 @이름으로 지금 상태를 물어보세요. 오래 응답이 없으면 '멈추기' 뒤에 다시 지시하는 방법도 있어요. |
| G4 파일 위치 | 파일이나 폴더를 제가 직접 열 수는 없어요. 빌드를 맡은 직원에게 "최신 빌드 위치를 알려 달라"고 지시하거나, 직원 창의 '변경' 탭에서 파일 경로를 확인해 주세요. 지시 카드는 제가 만들어 드릴게요. |
| G5 카드 수정 | 이미 올린 카드는 제가 고칠 수 없어요. 새 카드를 만들 테니, 앞 카드는 [실행]하지 말고 닫아 주세요. |
| G6 기능 여부 | 그 기능이 앱에 있는지 제가 확인하지 못했어요. 없다면 업무 카드로 올려 개발 담당에게 맡길 수 있어요. 카드를 만들까요? |
| 구매·바닥·벽·보상·장신구 (기획서 5번에서 계속 막는 것) | 구매와 바닥·벽 바꾸기, 미션 보상 받기, 직원 장신구는 대표님이 직접 즐기시는 부분이라 제가 대신하지 않아요. [상점](#view=shop)이나 [설정·꾸미기](#view=settings)에서 직접 해 주세요. |

## 4. 구현 메모 (강백엔·최가독용)
- 제외 목록은 `shared/secretaryTools.ts`의 `exclude` 항목이에요. 꾸미기 중 **풀 것**은 `placeItem`·`moveItem`·`storeItem`·`placeGridItem`·`moveGridItem`·`setGridItemOn`·`stowAllGrid`·`restoreGridItems`이고, **계속 막을 것**은 `buyItem`·`applySurface`·`claimMission`·`setGear`예요. `setGear`는 직원 장신구가 맞는지 확인 필요.
- 한 카드 단계 상한 `CARD_STEPS_MAX = 8` 때문에 가구 전부 치우기는 단계를 늘리지 말고 `stowAllGrid`(이미 있음) 또는 새 묶음 메서드를 쓰는 편이 맞아요.
- G2는 코드에서 `Manual.body`가 이미 있어서, 비서가 못 읽는 원인(조회 결과 축약 여부)을 먼저 확인해야 해요(`main/secretary.ts`의 스냅샷 구성, `main/secretaryCore.ts` 조회 결과 처리).


## 5. 이번에 채운 것 (강백엔, 0.13.0 — 미커밋)
기획서 2번(매뉴얼)과 4번(직원 관리) 범위만이에요. 결재 규칙·직원 권한은 넓히지 않았어요.

| 항목 | 상태 | 어떻게 |
|---|---|---|
| G2 매뉴얼 본문 읽기 | 채움 | 비서 도구 `read_manual(name, scope?, projectDir?)` — 본문 전체(2만 자까지)와 프로세스 단계, 경로를 원문 그대로. `listManuals`는 목록용 그대로 |
| G2 합치기·새로 쓰기·고치기 | 채움 | `saveManual` 단계에 원문↔수정본 비교(`compareSteps`). 고치기는 `previousPath`, 같은 이름·범위 덮어쓰기는 그 매뉴얼이 원문. 합치기는 `saveManual` + `deleteManual`을 한 카드로(위험 등급, 지울 본문도 비교에 보임) |
| 직원 업무 지침 점검 | 채움 | `staff_detail`로 지침을 읽고 고칠 점을 답에 정리 → `updateStaff({ systemPrompt })` 카드에 지금↔고친 지침 비교 |
| 예약 업무 조회 | 채움 | `overview(section: "schedules")` — 목록·id·요일·켬/끔. 없으면 `saveSchedule`(id는 새 UUID)로 추가 제안 |
| 예약 업무 저장·삭제 | 이미 있음 | `saveSchedule`·`deleteSchedule` — 지침·인자 모양만 보강 |
| 참고 문서 지정 | 이미 있음 | `setRefDocs` — 직원 상세에 지금 목록 표시, 목록 전체를 넘기도록 지침 보강 |
| 장비 목록 조회·지급 | 이미 있음 | `equipmentCatalog`(조회)·`setEquipment`(주의 등급) — 직원 상세에 지금 값 표시, 바꿀 칸만 고쳐 전체 객체로 넘기고 `allowedTools`·`disallowedTools`는 그대로 두도록 지침 보강. 카드를 만들 때 결재 없이 쓰는 도구가 늘거나 막은 도구가 풀리면 경고 |

남은 것: G1(꾸미기)·G3~G6은 이번 단계 범위 밖이에요. 실제 화면에서 비교 카드를 띄워 보지는 않았어요(QA 없음).

- G3 멈춘 직원 진단 (0.13.0 채움): 읽기 조회 `staffActivity(staffId)` — 마지막 활동·상태·대기 결재/질문·최근 도구/오류·대기열. 비서는 "왜 멈췄어?"에 이 결과로 답하고, 3절 G3 안내 문구는 조회가 불가능한 외부 직원일 때만 쓴다.
