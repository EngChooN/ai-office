# 여러 PC 한 랩 (PC 간 협업) — 결정 기록·기획서

> 작성: ai-office(리드) · 2026-11-01 · 대표와 논의해 확정한 내용
> 상세 기술 규격은 1단계 설계 문서(`docs/specs/multi-pc-protocol.md`)에서 정한다. 그 문서와 이 문서가 다르면 대표 결정인 이 문서가 우선이다.

## 1. 목적
배포처럼 특정 맥(B컴)에서만 할 수 있는 일이 있다. 대표가 평소 쓰는 맥(A컴)에서 B컴 직원에게 지시하고, 진행을 보고, 결재하고, 결과를 받을 수 있게 한다.
예: A컴에 리더·개발자, B컴에 디자이너·배포 담당 → 이들이 한 랩이 되고, A컴 리더가 B컴 직원에게 자연스럽게 일을 맡긴다.

## 2. 대표 결정 (확정)
| 항목 | 결정 |
|---|---|
| 전제 | A·B 모두 대표 본인 PC. 휴대폰 원격과 같은 신뢰 수준(내 기기끼리) |
| 본부 | A컴. 업무 보드·랩 정보는 A컴이 갖는다. B컴은 받은 일을 실행하고 보고한다 |
| 실행 위치 | 일은 그 직원이 있는 PC에서 실행한다(서명 인증서·로그인 등은 B컴 밖으로 나가지 않음) |
| 연결 | Tailscale(모바일 원격과 같은 방식). 처음 짝짓기는 **QR 또는 IP(+코드) 입력** |
| 직원 선택 | **A컴에서** B컴 직원 목록을 보고 랩에 넣을 직원을 고른다 |
| 결재 | B컴 직원의 결재 요청은 **A컴 화면**으로 넘어와 A컴에서 승인한다 |
| 파일 수정 | **복사본 + 변경 회수**: 일 시작 때 앱이 A컴 작업 폴더를 B컴으로 옮겨 주고, 끝나면 바뀐 부분만 A컴으로 돌아와 결재 카드로 뜬다 → 승인 시 반영. 비개발자도 git을 몰라도 된다 |
| 화면 | A컴 사무실 지도에 함께 앉아 있고 "원격" 표시. 연결이 끊기면 회색 |
| 진행 보기 | 실시간(내 직원처럼 대화·명령 진행이 보임) |
| 연결 끊김 | 맡긴 일은 "연결 대기"로 두었다가 B컴이 켜지면 자동으로 보낸다 |
| 휴대폰 원격 | 기존 QR 연결에 **IP 입력 방식 추가**(이번 작업에 함께 포함) |
| 범위 | 파일 복사본 작업까지 **한 번에** 만든다 |

## 3. 기존 기반 (다시 쓸 것)
- 원격 프로토콜 v2(`docs/specs/remote-protocol-v2.md`): `/v2/call`로 OfficeApi 전체 호출, `/v2/events` SSE, 첨부·파일 받기, 토큰·인증서 고정·잠금. A컴은 B컴의 v2 서버에 **클라이언트**로 붙는 구조를 기본안으로 한다.
- 모바일 원격 짝짓기(QR·토큰·Tailscale), `app/src/main/remote/*`.
- 리더의 `delegate`·[팀원 보고]·결재 흐름.

## 4. 완료 기준
1. A컴에서 QR 또는 IP 입력으로 B컴과 짝지을 수 있다. 휴대폰 원격도 IP 입력으로 연결할 수 있다.
2. A컴에서 B컴 직원 목록을 보고 골라 랩에 넣을 수 있다. 지도에 "원격" 표시로 보이고, 끊기면 회색이 된다.
3. A컴 리더가 `delegate`로 B컴 직원에게 일을 맡기면 B컴에서 실행되고, A컴에서 실시간 진행이 보이며, 결과가 [팀원 보고]로 돌아온다.
4. B컴 직원의 결재 요청이 A컴에 뜨고, A컴에서 승인·거절하면 B컴에 반영된다.
5. B컴이 꺼져 있으면 일이 "연결 대기"로 남았다가, 다시 연결되면 자동으로 전달된다.
6. 파일을 고치는 일은 복사본에서 하고, 변경 묶음이 A컴 결재 카드로 오며, 승인하면 A컴 폴더에 반영된다. 그사이 A컴에서도 같은 파일이 바뀌었으면 덮어쓰지 않고 충돌로 알린다.
7. 4개 언어 문구, 전체 테스트 실패 0, 타입 검사 통과, 보안 리뷰 통과.

## 5. 보안 원칙
- 짝지은 PC만 접속(토큰·인증서 고정, 모바일과 같은 잠금 규칙). 짝짓기 해제 시 즉시 접속 불가.
- B컴이 A컴에 보내는 변경 묶음은 A컴 작업 폴더 밖 경로·심볼릭 링크·`.git` 내부를 건드릴 수 없다.
- 결재가 필요한 명령은 B컴에서 A컴 승인 없이는 실행되지 않는다.
