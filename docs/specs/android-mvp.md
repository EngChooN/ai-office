## 0. 현재 상태 (출발점)
- **밖에서 접속할 서버가 없다.** 화면과 본체는 Electron IPC(`office:<메서드>` invoke 약 80개 + 이벤트 `onSnapshot`·`onLog`·`onChat`·`onFocus`)로만 대화한다.
- 유일한 네트워크 서버는 외부 직원 hooks용 `http://127.0.0.1:47823`(`external.ts:88-103`)이다. 이 PC 안에서만 열리고 인증·암호화가 없다. **재사용하지 않는다.**
- 프로젝트는 git을 쓰지 않는다. "별도 diff"는 리뷰를 따로 받는 **별도 변경 묶음**을 뜻한다.

## 1. 목적과 범위 정의: 원격 컴패니언
PC에서 도는 Claude Office를 밖에서 안드로이드 폰으로 **확인하고 조종**한다.
- 앱이 하는 일: **상태 보기 · 결정 응답(결재·질문) · 지시 보내기 · 알림**.
- 앱이 하지 않는 일: 직원(에이전트) 실행, 파일 접근, 임의 명령 실행, 설정 변경. 이것들은 계속 PC에서만 한다.
- 비용: 별도 서버 없음(포트포워딩 + 토큰 인증).

## 4. 판단 사항 (이번 갱신에서 정한 것)

### 판단 1. 1.0.0 알림 기준을 WorkManager 조회로 충족할 수 있는가 → **조건부로 충족. "즉시 알림"이 아니라 "놓치지 않는 알림"으로 기준을 정의한다**
- WorkManager 주기 작업의 최소 간격은 15분이고, 안드로이드 절전(Doze)·앱 대기 버킷 때문에 실제 실행은 **수십 분~수 시간 늦어질 수 있다.** 충전 중이 아니고 화면이 꺼진 시간이 길면 더 늦다.
- 그래서 1.0.0 알림 완료 기준을 다음으로 정한다.
  1. 앱을 열면 즉시 최신 대기 결정을 보여 준다(포그라운드 조회).
  2. 백그라운드에서는 새 대기 결정을 **언젠가 반드시** 알린다(중복 없이, 놓치지 않게). 마지막으로 알린 결정 id를 저장해 비교.
  3. 앱·설정·첫 연결 가이드에 "알림이 수십 분 지연될 수 있음"을 명시하고, 배터리 최적화 예외 설정 화면으로 가는 버튼을 둔다.
- 이 기준으로 **"결재 때문에 직원이 멈춘 걸 결국 알게 된다"는 1.0.0 목적은 충족**한다. "몇 분 안에 응답" 수준은 충족하지 못하며 FCM(2단계)의 몫이다.
- QA는 Doze 강제 진입(`adb shell dumpsys deviceidle force-idle`)으로 지연 폭을 측정해 릴리스 노트에 실측치를 적는다.

### 판단 2. 단체방을 1.0.0에 넣을지 → **넣지 않는다. 대신 "지시 전송"에 단체방 멘션 방식(@팀·@전체)을 허용할지 대표 확인**
- 이유
  - 회의에서 정한 API 4종에 채팅 조회가 없다. 넣으면 API·실시간성 요구가 늘고, 15분 조회 구조와 맞지 않는다(대화가 수십 분 늦게 보임).
  - 원격 컴패니언의 핵심은 "멈춘 직원 풀어 주기 + 일 시키기"이며, 지시는 4번 API로 충족된다.
- 대안(확인 필요 D2): `POST /v1/instructions`의 대상에 직원 id 외에 `"chat"`(단체방으로 보내기, 멘션 규칙 그대로)을 허용하면 팀·랩 단위 지시를 채팅 화면 없이 할 수 있다. 결과는 상태 목록에서 확인.

### 판단 3. 포장 방식: Capacitor vs 네이티브 Kotlin → **네이티브 Kotlin(Jetpack Compose) 권고**
> **임안드 의견 미수렴:** 이번 단계에서 임안드에게 의견을 요청했으나 사무실 도구에서 "임안드를 찾지 못했습니다"로 위임이 거절됐다(김기획은 PO 팀 팀장이고 임안드는 랩 소속이라 맡길 수 없음). 아래는 김기획의 검토안이며, **리드(claude-office)가 임안드 의견을 받아 확정**해야 한다(확인 필요 D1). 임안드가 반대 의견이면 이 절을 갱신한다.

| 기준 | Capacitor (웹 UI 포장) | 네이티브 Kotlin |
|---|---|---|
| 인증서 지문 고정 | WebView의 fetch로는 고정 불가 → 통신 전부를 네이티브 플러그인으로 다시 짜야 함. 웹/네이티브 경로가 섞여 **우회 경로가 생길 위험** | OkHttp `CertificatePinner` 등 표준 방식 하나. 리뷰가 쉽다 |
| Keystore 토큰 | 플러그인 필요 | 표준 API(EncryptedSharedPreferences/Keystore) 직접 |
| WorkManager 15분 조회 + 로컬 알림 | 백그라운드 작업은 웹 코드가 돌지 않아 **결국 Kotlin으로 별도 작성** | 표준 |
| QR 스캔 | 플러그인 | CameraX + ML Kit 등 표준 |
| 디자인 재사용 | 데스크톱 React 컴포넌트 일부 재사용 가능. 단 데스크톱 화면은 PC 폭 기준이라 모바일용으로 어차피 새로 배치 | 컬러 토큰·간격·타이포를 Compose 테마로 옮김. 화면 수가 적어(6종 + 상태 6종) 부담 작음 |
| 화면 범위 | 1.0.0 화면은 연결·상태·결정·지시뿐 → 재사용 이점이 작음 | — |
| 유지보수 | 웹 + 플러그인 + 네이티브 3층 | 1층 |
| 이 PC 준비물 | Android SDK 필요(동일) + 웹 빌드 | Android SDK·에뮬레이터 필요 |

- 결론: 1.0.0의 핵심 요구(지문 고정·Keystore·WorkManager·QR)가 **전부 네이티브 기능**이라, Capacitor로 해도 중요한 부분은 Kotlin으로 짜게 된다. 재사용 이점은 작고 보안 리뷰 부담은 커진다. **네이티브 Kotlin(Compose)** 권고.
- "데스크톱 디자인을 그대로 옮겨 쓰기"는 **컬러 토큰·컴포넌트 모양(카드·뱃지·버튼·상태 점)·문구**를 옮기는 것으로 정의한다. 이디자가 데스크톱 토큰(`index.css` shadcn 토큰)을 모바일 토큰표로 만들고, 임안드가 Compose 테마로 구현한다.
- 이전 결정(Capacitor)을 뒤집는 것이므로 **대표 확인 필요(D1)**.

## 5. PC 원격 API (프로토콜 v1)
> 상세 규격(필드 타입·오류 코드 전체)은 2단계 "프로토콜 v1 규격(김버전)"에서 확정한다. 아래는 기획 기준.

### 5-1. 서버 동작 (정리드 구현, 별도 diff ① ②)
- **diff ① 원격 API 서버** (메인 프로세스 새 모듈, 예: `main/remote.ts`)
  - 기본 꺼짐. 설정 "휴대폰 연결"을 켜면 HTTPS 서버를 띄우고 UPnP 포트 매핑을 시도. 결과(성공·실패·외부 주소)를 설정 화면에 표시. 실패 시 수동 포트포워딩 안내.
  - 끄면 서버를 닫고 UPnP 매핑을 해제.
  - 키쌍: 처음 켤 때 생성해 `userData`에 저장(소유자만 읽기). 자체 서명 인증서, 갱신은 같은 키로.
  - **REST 4종만 제공.** 나머지 경로는 404. 기존 `Office` 메서드를 호출해 PC 화면과 같은 동작을 공유.
  - 원격에서 온 지시·결정 응답은 기록에 "휴대폰에서"로 표시.
  - 모든 응답에 `protocolVersion`.
- **diff ② 인증·시도 횟수 제한**
  - 헤더 `Authorization: Bearer <token>`. 토큰은 URL·로그에 넣지 않는다. 상수 시간 비교.
  - IP별 실패 5회/10분 → 15분 잠금. 전체 합산 20회/10분 → 전체 15분 잠금. 수치는 상수 한 곳.
  - QR 재생성 = 새 토큰 발급 + 기존 토큰 즉시 폐기(폐기 목록에 해시 보관해 `token_revoked`로 응답).
  - 잠김이 생기면 PC 알림.

### 5-2. API 4종
| # | 메서드·경로 | 기능 | 연결 IPC | 응답 요지 |
|---|---|---|---|---|
| 1 | `GET /v1/status` | 상태 조회 | `snapshot` 일부 | 고용 직원(id·이름·직무·상태·활동·결재 대기 수)·서버 버전·`protocolVersion`. 장비·지침·폴더 경로·비용은 **보내지 않음** |
| 2 | `GET /v1/decisions` | 대기 결정 목록 | 결재·질문·기획 확인 대기 | id·종류(approval/question/plan)·직원·요약·선택지·생성 시각 |
| 3 | `POST /v1/decisions/{id}` | 결정 응답 | `decide`, `answerQuestion`, `reviewPlan` | 이미 처리됐으면 `409 already_decided` |
| 4 | `POST /v1/instructions` | 지시 전송 | `instruct` (판단 2 대안 채택 시 `sendChat`) | 접수 여부. 첨부 없음 |

- 결정 응답 시 결재 요약은 명령·파일 경로가 포함될 수 있다. 화면에는 보여 주되 **로그·알림 본문에는 넣지 않는다**(알림은 "결재 1건 대기"처럼 요약만).

### 5-3. 오류 응답
| 상태 | `error` | 앱 동작 |
|---|---|---|
| 401 | `token_revoked` | "PC에서 QR을 다시 만들었어요. 새 QR로 다시 연결하세요". 저장 토큰 삭제, 재시도 안 함 |
| 401 | `auth_locked` + `retryAt` | 잠김 카운트다운 화면, `retryAt`까지 요청 안 함 |
| 404 | `not_found` | 정의 외 경로 |
| 409 | `already_decided` | "이미 처리됐어요" 후 목록 새로고침 |
| 426 | `protocol_unsupported` | 앱 업데이트 안내 |
| 연결 불가 | — | 원격 꺼짐/PC 절전/네트워크 끊김 화면(구분 가능한 범위에서) |
| TLS 지문 불일치 | — | 인증서 불일치 화면, 연결 안 함, 무시 버튼 없음 |

### 5-4. QR 내용 (v1)
```json
{
  "v": 1,
  "host": "203.0.113.10 또는 DDNS 이름",
  "port": 47900,
  "token": "…",
  "spki": "sha256/base64…",
  "firebase": { "projectId": "…", "appId": "…", "senderId": "…" }
}
```
- `firebase`는 **선택·예약** 필드. 1.0.0 앱은 읽기만 하고 쓰지 않는다(없어도 됨).
- 앱은 **모르는 필드를 무시**한다(앞으로 필드가 늘어도 1.0.0이 깨지지 않게).
- `v`가 앱이 모르는 큰 값이면 "앱 업데이트 필요" 안내.
- 포트 기본값은 확인 필요(D4). QR은 화면에만 표시하고 파일로 저장하지 않는다.

## 6. 안드로이드 앱 구조 (임안드 구현, 판단 3 확정 전제)
- 연결 계층은 화면과 분리: `connect(qr)`·`request(api)`·`disconnect(forget)`·상태 흐름(Flow) 하나로 화면에 노출.
- 토큰은 Keystore에만. 로그·크래시 리포트에 토큰·지문·결재 요약 금지.
- 평문 HTTP 금지(네트워크 보안 설정), 사용자 설치 CA 불신, 릴리스 `debuggable=false`. 지문 검증 끄는 개발 스위치를 릴리스에 두지 않음.
- WorkManager 주기 작업(15분, 네트워크 연결 조건). 새 결정이 있으면 로컬 알림 채널 "결정 대기".
- FCM은 2단계: 1.0.0에는 FCM 라이브러리를 넣지 않는다. QR `firebase` 필드는 파싱만 해 둔다.
- 배터리 최적화 예외: 첫 연결 가이드 마지막 단계와 설정에서 안내(강제 요청하지 않음).

## 7. FCM 2단계 준비 (박패턴 설계, 1.0.0에는 인터페이스만)
- PC 쪽 `PushSender` 인터페이스(예: `send(deviceId, kind, summary)`)와 "아무것도 안 함" 구현만 둔다.
- 서비스 계정 키는 **앱에 넣지 않고** PC에만 둔다. 보관 위치·권한은 박패턴 설계에서 정한다.
- QR `firebase` 필드가 채워지면 2단계 앱이 등록 토큰을 PC에 보내는 흐름을 추가한다.

## 8. 버전 정책
| 대상 | 규칙 |
|---|---|
| 데스크톱 | 이번 원격 API 추가로 **마이너** 올림(예: 0.7.x → 0.8.0). 맥·윈도우 **같은 버전**으로 함께 빌드 |

## 9. 디자인 (이디자)
- 데스크톱 컬러 토큰·상태색(working/waiting/error)·카드·뱃지·버튼 모양을 모바일 토큰표로 옮긴다.

## 11. 완료 기준
1. PC: `typecheck`·`test` 통과, 기존 기능 회귀 없음.
2. 원격 API 테스트: 기본 꺼짐 / 4종 외 경로 거절 / 401 두 종류 구분 / 실패 제한(IP·전체) / QR 재생성 시 기존 토큰 폐기 / 끄면 포트·UPnP 매핑 닫힘 / `409 already_decided`.
3. 한리뷰 보안 리뷰 지적 사항 전부 반영.
4. 앱: 에뮬레이터에서 로컬 PC 서버에 QR로 연결, 상태 조회·결정 응답(결재·질문·기획)·지시, 오류 상태 6종 확인. 백그라운드 조회 알림이 중복 없이 1회 뜸.
5. 대표 실기기 체크리스트(12절) 준비.
6. 문서: README(설치·포트 개방 주의·호환 표), SPEC, CHANGELOG(쉬운 말), `docs/changelog-dev.md`, 릴리스 노트. 릴리스 노트에 **원격 기본 꺼짐, 포트 개방 보안 주의, 인증서 고정, 알림 수십 분 지연 가능**을 반드시 적는다.

## 12. `blocked(수동 QA)` 대표 실기기 체크리스트
- [ ] **LTE 외부망:** 와이파이 끄고 QR의 외부 주소로 연결·결정 응답·지시
- [ ] **공인 IP 변경:** 공유기 재시작 등으로 IP가 바뀐 뒤 앱 동작(DDNS 미사용 시 QR 재생성 필요 여부)
- [ ] **인증 실패 잠김:** 잘못된 토큰 반복 → 카운트다운 표시, 시간 지나면 복구, PC 알림. 공유기 뒤에서 IP별 구분이 실제로 되는지
- [ ] **토큰 폐기:** PC에서 QR 재생성 → 앱이 `token_revoked` 안내, 새 QR로 재연결
- [ ] **인증서 불일치:** PC 키 교체 후 접속 거부, 무시 버튼 없음
- [ ] **HTTP 평문 차단**
- [ ] **Doze 지연:** 화면 끄고 방치 후 새 결재 발생 → 알림까지 걸린 시간 기록
- [ ] **배터리 최적화 예외** 안내 버튼이 설정 화면으로 이동
- [ ] **회전·키보드:** 폰 세로/가로, 태블릿 2패널, 지시 입력창이 키보드에 안 가림
- [ ] **원격 끄기:** PC에서 끄면 앱이 "원격 꺼짐" 화면
