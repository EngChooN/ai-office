## 1. 배경 — 지금 직원이 어떻게 돌아가나 (코드에서 확인)

- 직원 1명 = `@anthropic-ai/claude-agent-sdk` `query()` 1개 (`app/src/main/hired.ts` `start()`). 스트리밍 입력, `resume: s.sessionId`로 세션 이어가기, `canUseTool`로 결재함 연동.
- 모델 선택은 `Staff.model`(별칭 → `MODEL_ID` 표) 한 열. 공급자 개념 없음 (`db.ts` staff 테이블의 `model TEXT`).
- `office` MCP 도구(팀 조회·위임·캡처 등)는 `this.hooks.officeTools(s.id)`로 **SDK 안에서 만든 in-process MCP 서버**를 `mcpServers`에 넘긴다.
- 장비(MCP·스킬)는 `strictMcpConfig`로 장비 탭에서 켠 것만 `mcpServers`로 넘긴다. 설정 원천은 `~/.claude/...`.
- 토큰·비용: 결과 메시지의 `total_cost_usd`·`modelUsage`를 query 누적값에서 차분해 `hooks.usage`로 저장(`hired.ts` 약 457~488줄).
- 로그인: 번들된 `claude` 실행 파일의 `auth status` / `auth login`(`setup.ts`).
- 세션 기록: `~/.claude/projects/*.jsonl`을 `transcript.ts`·`sessionRotate.ts`가 직접 읽는다 (대화 이어보기·요약·교체).
- 그 밖에 Claude 전용 의존: 시스템 프롬프트 preset(`claude_code`), 슬래시 명령 목록(`supportedCommands`), 스킬(매뉴얼), 훅(`~/.claude/settings.json`에 넣는 외부 직원 hooks), 플랜 사용률(Claude 플랜).

## 2. ① Codex 연결 — 조사 결과

### 2-1. 접근 방법 3가지

| 방법 | 설명 | 장점 | 단점 |
|---|---|---|---|
| **A. `codex app-server` (JSON-RPC, stdio)** | Codex 앱·IDE 확장이 쓰는 공식 서버. 앱이 자식 프로세스로 띄우고 JSON-RPC로 대화 | 스레드 시작/재개/중단, 서버→클라이언트 **승인 요청**, 알림 스트림, 로그인, MCP 상태·재로드 **[확인: README에 thread/start·resume·read·list, turn/start·completed, account/login/*, mcpServer/*, config/mcpServer/reload 존재]** | 프로토콜이 빠르게 바뀜(실험 필드 다수). 승인·토큰 알림 정확한 이름은 스파이크에서 **스키마를 생성해 고정**해야 함 |
| **B. `@openai/codex-sdk` (TypeScript)** | `new Codex()` → `startThread()` / `resumeThread(id)` / `thread.run()`. 내부적으로 `codex` CLI를 띄움 | 코드 가장 적음 | **[확인]** 공식 문서에 이벤트 종류·토큰 usage·승인 콜백이 없음. 승인은 App Server 쪽 역할이라고 안내됨 → **결재함 연동 불가** |
| **C. `codex exec --json`** | 턴마다 CLI 실행, JSONL 이벤트 | 가장 단순 | 상시 세션·결재 대기 불가(비대화형은 승인 요청 시 실패하거나 정책으로 우회) |

**→ 추천: A(app-server).** SDK(B)는 단발 작업(비서의 `askOnce` 같은 용도)에만 후보.

참고: SDK 문서는 기존 `codex mcp-server` 방식이 제거됐고 App Server를 쓰라고 안내한다 **[확인]**.

### 2-2. 기능별 대응표 (Claude Agent SDK ↔ Codex app-server)

| 기능 | Claude (지금) | Codex | 판정 |
|---|---|---|---|
| 대화(스트리밍 입력·출력) | `query()` 스트림 | `thread/start` → `turn/start`, 응답은 아이템 알림 스트림 | 가능 |
| 끼어들기·중단 | `interrupt`/`stopping` | `turn/interrupt` (README는 "Interrupt는 항상 가능"만 표기) | 가능 **[확인 필요: 메서드명]** |
| 도구 사용 | 내장 도구(Read·Edit·Bash…) | Codex 내장 도구(셸·파일 변경 `apply_patch`·웹 검색) | 가능, **도구 이름·종류가 달라** 결재 카드 문구 변환 필요 |
| 결재(승인) | `canUseTool` 콜백 → 결재함 | 서버→클라이언트 승인 요청(명령 실행·파일 변경) 에 응답 | 가능 **[추정: 요청 이름은 `item/commandExecution/requestApproval` 계열, 스키마로 확정 필요]** |
| 자동결재/모두결재/편집만 | `permissionMode` + 앱 규칙 | 승인 정책(`approval_policy`: untrusted/on-request/never) + 샌드박스(read-only/workspace-write/full-access) | 가능. 앱 쪽 판정(`isAllowed` 등)은 승인 요청이 올 때 앱이 재사용. **샌드박스 경계는 Claude와 다른 모델**이라 UX 설명 필요 |
| 세션 이어가기 | `resume: sessionId` | `thread/resume`(threadId), 기록은 `~/.codex/sessions` | 가능. `sessionId` 열을 공급자 중립 `threadId`로 |
| MCP `office` 도구 | in-process SDK MCP | **프로세스 밖 MCP만** 가능(stdio 또는 HTTP) | **가능하나 작업 필요**: 앱이 `127.0.0.1` 임시 HTTP MCP 서버를 열고 직원별 토큰으로 `staffId`를 식별 → Codex에 `mcp_servers.office`로 주입 (`-c` 오버라이드 또는 SDK `config`) |
| 장비 MCP(외부 서버) | `mcpServers` 객체 | `config.toml`의 `mcp_servers.*` 또는 실행 시 오버라이드 | 가능. 같은 장비 정의를 TOML 오버라이드로 변환. claude.ai 커넥터는 원래도 불가 |
| 토큰 집계 | 결과의 `total_cost_usd`, `modelUsage` | 토큰 사용 알림(입력·출력·캐시 토큰) **[확인 필요: 알림명]**. **금액은 주지 않으므로** 앱이 모델별 단가표로 계산 | 가능, **단가표 신설** |
| 시스템 프롬프트·직원 정체성 | preset `claude_code` + append | `developer_instructions` / `AGENTS.md` / `thread/start`의 지침 필드 | 가능 **[확인 필요: 필드]**. 구현 시 `AGENTS.md`를 건드리지 않도록 오버라이드 방식 우선 |
| 스킬(업무 매뉴얼) | `skills` 옵션, `~/.claude/skills` | Codex도 `~/.codex/skills` 존재(이 PC에서 확인) — 형식 호환 **[확인 필요]** | 앱이 매뉴얼 내용을 지침에 주입해 대체(2-7) |
| 슬래시 명령 목록 | `supportedCommands` | 없음/다름 | 미지원(자동완성 숨김) |
| 이미지 첨부 | 첨부 → 메시지 | 입력 아이템에 이미지 지원 **[추정]** | 2차 |
| 세션 기록 보기·요약·교체 | `.claude/projects/*.jsonl` 파싱 | `~/.codex/sessions` 롤아웃 형식, 또는 `thread/read` | 가능, **파서 별도 구현**(app-server의 `thread/read`가 더 안정적) |
| 플랜 사용률 | Claude 플랜 | ChatGPT 플랜 사용량 **[확인 필요]** | 대체: 조회 가능하면 사용량 카드, 아니면 앱 집계(2-7·2-9-⑤) |

### 2-3. 로그인 방식 제안

이 PC의 `~/.codex/auth.json`은 `auth_mode: chatgpt`이고 토큰을 담고 있다 **[확인]**. 즉 Codex CLI는 (a) ChatGPT 계정 로그인 (b) API 키 두 방식을 쓴다.

| 안 | 설명 | 장단점 |
|---|---|---|
| **A. 앱이 Codex 자체 로그인에 위임 (추천)** | 설정 → "GPT(Codex) 로그인" 버튼 → app-server `account/login/*`(브라우저 OAuth) 또는 `codex login` 실행. 앱은 **토큰을 저장·열람하지 않고** `account/read`로 로그인 여부·이메일만 표시 | 비밀을 앱이 들지 않아 안전. Claude 로그인과 대칭(`setup.ts`와 같은 UX) |
| B. API 키 입력 | 설정에 키 입력 → 앱 보안 저장소 → 환경변수로 주입 | 단순하나 키 보관 책임이 앱에 생김, 종량 과금 |
| C. A+B 병행 | 기본 A, 고급에서 B | 구현·문서 증가 |

주의: 앱 번들에 Codex 바이너리를 **같이 넣을지**(Claude처럼 `asar.unpack`, 플랫폼별 패키지) vs **사용자가 설치한 `codex`를 찾아 쓸지** 결정 필요(11-③). 앱이 사용자의 `~/.codex/auth.json`을 직접 읽거나 복사하지 않는다(민감 정보 — 이 PC의 `config.toml`에도 평문 토큰이 있었다. 앱은 Codex 설정 파일을 읽어 장비로 가져오지 않는다).

### 2-4. 직원별 모델 공급자 선택 구조

```
Staff.provider: 'claude' | 'codex'     // 새 열, 기본 'claude'
Staff.model:    공급자별 모델 id        // 기존 별칭 + 'gpt-5…' 등 (목록은 앱이 account/model 조회로 갱신, 실패 시 내장 목록)
Staff.sessionId → Staff.threadId(이름만 중립화, 기존 값 유지)
```

- **DB:** `staff`에 `provider TEXT NOT NULL DEFAULT 'claude'` 추가(기존 행은 자동 'claude'). 마이그레이션 1줄.
- **공급자 어댑터 인터페이스** (hired.ts를 나누는 핵심):
  ```ts
  interface AgentRuntime {
    start(opts): void
    send(text, attachments): void
    interrupt(kind: 'stop'|'resume'): Promise<void>
    setModel(id): void
    close(): void
    // 이벤트(공급자 중립): message / toolRequest(결재) / usage / sessionId / error / commands
  }
  ```
  `ClaudeRuntime`(지금 `hired.ts`를 그대로 옮김)와 `CodexRuntime`(신규). 결재·급여·보고는 중립 이벤트만 본다. **Claude 쪽 동작이 바뀌면 안 되므로 1단계는 "행동 변화 없는 이동 리팩터링 + 기존 테스트 598개 유지"**.
- **UI:** 고용 창에 "AI" 선택(Claude / GPT) → 모델 선택이 해당 공급자 목록으로 바뀜. Codex 직원에는 명패에 작은 표시. Claude 전용 기능은 사용자 유형·직원 공급자에 따라 숨기거나 대체한다(2-7). 고용 창의 모델 버튼은 쓸 수 있는 모델만 보이고 추천이 붙는다(2-9).
- **공급자 변경:** 직원의 공급자는 **고용 후 변경 불가**(세션 기록 형식이 달라 이어붙일 수 없음). 바꾸려면 새로 고용 — 분신 만들기를 재사용 가능.
- **팀·랩·업무 보드·회의:** 공급자 무관하게 동작해야 한다. 회의·위임은 `AgentRuntime` 중립 메시지만 쓰므로 변경 거의 없음. `office` 도구 설명은 공급자 무관이라 그대로.
- **비서(secretary)·`askOnce`·요약:** 공급자 고정이 아니라 `AiBackend`로 쓸 수 있는 쪽 모델로 동작한다(2-8).

### 2-5. 위험·미확인

1. **승인·토큰 알림 정확한 이름·필드**: 이 PC의 Codex 앱 바이너리는 `--version` 실행이 출력 없이 끝나 스키마를 생성하지 못했다. **스파이크 1일차에 `codex app-server generate-ts`(또는 json-schema)로 스키마를 뽑아 확정** — 이 단계 전까지 위 표의 [추정] 항목은 가정.
2. **프로토콜 안정성**: 실험(experimental) 표기 필드가 많다. Codex 버전을 앱이 **고정 번들**(권장)하지 않으면 사용자의 Codex가 업데이트될 때 깨질 수 있다.
3. **샌드박스 모델 차이**: Codex는 OS 샌드박스(read-only/workspace-write)가 기본 방어선. Claude의 "결재함 중심" 흐름과 조합 시 "승인 없이 막힘"이 생길 수 있다 → `approval_policy: on-request` + `workspace-write` 기본, "모두 결재"는 `untrusted`로 매핑 **[확인 필요]**.
4. **비용 표시**: 구독(ChatGPT 플랜) 로그인은 토큰당 금액이 없다. 급여 명세서는 "추정 비용(API 단가 환산)"으로 표시하고 한도 알림은 토큰 기준으로.
5. **라이선스·약관**: Codex CLI는 Apache-2.0 **[추정]**. 앱에 번들해 배포할 때 NOTICE·약관(ChatGPT 계정을 제3 앱에서 쓰는 조건)을 **대표/법무 확인 필요**.
6. **개인정보**: 외부 직원(hooks) 연동은 `~/.claude/settings.json` 전용이라 Codex 외부 세션은 감시 범위 밖(보기 전용 외부 직원은 1차 제외).

### 2-6. 공급자 감지와 온보딩 (사용자 3유형: Claude만 / Codex만 / 둘 다)

**원칙:** 앱은 "준비된 공급자 집합"(`ready ⊆ {claude, codex}`)만 본다. 하나만 준비돼 있어도 모든 화면이 막히지 않아야 한다. 지금 온보딩은 Claude 로그인을 통과 조건으로 삼는데(`setup.ts`), 이를 "**하나라도 준비되면 통과**"로 바꾼다.

| 공급자 | 설치 감지 | 로그인 감지 | 비고 |
|---|---|---|---|
| Claude | 앱에 번들된 `claude` 실행 파일(`claudeBinaryPath()`)이 있으면 설치됨. 터미널용 `claude`가 따로 있는지(`hasTerminalClaude`)는 지금처럼 참고 정보 | `claude auth status` JSON의 `loggedIn`·`email`·`authMethod` (지금 코드 그대로) | 새 작업 거의 없음 |
| Codex | ① 번들 실행 파일(11-③ 결정 시) ② 없으면 `PATH`의 `codex`, `/Applications/Codex.app/Contents/Resources/codex` 등 알려진 위치 순서로 탐색. 실행해 `--version`이 정상 종료하면 설치됨 | `codex app-server`를 잠깐 띄워 `account/read`(로그인 여부·이메일·플랜) 조회 **[확인: README에 `account/read` 존재]**. 대안 `codex login status` **[확인 필요]** | `~/.codex/auth.json`은 **열지 않는다**(토큰 파일). 존재 여부로 추측하지도 않고 반드시 Codex에게 묻는다 |

- **상태값(공급자별):** `missing`(설치 안 됨) / `loggedOut`(설치됨, 로그인 안 됨) / `ready` / `broken`(실행 실패·버전 불일치). 화면 문구는 이 4가지만 쓴다.
- **조회 시점:** 앱 시작 직후(백그라운드), 설정 화면 열 때, 창 포커스 복귀 시(30분 경과 시), 로그인 흐름 종료 시, 설정의 [다시 확인]. 결과는 메모리 캐시 + `office.db` 설정 1행(마지막 확인 시각·상태·이메일). 조회는 5초 타임아웃, 실패는 `broken`이 아니라 "확인 못 함"으로 두고 이전 값을 유지한다(오프라인에서 직원이 갑자기 잠기지 않게).
- **직원 실행 중 만료:** 실행 중 인증 오류가 오면 그 공급자 상태를 `loggedOut`으로 내리고, 해당 공급자 직원 카드에 "로그인이 필요해요" 배너. 다른 공급자 직원은 영향 없음.

**온보딩 흐름**
1. 첫 실행 → 두 공급자 상태를 동시에 조회(스피너 최대 5초).
2. **둘 다 `ready`** → 바로 통과. 기본 설정 한 줄 안내("Claude와 GPT 직원을 모두 고용할 수 있어요").
3. **하나만 `ready`** → 바로 통과. 다른 쪽은 설정에 "GPT(Codex) 연결하기" / "Claude 연결하기" 카드로만 둔다(경고가 아니라 선택 사항).
4. **둘 다 `loggedOut`/`missing`** → 막히는 유일한 경우. 두 개의 카드를 나란히 보여 주고 **하나만 연결하면** 넘어간다. 각 카드에 [로그인] 버튼(`missing`이면 설치 안내 또는 앱 내 설치), 필요 시 "나중에 하기"는 두지 않는다(직원을 만들 수 없으므로).
5. **기존 사용자(0.13.x → 업그레이드)** → Claude `ready`면 아무것도 묻지 않는다. 직원은 `provider='claude'`로 이어진다. 설정에 Codex 카드가 새로 보이고, 첫 실행 때 배너 한 번("GPT 직원도 고용할 수 있어요").
6. 이후 어느 쪽이든 나중에 연결·해제 가능. 해제 시 그 공급자 직원은 삭제되지 않고 "로그인 필요" 상태로 남는다.

### 2-7. Claude 전용 기능 처리 — 원칙: Codex에도 있으면 숨기지 않고 연결한다

원칙(대표 지적): **Codex에도 같은 기능이 있으면 숨기지 않고 Codex 쪽 기능으로 연결한다.** 연결할 수 없을 때만 **대체**(앱이 같은 효과를 내는 다른 방법), 그것도 안 되면 **숨김**(회색으로 두지 않음)이다. 둘 다 쓰는 사용자에게는 직원별로 그 직원의 공급자 기능이 보인다. 안내 문구는 사용자가 찾을 만한 곳에만 한 줄 둔다.

### 2-8. 앱 내부 AI(비서·요약·askOnce)의 공급자화

**대표 결정: 앱 내부 AI도 쓸 수 있는 쪽 모델로 돈다.** 지금 `askOnce`는 `office.ts`에서 8곳 이상(요약·회의 정리·계획·검토 등), 비서(`secretary.ts`)는 별도 세션으로 `claude` 모델(`haiku` 등)을 직접 부른다. 이를 `AiBackend`로 감싼다.

```ts
interface AiBackend {
  ask(opts: { prompt; system; tier: 'light' | 'standard'; cwd; abort }): Promise<{ text; usage }>   // askOnce 대체 (단발)
  session(opts): SecretarySession                                                                    // 비서(상시 대화)
}
```
- **tier**로 요청한다: 코드가 `'haiku'`를 박지 않고 `light`(요약·분류)/`standard`(계획·비서) 중 하나를 말하면, 공급자별로 모델 표(2-9)의 `lightFor`·`standardFor`가 실제 모델을 정한다.
- **공급자 고르기:** 설정 `internalAi: 'auto' | 'claude' | 'codex'`(기본 `auto`).
  - `ready`가 한 개 → 그 공급자.
  - 둘 다 `ready` + `auto` → 기본 **Claude**(기존 사용자 동작 유지, 11-⑦에서 대표 확인). 사용량 분산(2-9-⑤)이 들어오면 한도에 덜 가까운 쪽.
  - 선택한 공급자가 실행 중 실패(로그인 만료·한도 초과)하면 **다른 `ready` 공급자로 한 번 재시도**, 그래도 실패하면 지금처럼 사용자에게 오류.
- **단발(askOnce):** 상태가 없으므로 바로 전환 가능. Codex는 `thread/start`(임시·기록 안 남김 **[확인 필요: 임시 스레드 옵션]**) → `turn/start` → 완료 대기 → 스레드 종료. 도구를 쓰지 않는 읽기 전용(Claude의 `dontAsk`에 해당: `approval_policy=never` + `read-only` 샌드박스) **[확인 필요]**.
- **비서:** 대화 맥락이 `userData/secretary` 세션과 `secretaryCompact`(요약)에 있다. 공급자가 바뀌면 **세션 id는 이어 쓸 수 없으므로**, 비서의 압축 요약(앱 쪽 텍스트)을 새 공급자 세션의 첫 지침으로 넘기고 새로 시작한다(사용자에게는 "비서가 다른 모델로 바뀌었어요" 한 줄). 비서가 쓰는 앱 도구(`secretary` 도구 세트)는 `office` MCP와 같은 로컬 MCP 서버로 노출 **[확인 필요: 현재 in-process 도구의 수·크기]**.
- **토큰·비용:** 내부 AI 사용량도 공급자별 단가로 급여 명세서의 "앱 내부(비서·요약)" 항목에 합산.
- **플랜 사용률 콜백**(`onRateLimit`)은 Claude 전용 입력이므로 `AiBackend` 이벤트로 일반화(`rateLimit` 이벤트: 공급자·사용 비율·초기화 시각).

### 2-9. 새 기능: 모델 추천 (고용 창)

**한 줄:** 업무 템플릿을 고르거나 업무를 직접 입력하면, 쓸 수 있는 모델 중 가장 맞는 것의 버튼에 **빛(글로우)**이 나고 **"추천" 배지 + 이유 한 줄**이 붙는다. 사용자는 다른 모델을 고를 수 있다.

**① 화면 동작**
- 고용 창의 모델 선택 줄(모델 버튼들) 위 또는 아래에 모델 버튼이 있다. 추천 모델 버튼: 은은한 글로우(`prefers-reduced-motion`이면 정지) + "추천" 배지. 색에만 의존하지 않고 배지로도 구분(접근성).
- 버튼 아래에 이유 한 줄. 예: "코드 수정이 많은 업무라 GPT 코덱스 모델이 잘 맞아요", "여러 문서를 읽고 정리하는 업무라 Claude Opus가 잘 맞아요".
- **사용자가 직접 모델을 고르면** 그 선택이 우선하며 추천은 배지만 그 버튼에 남고 자동으로 되돌리지 않는다. 템플릿·업무를 바꿔 추천이 달라지면 글로우만 이동(선택은 사용자가 누르기 전에 바꾸지 않는다).
- **추천 없음 처리:** 일치하는 업무 유형이 없으면 "범용" 추천(균형 모델). 쓸 수 있는 모델이 하나뿐이면 추천 배지를 숨기고 이유 줄만("연결된 모델이 하나라 이걸로 일해요" 또는 생략).
- 입력은 300ms 디바운스, 토큰 0(아래 ③).

**② 후보 모델 = 쓸 수 있는 모델만**
- 후보 = (`ready` 공급자의 모델 목록) ∩ (모델 표에 있는 모델). Claude만이면 Claude 모델, Codex만이면 GPT 모델, 둘 다면 전체.
- 모델 목록은 공급자가 알려 주는 것을 우선(Codex app-server의 모델 조회 **[확인 필요]**, Claude는 앱 내장 별칭). **표에 없는 새 모델**은 "범용·중간" 기본 점수로 후보에 넣고 추천 점수는 낮게 둔다(새 모델이 나와도 앱이 깨지지 않게).

**③ 어떻게 고르나 (토큰 0)**
1. 입력: 템플릿 ID, 또는 사용자가 쓴 업무 텍스트.
2. **업무 유형 판정:** 템플릿이면 템플릿이 가진 `taskType`을 그대로. 직접 입력이면 **키워드 사전 매칭**: 텍스트를 소문자화하고(CJK는 형태소 없이) 사전의 키워드가 **부분 문자열로 포함**되는지 센다. 유형별 일치 수 합 → 상위 1~2개 유형을 가중치(예: 1위 0.7, 2위 0.3)로 사용. 일치 0개 → `general`.
3. **점수:** `score(model) = Σ_type weight(type) × affinity[model][type] + tierBonus`, 같은 점수는 (a) 가벼운 쪽(비용), (b) 이미 이 사용자가 쓰는 공급자 순으로.
4. 결과: 1위가 "추천", 이유 키는 `reasonKey = <taskType>` (1위 유형)로 4개 언어 사전에서 문장을 찾고 `{모델}`을 채운다.
- AI 호출 없이 항상 즉시 결과가 나온다(오프라인·Codex 한도 걱정 없음). 정확도 한계는 안내하지 않고, 이유 문구가 근거를 말해 사용자가 판단하게 한다.

**④ 데이터 표 (코드에 박지 않는다)**
- 파일: `app/src/shared/modelCatalog.json`(앱 내장). **고치는 방법:** 문서 한 파일만 수정(코드 변경 없음). 선택: 사용자 데이터 폴더의 같은 이름 파일이 있으면 덮어씀(고급·테스트용), 향후 원격 갱신(11-⑧).
- 로더는 스키마 검사(누락·범위 밖 값은 무시하고 내장 기본으로 폴백) + 단위 테스트(모든 모델·유형에 값이 있고 1~5 범위).

**⑤ 선택 항목: 사용량 분산(둘 다 있을 때)**
- 아이디어: 한 공급자 사용량이 한도에 가까우면(예: 80%+) 그 쪽 모델 점수를 깎고 이유 줄에 "Claude 사용량이 많아 GPT를 먼저 추천해요". 점수식에 `loadPenalty(provider)`(70%까지 0, 100%에서 −1.5 선형) 하나만 추가하면 되므로 구조상 부담이 작다.
- **가능성 / 데이터 출처:**
  | 공급자 | 데이터 출처 | 판정 |
  |---|---|---|
  | Claude | 지금 앱이 쓰는 SDK의 `onRateLimit`(사용 비율·초기화 시각), 앱 DB의 플랜 사용률 | **가능**(이미 있음) |
  | Codex | (a) app-server의 계정 사용량·rate limit 조회·알림 **[추정: 있는 것으로 알려졌으나 이번에 확인하지 못함]**, (b) 없으면 앱이 직접 집계한 Codex 직원·내부 AI 토큰을 **사용자가 정한 한도**(급여 명세서의 일·주·월 토큰 한도)와 비교 | (a)면 **가능**, (b)는 **근사치**(구독 한도와 무관) |

- **추천:** 첫 공개에는 **넣지 않고(구조만 준비)**, P0 스파이크에서 Codex 사용량 조회 가능 여부를 확인한 뒤 후속(M4)으로 한다. 사용량이 불명이면 페널티 0으로 안전하게 동작하게 한다.

## 4. 영역별 영향

### 4-1. 데이터 폴더·마이그레이션
- 새 이름 앱이 첫 실행 시 **옛 폴더가 있고 새 폴더가 없으면 옛 폴더를 통째로 새 폴더로 복사**(이동 아님, 옛 것은 보존 — 되돌릴 수 있게). 대상: `office.db`(+`-wal`/`-shm`는 **앱이 꺼진 상태에서 한 번에**), `remote/`, `browser/`, `attachments/`, `secretary/` 등 전체.
- 이중 안전장치: 복사 전 옛 DB 무결성 확인(`PRAGMA integrity_check`), 복사 후 새 DB 열기 성공 확인, 실패하면 **옛 폴더를 그대로 계속 사용**(`setPath` 폴백).
- 두 이름 앱이 동시에 켜지면 안 된다 → 기존 `dataLock.ts`가 같은 폴더를 보는 경우만 막으므로, **옛 앱 실행 여부를 별도로 감지**(옛 폴더 잠금 파일 확인)하고 "옛 Claude Office를 끄고 다시 열어 주세요" 안내.
- 윈도우도 같은 로직(`%APPDATA%`). 키체인·자격증명 저장 사용 여부는 **[확인 필요]**(`EnableCookieEncryption` 퓨즈 → 쿠키는 앱 식별자에 묶일 수 있음).

### 4-2. 번들 ID와 자동 업데이트 연속성
이 앱의 자동 업데이트는 Squirrel 등이 아니라 **직접 만든 방식**(GitHub Release의 dmg/zip을 내려받아 `.app`·폴더를 교체, `appInstall.ts`)이다. 그래서 번들 ID가 바뀌어도 "업데이트" 자체는 가능하다. 문제는 아래:
- 이미 설치된 옛 앱(0.13.x)은 **옛 URL·옛 파일명 규칙**(`Claude-Office-mac-arm64.dmg`)으로 최신 릴리즈를 찾는다. → 새 릴리즈에도 **옛 이름의 에셋을 같이 올려야** 옛 앱이 찾아서 설치한다. dmg 안의 `.app` 이름이 달라도 `appInstall`은 마운트 후 `.app`를 찾으므로 동작 **[확인: 96줄 `endsWith('.app')`]**, 그러나 **설치 위치를 옛 `.app` 경로로 덮어쓰는지** 새 경로(`/Applications/AI Office.app`)로 둘지 정해야 한다.
- 윈도우는 `claude-office.exe`를 이름으로 찾아 교체·재실행하므로(`appInstall.ts` 124·171줄) **실행 파일 이름을 바꾸면 옛 앱의 업데이트가 깨진다.** → 다리 릴리즈에서는 `executableName`을 유지하거나, 옛 앱이 이해하는 형식으로 에셋을 따로 제공.
- 번들 ID(`com.joonyoung.…`)가 바뀌면 맥에서 **다른 앱으로 인식**: 로그인 항목(자동 시작), 알림 권한, 화면 녹화·접근성 권한(화면 캡처 기능!), 방화벽 허용이 모두 초기화된다. 임시(ad-hoc) 서명이라 이미 권한이 서명 변경에 취약하지만, 번들 ID 변경은 확실히 초기화.
- **→ (참고, B안에서는 생략)** 다리 릴리즈(0.14.x): 이름·ID는 옛 것 그대로 두고 "새 이름으로 곧 바뀝니다" 안내 + (선택) 옛 앱이 새 이름 앱을 받도록 에셋 이중 제공. 그 다음 릴리즈에서 개명. 이렇게 하면 한 번에 깨질 위험을 나눈다.
- **용량(확정):** Codex 번들로 맥 기준 약 +260MB → dmg·zip이 약 2배. 내려받기·덮어쓰기 시간과 GitHub 에셋 용량(옛 이름 에셋 이중 업로드 시 4벌)이 늘므로 릴리즈 체크리스트에 용량·업로드 시간 확인을 넣는다. Codex 버전은 고정이며 앱 업데이트(`appInstall`)로만 함께 올라간다.
- 서명·공증: 지금은 ad-hoc. 개명은 서명 문제를 악화시키지 않지만, 정식 서명 인증서를 새 번들 ID로 만든다면 **이 시점이 도입 적기**(대표 결정 필요 아님, 참고).

### 4-3. GitHub 저장소·사이트
- 저장소 이름을 `claude-office → ai-office`로 바꾸면 GitHub이 **옛 URL을 새 URL로 리다이렉트**한다(웹·API 모두, 단 "옛 이름으로 새 저장소를 만들지 않는 한"). 즉 옛 앱·안드로이드 앱의 `repos/EngChooN/claude-office/releases/latest` 호출은 **계속 동작**한다 **[추정: API 리다이렉트는 301로 따라가야 함 → `fetch`는 기본으로 따라가지만 안드로이드 쪽 HTTP 클라이언트 설정 확인 필요]**. **옛 이름으로 새 저장소를 만들면 안 된다.**
- 소유자(`EngChooN`)를 조직으로 옮기는 안(예: flitto 조직)은 별개 결정 — 이전 시에도 리다이렉트는 유지되나 이중 변경은 피한다.
- 사이트(`site/`)는 정적 페이지: 이름·링크·다운로드 에셋 이름 일괄 변경. 도메인·호스팅이 별도라면 **[확인 필요]**(현재 `site/index.html`만 확인).
- `intro.html`·README 4개 언어·CHANGELOG는 이름 치환 + "예전 이름은 Claude Office" 한 줄 안내.

### 4-4. 모바일(안드로이드) 앱
- 표시 이름(strings.xml 4개)은 바꿔도 무해.
- **`applicationId`는 바꾸면 완전히 다른 앱**이 된다(업데이트로 이어지지 않고 옛 앱 삭제·재설치·재페어링). 지금은 사이드로드 배포(스토어 미확인 → **[확인 필요]**)라 영향이 작지만 사용자 부담이 크다. → **`applicationId`·패키지명은 유지 추천**(사용자에게 보이지 않음).
- 프로토콜의 호스트·서비스 식별(mDNS/QR 문자열)에 `claude-office` 문자열이 있는지 **[확인 필요]**(`remote-protocol` 문서·`remote/` 코드 grep 필요). 바꾸면 이전 버전끼리 호환이 깨지므로 프로토콜 식별자는 유지.
- 안드로이드 업데이트 확인 URL은 저장소 리다이렉트로 유지되지만, 새 릴리즈 에셋 이름 규칙이 바뀌면 `UpdateCheck.kt` 동시 수정.

### 4-5. 코드·문서
- 코드 내부 식별자(`claude-office` 패키지명, `CLAUDE_OFFICE_USER_DATA` 환경 변수, 업데이트 임시 폴더 `claude-office-update`, 설정 백업 `.claude-office.bak`): 표시에 안 보이는 것은 **바꿔도 이득이 적고 위험만 있다**. 환경 변수는 새·옛 둘 다 인식(옛 것 폐기 예고).
- 사용자 눈에 보이는 문구(4개 언어 사전 약 40곳+, 대화 상자·알림·트레이·창 제목)는 `t()` 사전 한곳 수정. 단 **"Claude"가 모델·제품 이름으로 나오는 문구(Claude 로그인, Claude 플랜)는 바꾸면 안 된다** — "Claude Office"만 정확히 치환(전체 치환 금지).
- ai-office라는 이름이 GPT 직원 도입과 맞물려, 소개 문구("Claude Code를 대체…")도 **공급자 중립으로 다시 써야 한다**(CONTEXT·README 한 줄 정의). Claude Code 비유가 핵심 지향점이라 문구는 대표 결정(11-⑤).
- 사용자 정의 **외부 hooks 표식**(`~/.claude/settings.json`에 넣는 사무실 hooks 이름·포트)에 옛 이름이 있으면 옛·새 모두 인식해 정리(안 하면 옛 hooks가 남는다) **[확인 필요: `external.ts` 표식 문자열]**.

### 4-6. 상표·브랜드
"Claude"가 이름에 들어간 현재 앱은 Anthropic 상표 정책상 위험 요소가 있었고, ai-office는 이를 피한다. 다만 **"ai-office"는 일반명사 조합이라 선점·상표 충돌 가능**(이미 같은 이름의 서비스·저장소 다수일 가능성). 대표/법무 확인 권고(검색은 이번에 하지 않았다 — **[확인 필요]**).

## 5. 마이그레이션 방안 (요약)

1. **(확정 B안: 다리 릴리즈 생략)** Codex 첫 공개와 개명을 한 번에 낸다. 릴리즈 체크리스트에 옛 이름 에셋 이중 업로드를 넣는다.
2. **저장소 개명**(리다이렉트 유지) + 사이트·문서 링크 갱신.
3. **개명 릴리즈**: `productName`·표시 이름 변경, **첫 실행 복사 마이그레이션(확정 B안)**. 환경 변수 새·옛 동시 인식.
4. 마이그레이션 실패·롤백 경로: 옛 폴더는 삭제하지 않고 N 버전 뒤에만 정리 안내.
5. 테스트: 옛 데이터 폴더 fixture(실제 `office.db` 스키마 버전별)로 "복사 → 열기 → 직원·보드·원격 인증서 유지" 자동 테스트, 두 앱 동시 실행 감지 테스트.

## 7. 개명과 Codex의 관계
- 둘은 독립 작업이지만 **대표 결정으로 한 번에 출시**한다(11절). 위험이 겹치므로(데이터 폴더 복사 + 새 공급자 + 3유형 온보딩) 개발은 **브랜치를 나눠 따로 검증**하고, 릴리즈 직전에 합쳐 "옛 설치본 → 새 버전 업데이트 → 3유형 첫 실행" 시나리오를 한 번 더 돈다.
- B안은 번들 ID·exe를 유지하므로 **다리 릴리즈는 필요 없다**. 대신 옛 앱이 찾는 **옛 이름 에셋(`Claude-Office-mac-arm64.dmg` 등)을 새 릴리즈에도 같이 올려야** 한다(4-2).
- Codex 번들(+약 260MB)로 설치 파일이 약 2배가 되고, Codex 버전은 앱 업데이트 때만 올라간다(4-2).
- 소개 문구는 특정 AI를 내세우지 않는 표현으로 개명과 함께 바꾼다(4-5).
