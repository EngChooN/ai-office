# Show GN 1.0 초안 — PM 검토 (김기획, 2026-11-04)

대상: `show-gn-1.0-draft.md` (원본 미수정). 기준: CHANGELOG.md(1.0.1)·README.ko.md·SPEC.md. 실제 설치·실행은 하지 않았고 문서와 대조만 했습니다.

## 한 줄 판정
기능 나열은 대체로 맞습니다. 다만 **휴대폰 연결 설명, 결재 이어 가기 표현, 피드백이 공개 이슈로 간다는 점**은 사실과 어긋나거나 빠져 있어 게시 전에 꼭 고쳐야 합니다. 개발자 독자에게는 '왜 써야 하나'와 '다른 도구와 뭐가 다른가'가 약합니다.

## A. 꼭 고칠 것

1. **휴대폰 포트 설명이 현재 기본값과 다름** (초안 '알려진 제한 사항')
   - 근거: SPEC.md 표 24 — 신규 설치 기본은 Tailscale 모드로 Tailscale 주소에만 바인딩하고, `lan`(같은 네트워크)·`router`(UPnP·포트포워딩, 고급)는 선택. README.ko.md:82의 "인터넷 쪽으로 열린다"는 `router` 방식 설명으로 보이며 신규 기본과 다릅니다(README도 같이 점검 필요).
   - 현재 → 제안: "켜면 PC의 포트(기본 47900)가 인터넷 쪽으로 열리므로…" → "기본은 꺼져 있습니다. 켜면 Tailscale 주소로만 접속되고(권장), 같은 네트워크 전용·공유기 포트포워딩 방식도 고를 수 있습니다. 포트포워딩 방식은 외부에 포트가 열리니 쓰지 않을 때는 끄세요. 폰의 결재·지시는 PC에서 하는 것과 같은 권한입니다."
   - 확인 필요: 신규 설치 기본이 실제 1.0.1에서도 Tailscale인지 `[확인]`.

2. **'앱을 껐다 켜도 이어서 처리' 과장** (결재함 항목, 첫 댓글)
   - 근거: CHANGELOG 1.0.0 — 7일 안의 것만 '이어 가기' 카드로 복원, 승인·반려·답은 **그 직원에게 새 지시로** 전달, 승인은 같은 도구·내용 1회만 자동 허용.
   - 현재 → 제안: "승인 대기 중인 결재는 앱을 껐다 켜도 이어서 처리됩니다." → "결재·질문은 저장되어, 앱을 껐다 켜도 7일 안의 것은 '이어 가기' 카드로 다시 뜹니다. 승인하면 직원에게 새 지시로 전달됩니다(중단된 작업이 그대로 재개되는 것은 아닙니다)."

3. **피드백이 공개 GitHub 이슈로 올라간다는 안내 없음** (피드백 항목)
   - 오류 기록을 가려도 이슈는 공개입니다. 개발자 독자는 이 점을 먼저 묻습니다.
   - 현재 → 제안: "…오류 기록을 첨부할지는 직접 고를 수 있고, 개인 경로 등은 가려집니다." → "GitHub 이슈는 공개이므로, 첨부 전에 미리보기로 내용을 확인하세요. 홈 폴더 위치·이름·이메일·비밀번호 같은 값은 가려 넣지만 완벽하다고 보장하지는 않습니다."

4. **데이터·비용 질문에 답이 없음** (독자 필수 질문)
   - 초안은 "사용량이 로그인 계정에 청구"만 말합니다. 추가: (a) 앱 자체 서버 없이 PC에서 돌고 대화·기록은 PC의 로컬 DB(SQLite)에 저장되며, 모델 호출은 사용자 Claude/ChatGPT 계정을 통해 각 회사로 간다는 것 (b) 직원을 여러 명 동시에 돌리면 구독 한도를 빨리 쓴다는 것 (c) 앱이 수집하는 텔레메트리 여부.
   - 확인 필요: (c) 텔레메트리 유무는 SPEC·README에서 확인하지 못했습니다. 개발 담당이 코드 기준으로 확정한 뒤 "수집하지 않습니다/수집합니다"를 한 줄로 쓰세요. 지어 쓰지 마세요.
   - 확인 필요: 구독 계정 로그인을 앱이 대신 쓰는 방식이 각 사 이용약관에 맞는지는 이 검토에서 확인하지 못했습니다. 게시 전 대표 확인 권장.

5. **작성 규칙·내부 일관성**
   - 초안 안내문은 "제작 동기 문장은 현재 글에 넣지 않았다"고 하지만, 본문에는 '만든 이유' 문단이 있습니다. 둘 중 하나를 고치세요. 규칙상 제목에 계기를 쓰는 것만 금지이므로 본문 문단은 괜찮고, 안내문과 체크리스트를 현실에 맞추면 됩니다.
   - 첫 댓글 "이 글은 사용 중에 본 것을 그대로 적었습니다"는 의미가 모호하고 'AI 생성 글 금지' 규칙과 충돌해 보일 수 있습니다. 대표님이 직접 고쳐 쓴 글이라는 점이 드러나게 대표님 말투로 다시 쓰거나 삭제하세요.
   - 게시 전 확인 목록의 맥 dmg·Windows Setup.exe 실기기 확인, 안드로이드 apk 파일 이름·릴리즈 첨부 여부는 아직 미확인입니다. 게시 전 필수로 올리세요.

## B. 있으면 좋은 것

6. **'왜 써야 하나'를 첫 3줄로.** 현재 "코드를 직접 다루지 않아도 되도록 만들었습니다"는 개발자 독자에게는 차별점이 아닙니다. 제안: "Claude Code·Codex 세션 여러 개를 터미널 창 대신 한 화면에서 보고, 파일 수정·명령 실행은 모두 결재함을 거치게 하는 앱" + "그래서 내가 얻는 것: 누가 무엇을 하는지 한눈에, 위험한 작업은 승인 후에만, 틀리면 되돌리기".

7. **다른 도구와의 차이 한 문단.** 독자는 'Claude Code를 터미널 여러 개로 쓰는 것'·다른 멀티 에이전트 도구와 비교합니다. 사실로 확인되는 차이만 쓰세요: 직원 단위 역할·팀장 위임, 결재함 단일 창구, 터미널에서 이미 도는 외부 세션을 '외부 직원'으로 관찰(옵트인 hooks, SPEC.md:53), Claude와 GPT 혼용. 다른 도구의 기능을 단정해서 비교하지는 마세요(검증 불가).

8. **'기술적으로 어떻게' 한 줄.** README 스택 줄 기준: Electron + React, Claude 직원은 Agent SDK, GPT 직원은 Codex app-server. 개발자 독자의 신뢰를 얻는 정보입니다.

9. **지원 범위 한 줄.** 맥은 Apple Silicon 전용(초안에 있음), Intel 맥·Linux 미지원도 명시. 라이선스 MIT는 본문 끝에만 있으니 상단 한 줄에도.

10. **제목.** "AI Office - Claude·GPT를 '직원'으로 고용해 사무실처럼 일 시키는 무료 데스크톱 앱"은 규칙(이름 - 기능 한 줄)에 맞습니다. '무료'는 홍보 어감이 있고 오픈소스가 더 정보적입니다. 제안: "AI Office - Claude Code·Codex 세션을 직원처럼 운용하는 결재 기반 데스크톱 앱(오픈소스)".

11. **받고 싶은 피드백을 더 구체적으로.** 현재 4항목 중 "어떤 업무에 써 보셨는지"는 설문 성격입니다. 제안 추가: "여러 직원을 동시에 돌릴 때 결재 알림이 감당되는지", "Windows에서 막힌 단계(설치·로그인·훅·Git 경로)", "휴대폰 연결 방식 중 어느 것을 썼고 어디서 막혔는지".

12. **'정식 1.0'과 Windows 미검증의 균형.** 제한 사항에 이미 정직하게 적혀 있어 좋습니다. 다만 "Windows는 충분히 검증하지 못했습니다"를 제목 아래 요약에도 한 줄 넣으면 기대치 관리가 됩니다.
