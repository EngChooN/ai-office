# 바탕화면 비서 디자인 전달안

## 대화 흐름·윈도우 배치 추가 시안 (2026-10-31)

`panel-concepts/conversation-windows-concept.png`는 승인된 D2를 바탕으로 한 라이트·다크 생성 시안이다. 화면 전체를 한 번에 보여 주기 위해 실제 400×520보다 세로로 길게 그렸으며, 그림 속 캐릭터·아이콘과 문구는 참고용이다. 실제 구현은 기존 D2 테마와 앱의 캐릭터 에셋을 기준으로 한다. 아래 기준이 그림보다 우선한다.

- **창과 배치:** 폭 400 CSS px, 높이는 기존 D2의 520px을 기본으로 하되 사용 가능 영역에 맞춰 줄이고 대화 영역만 스크롤한다. 머리줄과 입력창은 고정한다. 윈도우에서는 작업표시줄을 제외한 현재 모니터의 사용 가능 영역 안에 캐릭터와 창을 배치한다. 가장자리와 최소 12px을 두고 공간이 부족하면 반대편으로 옮긴다. 아래 작업표시줄 그림은 한 예이며 위·좌·우 위치와 배율 변경도 개발 검증이 필요하다.
- **머리줄:** 상대 선택 버튼에 현재 상대 이름과 펼침 표시를 둔다. 선택 목록은 앱 사이드메뉴의 실제 비서·직원·대화방 목록과 대응하고 현재 선택을 표시한다. `작업 중 N명`은 전체 작업 중 직원 수, `결재 N`은 대기 결재 수다. 결재 배지를 누르면 관련 대기 카드로 이동한다. 좁을 때 버튼의 이름을 말줄임하고 전체 이름을 접근 가능하게 제공한다.
- **대화:** 선택한 상대의 메시지와 관련 결재·질문·완료 카드를 발생 시간순으로 배치한다. 창을 열거나 상대를 바꾸면 최근 메시지가 보이도록 한다. 사용자가 이전 내용을 읽는 중에는 새 메시지로 스크롤을 빼앗지 않고 새 메시지로 이동할 수 있게 한다. 시안은 여러 카드의 형태를 함께 설명하기 위한 합성 예시다.
- **결재·질문:** 카드에는 요청자, 제목, 필요한 설명을 표시한다. 결재는 `승인`과 `반려`, 질문은 선택지와 `답 보내기`를 제공한다. 처리 중에는 해당 동작을 잠그고 상태를 표시하며, 성공·이미 처리됨·실패는 실제 결과에 따라 표시한다. 권한과 기존 결재 처리 경로는 그대로 따른다.
- **완료:** `○○ 완료`, 실제 결과 요약 한 줄, `결과 열기`를 표시한다. 결과가 없거나 열 수 없을 때는 그 사실을 표시하고 버튼을 비활성화한다. 결과 열기의 대상은 실제 업무 결과에 연결한다. 닫힌 창의 새 완료 배지는 결재 배지와 구분해 표시하고, 읽음 처리 기준은 개발 검토 시 확정한다.
- **캐릭터:** 완료 시 기존 `app/src/renderer/deskPet/sprites/face-happy.png` 기쁨 표정을 약 1.5초 표시하고 `○○ 작업이 완료됐어요` 말풍선을 최대 5초 표시한다. 생성 시안 속 다른 몸과 손 모양은 쓰지 않는다. 기존 표정 우선순위와 움직임 줄이기 기준을 따른다.
- **시각 규격:** D2의 라이트·다크 색상, 테두리, 시스템 글꼴, 보라색 강조를 재사용한다. 본문 13~14px, 카드 안팎 간격 12~16px, 입력창 높이 40px 이상, 주요 버튼 높이 32px 이상을 기준으로 한다. 긴 텍스트는 줄바꿈하고 이름·상태·포커스는 색상만으로 구분하지 않는다. 테마별 명암과 키보드 조작은 실제 구현에서 확인한다.

**인계·미확정:** 정리드가 프론트엔드 담당자에게 이 시안과 기준을 전달한다. 완료 배지의 읽음 처리, 결과가 여러 개인 업무의 연결 대상, 실제 상대 목록과 카드의 연결 규칙은 개발 검토에서 확정한다. 윈도우 실기기, 여러 작업표시줄 위치·배율, 실제 라이트·다크 동작은 아직 확인하지 않았다.

## 기준과 파일

직원 캐릭터는 `docs/design-refresh/v3/character-refine-v2-office.png`의 굵은 외곽선과 작은 몸, 단순한 얼굴을 참고한다. 비서 표식은 기존 `SparklesIcon`을 재사용한다 (`docs/specs/secretary-ui.md`). 첨부 이미지는 형태와 배치의 시각 시안이며 픽셀 단위 스프라이트나 실제 앱 캡처가 아니다. 정확한 한글과 상태는 아래 명세를 기준으로 한다.

## 캐릭터와 상태

- 캐릭터 영역 72×72 CSS px 기본, 설정 범위 64~80px. 비율 고정, 바닥 기준 중앙 정렬. 도트 가장자리는 nearest-neighbor로 확대하고 흐림 처리를 하지 않는다. 비서 반짝임은 머리 옆 12×12px, 기존 primary 색상과 SparklesIcon을 쓴다.
- 평소: 정면 기본 자세. 4~7초 간격으로 120ms 눈을 감았다 뜬다. 바쁜 동작은 없다.
- 결재: 오른쪽 위 18×18px `!` 배지, 말풍선 `결재 N건 · 첫 결재 제목`. 새 결재가 들어온 순간 2px 위로 이동 후 제자리로 240ms 한 번. 배지는 대기 결재가 있는 동안 유지한다.
- 직원 업무 중: 작은 작업 표시와 `직원 N명 일하는 중`. 비서 답변과 독립된 상태이며 작업 인원은 실제 값을 사용한다.
- 대답 중: `생각하는 중…` 말풍선, 완료 시 실제 답을 짧게 보여 준다. 실패 시 실제 오류 안내를 보여 준다.
- 여러 상태가 겹치면 결재 배지는 항상 유지하고 말풍선은 대답 중 → 새 결재 → 직원 업무 순으로 한 개만 표시한다. 새 결재 문구를 표시하지 못한 경우 현재 표시가 끝나면 한 번 보여 준다. 말풍선은 5초 뒤 접되 대답 중은 완료까지 유지한다. 움직임 줄이기 설정에서는 움직임 없이 상태를 표시한다.
- 말풍선 최대 폭 240px, 안쪽 여백 10px 12px, 모서리 12px, 13px 글자, 제목은 최대 두 줄 후 말줄임. 전문은 창의 결재 목록에서 확인한다.

## 작은 창

- 캐릭터 옆 340×최대 520px, 화면 사용 가능 영역에서 12px 이상 여백. 공간이 부족하면 반대편에 배치하고 높이를 줄여 내부 스크롤한다. 흰 카드, 기존 앱의 카드/테두리/그림자와 시스템 글꼴 재사용. 모서리 16px, 내부 여백 16px, 구역 사이 16px, 기본 글자 13~14px, 제목 15px semibold.
- 위에서부터 `비서`와 닫기, 최근 대화(최신 내용, 스크롤), 입력창과 보내기, `결재 대기 N건`, 목록, `앱에서 열기`. 입력창은 40px 이상, 버튼은 최소 44×32px. 긴 제목은 두 줄로 줄이고 전체 제목에 접근 가능하게 한다.
- 결재 항목은 제목, `승인`(기존 기본 버튼), `반려`(기존 보조 버튼), 해당 결재를 여는 `앱에서 열기`. 이미 처리된 항목은 `이미 처리됨`을 표시하고 처리 버튼을 감춘다. 자동으로 처리된 경우 `자동결재`를 별도 문자로 표시한다. 목록이 비면 `결재 대기 없음`.
- 전송 중·처리 중에는 해당 버튼을 비활성화하고 `처리 중…`을 표시한다. 실패 시 결과를 단정하지 않고 오류와 재시도 방법을 표시하며 실제 상태를 갱신한다. 색상만으로 상태를 구별하지 않는다. 키보드 포커스 표시, 버튼별 접근 가능한 이름, 상태 변경 알림을 제공한다.
- 맨 아래 `앱에서 열기`는 비서 화면으로, 항목의 `앱에서 열기`는 해당 결재로 이동한다. 변경 지시는 기존 비서 확인 카드로 연결한다.

## 개발 전달 및 확인할 사항

캐릭터 몸통은 창 열기만 한다. 드래그는 클릭과 이동 거리로 구분하고, 중복 클릭 방지·권한·자동결재·공통 처리 경로는 기획서의 안전장치대로 구현한다. 기준 거리와 실패·권한 없음의 상세 문구는 개발 검토에서 확정한다. 이 문서는 CSS/canvas 작업을 위한 시각 기준이며 실제 작동과 접근성 검증은 구현 후 필요하다. 시안 확정 후 정리드가 박패턴에게 전달한다.

## 구현용 최종 에셋 (2026-10-31, 리드 확정)

- 사용 파일: `sprites/body-idle.png`, `sprites/body-blink.png` (90×127, 여백 없이 잘라 낸 원본). 대표 피드백("너무 작다")에 따라 투명 여백을 없앴다. 표시 크기는 캐릭터 **높이 기준 기본 112px, 설정 범위 80~160px**이다. `{64,80,128,160}` 크기의 정사각 body 파일은 여백이 커서 캐릭터가 작게 보이므로 쓰지 않는다.
- 몸통은 `idle-160.png`에서 생성 이미지의 보라 반짝임을 지운 것 한 장이 기준이다. `blink`는 같은 그림에서 눈 부분만 감은 눈으로 바꿨다. 같은 크기끼리 눈 영역 밖의 픽셀이 모두 같고, 네 모서리가 투명한 것을 스크립트로 확인했다.
- 결재 상태, 직원 업무 중, 생각 중은 별도 그림 없이 `body-idle` 위에 코드로 얹는다. 반짝임은 `SparklesIcon` 12px, 결재는 18px `!` 배지, 작업 표시와 생각 표시는 작은 아이콘이다. 이렇게 하면 상태가 바뀌어도 몸통이 흔들리지 않는다.
- 아래의 `{idle,blink,approval,working,thinking}-*.png` 20장은 중간본이므로 사용하지 않는다.

## 스프라이트 제작 중간본 (2026-10-31)

`sprites/{상태}-{물리 픽셀 크기}.png`. 상태는 `idle`, `blink`, `approval`, `working`, `thinking`, 크기는 `64`, `80`, `128`, `160`이다. 128px은 64px 표시의 2배, 160px은 80px 표시의 2배다. 총 20장이다.

프레임 제안: 평소 `idle` 유지 4~7초 → `blink` 120ms → `idle`. 결재 도착 `approval`을 표시하고 위치를 위로 2px 이동했다가 240ms 안에 복귀시키며 결재가 남으면 `approval` 유지. 직원 업무 중 `working` 유지. 대답 중 `thinking` 유지 후 `idle`로 복귀. 말풍선 텍스트는 이미지 밖에서 표시한다.

**검수 미완료:** 현재 그림은 상태별로 따로 생성되어 캐릭터의 위치·크기·세부 형태가 서로 다르다. 전환 시 흔들려 보이며, 기존 SparklesIcon과 정확히 일치하지 않고 결재 배지도 명세의 18px에 맞지 않는다. 기계적 축소본으로 여백도 크므로 구현용 최종 에셋으로 사용하지 않는다. 같은 기준 캔버스에서 프레임을 맞추고 실제 크기로 재검수해야 한다. 승인된 전체 화면 시안의 첨부 아이콘은 최종 명세에 없는 요소다.

## 추가 움직임 디자인 제안 (2026-10-31)

현재 앱의 기준은 `app/src/renderer/deskPet/sprites/body-idle.png`, `body-blink.png`의 60×94 투명 PNG다. 아래는 제작 전 동작 제안이며 `motion-concept.png`는 참고 시안이다. 시안은 크기와 원점이 정렬된 프레임 파일이 아니다.

| 동작 | 순서와 각 프레임 시간 | 사용 시점 |
| --- | --- | --- |
| 숨쉬기 | 기본 500ms → 살짝 들숨 400ms → 기본 500ms → 약한 날숨 400ms | 평소 반복, 1.8초. 발과 몸의 중심은 고정 |
| 두리번 | 기본 150ms → 왼쪽 눈동자 350ms → 기본 150ms → 오른쪽 눈동자 350ms → 기본 150ms | 15~30초 간격으로 한 번, 눈동자만 이동 |
| 결재 알림 | 기본 100ms → 한 손 살짝 들기 180ms → 유지 240ms → 기본 180ms | 새 결재 도착 시 한 번, 결재 배지는 별도 유지 |

일하는 중이나 생각 중인 표시는 몸과 분리하여 유지한다. 동작이 겹치면 결재 알림을 우선하고, 끝나면 현재 상태에 맞춰 숨쉬기를 재개한다. 눈 깜빡임은 두리번과 결재 동작이 끝난 뒤 실행한다. 움직임 줄이기 설정에서는 기본 자세로 유지하며 결재 배지와 문구는 그대로 표시한다.

**제작 및 검증 필요:** 60×94의 동일 원점 투명 프레임과 2배 프레임 미리보기는 아직 만들지 않았다. 시안 속 인물과 손은 확정 원본과 픽셀 단위로 일치하지 않으므로 앱 에셋으로 사용하지 않는다. 작업 표시나 말풍선과의 실제 겹침도 확인하지 못했다.

## 표정 디자인 시안 (2026-10-31)

`expression-concept.png`는 표정 방향을 보여 주는 생성 시안이다. 왼쪽 위부터 가로로 놀람·생각 중·기쁨, 아래 왼쪽부터 걱정·졸림·집중이다. 기준 캐릭터와 픽셀이 일치하는 60×94 스프라이트가 아니며 앱에 사용할 수 없다. 대표가 2026-10-31 이 방향대로 진행하기로 확인했다.

| 표정 | 사용 시점 | 유지 시간 |
| --- | --- | --- |
| 놀람 | 새 결재 도착 | 약 1.5초 |

| 졸림 | 결재와 일하는 직원 없이 10분 넘게 조용할 때 | 일이 생길 때까지 |
| 집중 | 직원이 일하는 중 | 일이 끝날 때까지 |

겹칠 때 우선순위는 놀람 → 걱정 → 기쁨 → 생각 중 → 집중 → 졸림 → 평소다. 움직임 줄이기에서도 표정은 바뀌고 깜빡임은 멈춘다. 생각 중·집중 등 지속되는 표정에는 눈 감은 프레임이 필요하다. 최종 그림은 `body-idle.png`와 60×94 캔버스 및 위치를 맞추고 얼굴 밖 픽셀을 보존해야 한다.

### 표정 최종 그림 (2026-10-31)

`expression-sprites.py`가 앱의 `body-idle.png` 위에 눈썹·눈·입만 픽셀 단위로 덧그려 `sprites/expressions/`에 만든다. 표정은 스크립트 안의 글자 그림(글자 하나 = 픽셀 하나)으로 정의되어 있어 그곳만 고치면 다시 만들 수 있다.

- `face-{surprised,thinking,happy,worried,sleepy,focused}.png`: 놀람·생각 중·기쁨·걱정·졸림·집중 (60×94)
- `face-{thinking,sleepy,focused}-blink.png`: 오래 유지되는 표정의 눈 감은 프레임. 감은 눈은 `body-blink.png`와 같고 눈썹·입은 표정 그대로다. 놀람·걱정은 짧게 지나가고 기쁨은 이미 눈을 감은 표정이라 만들지 않았다.
- `preview-{112,160}@2x.png`: 앱 크기(높이 112·160px)의 2배 그림과 얼굴 확대
- 검사: `app-sprites.py --check`가 표정 그림도 검사한다. 평소 그림과 얼굴 영역(x 17~37, y 28~43) 밖이 픽셀까지 같은지, 눈 감은 프레임은 같은 표정과 눈 영역 밖이 같고 눈 영역은 `body-blink.png`와 같은지 본다.

앱 연결(표정 전환·우선순위·유지 시간)은 아직 하지 않았다. 표정 그림은 앱 폴더에 넣지 않았다.
