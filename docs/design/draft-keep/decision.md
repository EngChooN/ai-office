# 작성 중인 글 유지 — 최종 설계 결정 (정리드, 2026-11-25)

두 안(plan-choi.md, plan-park.md)은 방향이 같다: 컴포넌트 밖 메모리에 키별로 보관, `useState` 한 줄 교체, 성공 후 비우기, 기존 채우기 신호는 그대로, File 객체 그대로 보관, ⌘K·펫 창 제외, 대화방은 방별 키.

## 선택
- **뼈대는 최가독 안** — `lib/drafts.ts`의 작은 zustand 스토어 + `useDraft(key, 초기값)` + `clearDraft(prefix)`. 기존 관례(작은 기능 스토어 = zustand)와 같아 읽는 사람이 새 개념을 배울 필요가 없다.
- **박패턴 안에서 가져옴**
  - 값이 처음 값(빈 글·빈 배열)으로 돌아가면 항목을 지운다 → 쌓이지 않고, 별도 "비우기" 호출 없이 기존 `setDraft('')`만으로도 정리된다.
  - `initial`을 처음 렌더 값으로 고정(ref) — 최가독 예시는 `[]` 같은 객체 초기값이면 선택자가 매번 새 값을 돌려 무한 렌더가 날 수 있다(zustand 5). 이 점을 테스트로 막는다.
  - 첨부는 키가 있을 때만 보관, 없으면 지금과 같은 `useState`(대화상자 등 영향 없음). 최가독의 `useId` 임시 칸은 쓰지 않는다(더 단순).
  - 직원이 해고·삭제되면 `clearDraft('staff:<id>:')`.
  - 업무 지침 편집은 `isEditing`도 같이 보관해야 돌아왔을 때 편집창이 열려 있다.
- **보내기 실패 처리** — "먼저 비우고, 실패하면 되돌린다". 먼저 비우는 지금 방식이 연타 중복 전송을 막아 주므로 순서를 바꾸는 것보다 영향이 작다.

## 범위 (최가독 1차 + 긴 글 칸)
- 이번: 직원 지시창(+첨부·고른 매뉴얼), 분신 지시(+첨부), 대화방(방별, +첨부), 업무 보드 새 카드(+첨부·팀·프로젝트·자율), 비서 페이지, 예약 폼, 업무 지침 편집, 커밋 메시지·PR 제목.
- 채택 안 함: 이름·직무·참고 문서 경로(짧은 한 줄, 편집 중 상태와 얽힘), 결재 카드 의견칸(카드 수가 많고 카드가 사라질 때 정리 지점이 따로 필요) — 같은 훅으로 나중에 한 줄씩 붙일 수 있다.
- 제외: 회의실(개편 중), 대화상자, 검색칸, ⌘K·펫 창(별도 창이라 메모리 공유에 IPC 필요).

## 박패턴 안의 `useSyncExternalStore` 직접 구현을 안 쓴 이유
기능은 같지만 프로젝트 관례가 zustand이고, 변경마다 모든 구독자를 깨우는 구조를 직접 관리할 필요가 없다.
