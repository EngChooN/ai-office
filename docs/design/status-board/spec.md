# 상태 보드 최종 기획서 (2026-11-26)

대표가 고른 시안(`decision.md`)과 1단계 구현·조사·검토 결과를 합친 문서입니다. 디자인 5항목은 모두 대표가 직접 골랐습니다.

## 1. 목적
직원에게 맡긴 일이 지금 어떤 상태인지 보는 **읽기 전용 상태 보드**를 데스크톱·안드로이드에 만든다. 대표 응답을 기다리는 일은 맨 위에 따로 보이고, 검토 뒤 코드가 바뀐 일에는 '재검토 필요'가 붙는다.

## 2. 대표 결정
- 1차 범위: 상태 보드 + 대표 응답 대기 + 재검토 필요 표시
- 안드로이드: 1차부터 포함(읽기 전용 보드·대기 줄)
- 데모 GIF: 기능 완료 뒤 시점 재논의
- 디자인 5항목: 아래 4장(대표 직접 선택)

## 3. 기능 규칙 (구현됨, 커밋 `c299a18`)
- 상태 5개, 보드 순서: 할 일 → 진행 중 → 대표 응답 대기 → 검토 중 → 완료. 4개 언어 문구 있음.
- 저장: 상태, 대기 시작 시각(대표 응답 대기일 때만), 검토 커밋. 상태 칸이 없는 옛 기록은 보드 칸 위치로 채운다. '진행 중'으로 돌아가면 검토 기록 삭제.
- 스냅샷: 형식 버전(1)·상태·대기 시작 시각·검토 커밋 + 서버가 매번 계산하는 '재검토 필요'(필요/아님/판단 불가). 읽는 쪽은 버전 분기 없이 모르는 칸은 버리고 빈 칸은 기본값.
- 재검토 판정: 검토 커밋≠HEAD → 필요, 같음 → 아님, 커밋 없음·HEAD 조회 실패 → 판단 불가(표시 끔). 저장 전 파일 변경은 반영하지 않음(커밋만 비교).
- 대기 시간: 음수는 0분, 1분 미만은 "1분 미만", 이후 "42분", "3시간 5분", "2일 4시간".
- 검증 결과는 통과/실패 요약과 원본 로그 링크만.
- 호환(강백엔): 공개 서버는 스냅샷을 받지도 중계하지도 않아 영향 없음. 기존 필드는 바꾸거나 지우지 않고 새 필드만 더한다. 안드로이드는 모르는 필드 무시 확인. `mobile/` 웹 화면은 미확인.

## 4. 디자인 (모두 대표 확정)
| 항목 | 확정안 |
|---|---|
| ① 데스크톱 배치 | 지금 4칸 그대로, 카드에 상태 칩. 대기 칸은 새로 만들지 않음 |
| ② 안드로이드 | 개수 타일(대기·진행 중·검토 중·완료) + 고정 대기 줄 + 상태 순 목록 |
| ③ 대기 줄 | 맨 위 노란 띠 한 줄(결재 띠와 같은 자리·모양), 오래된 순, '+N건' |
| ④ 재검토 표시 | 파랑 테두리 칩 '↻ 재검토 필요'(라이트 #0B6DA1 / 다크 #5CC8FF), 완료 카드에서도 흐리지 않음 |
| ⑤ 말풍선 | 대표 응답 대기 직원만 '!' 말풍선 유지, 마우스를 올리면 일 이름·대기 시간 |

**미확정 디자인 항목: 없음.** 세부 수치는 `decision.md`의 개발 전달 기준을 따른다. 영어·일본어·중국어 긴 문구가 칩·띠를 넘치는지는 구현 뒤 확인한다.

## 5. 재사용·신규 (최가독)
- 재사용: 데스크톱 `Badge`·`Page`·`Card`·`useNow`·`ApprovalBand`(선례)·`HelperChip` 모양. 안드로이드 `OfficeCard`·`StatusBadge`·`SummaryTiles`·`DecisionCard`(선례).
- 조금 고침: `BoardPage`의 `TaskCard`·`TaskDetail`, `STATUS_META`와 같은 모양의 업무 상태 표, 안드로이드 `elapsedText`(대기 문구는 `waitLabel`로 통일).
- 새로 만듦: 업무 상태 칩, 대기 띠/줄, 재검토 칩, 안드로이드 업무 목록 화면과 데이터 틀, 말풍선 연결.
- 폰 응답(`statusBody`·`RemoteStaff`)에 스냅샷을 실어야 한다(아직 안 실림).

## 6. 남은 일 (한리뷰 1차 판정: 수정 필요)
1. **커밋 번호 형식 통일** — 짧은 번호와 전체 번호를 비교하면 같은 커밋인데도 '필요'가 나온다. 전체 번호만 허용하거나 같은 커밋인지 확인 후 비교, 테스트 추가.
2. **조회값 재사용 범위** — HEAD 조회 보관함은 응답 한 번 안에서만 공유, 다음 응답은 새로 조회, 테스트 추가.
3. 앱이 일할 때 상태를 바꿔 주는 연결(일 시작·결재 대기·검토 넘김) 아직 없음. 채팅으로만 맡긴 일은 이번 범위 밖.
4. 스냅샷을 폰 응답에 싣기, `mobile/` 웹 화면의 모르는 필드 처리 확인.

## 9. 완료 기준
1. 대표가 고른 시안대로 두 앱 보드가 보이고 같은 스냅샷을 읽어 상태가 일치한다.
2. 대기 줄에 규칙대로 대기 시간이 표시된다.
3. 검토 뒤 커밋이 바뀐 일에 '재검토 필요'가 뜨고, 판단 불가일 때는 안 뜬다.
4. 타입 검사·자동 테스트 통과, 한리뷰 승인, 오큐에이 체크리스트 실패 0건.
