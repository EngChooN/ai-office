## 1. 두 방식은 어떻게 다른가 (쉬운 설명)

| | 지금 방식 (위험한 것만 막기) | 바꿀 방식 (안전한 것만 열기) |
|---|---|---|
| 비유 | 출입문 경비가 **수상한 사람 명단**을 보고 막는다. 명단에 없으면 통과 | 경비가 **등록된 사람 명단**을 보고 연다. 명단에 없으면 전부 대표에게 묻는다 |
| 새 위험 수법이 나오면 | 명단에 없으니 **통과해 버린다** → 뚫린 뒤에 명단을 늘린다 | 명단에 없으니 **일단 막힌다** → 안전이 확인돼야 명단에 추가 |
| 불편함 | 거의 없음 | 처음 보는 명령은 전부 대표 확인 → 요청이 늘어남 |
| 실패하는 방향 | 위험한 걸 놓침 (위험) | 안전한 걸 막음 (불편) |

**지금 코드의 실제 모양 (중요)**
- 명령 **이름**: 이미 허용 목록입니다. `SAFE_COMMANDS`·`RULE_COMMANDS` 등에 없는 이름은 대표 확인입니다 (`autoApprove.ts:361`, 커밋 `5cbb3ec`의 "fail-closed").
- 명령의 **인자·옵션·연결(`&&`, `$()`, 리다이렉트 등)**: 위험한 모양을 골라 막는 블랙리스트입니다. 예: `git push`, `sed -i`, `curl -d`, PATH 조작, 환경변수 주입.
- 그래서 "전환"은 **인자 쪽도 "알려진 안전한 모양만 허용"으로 바꾸는 것**입니다.

## 3. 지금 방식이 반복해서 뚫린 사례와 위험

### 검토 이력 요약 (코드·커밋 기록 기준)

### 패턴: 왜 계속 뚫리나
1. **셸 문법이 너무 넓다.** 같은 뜻을 쓰는 방법이 무한합니다(따옴표, 변수, 치환, 축약어, 옵션 별칭). 블랙리스트는 방법을 하나씩 추가할 수밖에 없습니다.
2. **도구마다 옵션 규칙이 다르다.** `-w`가 값을 받는지(npm) 안 받는지(pnpm) 같은 차이를 놓치면 이름 하나가 숨습니다.
3. **라운드마다 새 구멍이 나온다.** 11차까지 막았는데 이번 작은 변경에서도 5종이 나왔습니다. 끝이 보이지 않습니다.
