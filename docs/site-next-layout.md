# 소개 페이지 배치안과 새 캡처 목록

작성: 이디자 · 2026-11-14 · 디자인 제안, 대표 미확인
기준: `docs/site-next-copy.md`, 현재 `site/index.html`, `site/assets/screens/README.md`. 실제 앱 조작과 새 캡처는 아직 확인하지 않았다. 미배포 기능은 이번 배포 포함과 실제 화면 확인을 모두 통과할 때만 싣는다.

## 공통 디자인 기준

현재 사이트의 짙은 배경 `#14131C`, 카드 `#201F2D`, 밝은 글자 `#EDEBF8`, 보조 글자 `#A7A3C4`, 보라 강조 `#9B8CFF`, 분홍 보조 강조 `#FF7AC6`를 재사용한다. 카드와 화면 틀은 기존처럼 18px 둥글게, 얇은 테두리와 은은한 그림자를 쓴다. 강조색은 제목의 일부, 버튼, 작은 표시에만 쓴다. 노랑은 주의·처리 상태에만 제한한다. 색만으로 상태를 구별하지 않고 글자도 함께 둔다.

레트로는 사이트 전체를 도트 화면으로 바꾸지 않고 스타일 섹션의 실제 앱 캡처에서 보여 준다. 레트로 캡처 안의 각진 말풍선·도트 글꼴은 그대로 보존하고, 바깥 틀은 사이트의 둥근 카드로 통일한다. 화면 글자를 읽을 수 있도록 사진을 임의로 잘라 내지 않는다. 좁은 화면에서 너무 작아지는 결재·비서 화면은 전체 화면 사진과 별도로 핵심 부분을 확대한 보조 이미지 또는 실제 텍스트 설명을 제공한다. 확대는 원본 화면 내용을 바꾸지 않는다.

PC 기준 화면 폭 1400px: 기존처럼 내용 최대 1140px, 좌우 안쪽 여백 24px, 섹션 상하 약 112px. 휴대폰 기준 폭 390px: 좌우 여백 20~24px, 섹션 상하 약 64~72px, 한 줄 배치. 모든 값은 제안이며 실제 네 언어와 화면에서 줄바꿈·잘림 확인 후 조정한다. 화면 사진은 비율을 유지하고, 가로 넘침 없이 표시한다. 키보드 초점, 버튼 이름, 이미지 설명도 유지한다.

## 섹션별 배치 — 위에서 아래로

| 5. 안전 | 결재 화면을 크게 한쪽에, 한 줄 설명·위험 알림·직원별 허용·되돌리기 설명을 반대편에 둔다. 장비 카드는 보조 사진. | 결재 사진과 설명을 먼저, 장비 사진과 설명을 다음에 쌓는다. 실제 확인하지 않은 동작은 캡처나 문구로 단정하지 않는다. |

**맨 위 큰 사진 추천 1안:** 최신 `office.webp`를 다시 찍어 직원들이 일하는 사무실 실내와 왼쪽 주요 메뉴가 한 화면에 보이게 한다. 앱이 무엇인지 첫눈에 알 수 있고 색감과 둥근 화면을 함께 보여 준다. 개인 정보 없는 예시 회사와 읽을 수 있는 창 크기를 사용하며 중요한 글이나 메뉴를 가리는 팝업은 띄우지 않는다. 비서의 자세한 기능은 바로 아래 독립 섹션의 큰 사진에서 설명한다. 기존 페이지도 실내 사진을 첫 화면에 사용한다는 점을 코드에서 확인했다. 실제 최신 앱 화면의 적합성은 촬영 때 확인해야 한다.

## 새로 찍을 캡처 목록

공통: WebP, 한국어부터 `site/assets/screens/ko/`에 저장. PC는 **2720×1720**(표시 기준 1360×860의 2배), 휴대폰은 **1170×2532**(표시 기준 390×844의 3배). PC/휴대폰 모두 기본은 **라벤더·다크**. 예외인 레트로는 아래에 표시하며 기존 캡처 규칙의 테마 예외로 기록한다. 같은 이름을 네 언어 폴더에 쓰고, 한국어는 필수다. 다른 언어 파일이 없으면 기존 사이트는 영어 → 한국어 순으로 대신 보여 준다. 네 언어의 새 화면 확인 및 촬영 여부는 후속 작업에서 확인한다. 빈 데모 데이터와 가상 이름·경로를 사용한다. 실제 촬영·압축은 담당자에게 인계한다.

PC·휴대폰은 위의 공통 픽셀 크기를 뜻한다. `phone-fold.webp`는 넓은 폰의 좌우 분할을 보여 주므로 일반 휴대폰의 세로 크기 1170×2532를 그대로 적용하면 장면이 성립하지 않을 수 있다. **촬영 기기와 실제 분할 폭을 먼저 확인하고**, 원본 비율을 유지한 별도 크기를 정한 뒤 규칙 예외로 기록한다. 잘라서 세로 규격에 억지로 맞추지 않는다. `day-morning.webp`를 재사용하므로 별도의 `secretary-summary.webp`는 만들지 않는 제안이다. 사진 속 글자가 작으면 별도 상세 이미지 또는 설명으로 보완한다.

기존 `staff-mix.webp`, `board.webp`, `meeting.webp`, `dashboard.webp`, `exterior.webp`, `decorate.webp`, `demoday.webp`, `export.webp`, `interaction.webp`는 현재 화면과 맞는지 후속 확인 후 재사용한다. `settings.webp`, `providers.webp`, `secretary.webp`는 최종 구성에서 필요 여부를 정한다. 캡처별 설명점은 새 화면에서 가리는 곳이 없는지 다시 위치를 잡는다. README의 압축 기준과 원본 보관 규칙을 따른다.

## 확인과 인계

- 확인함: 기획안의 순서·문구, 현재 사이트의 색상·둥근 틀·교차 배치, 스크린샷 규칙과 기존 파일 목록.
- 확인 못 함: 실제 최신 앱의 화면·동작, 미배포 비서 기능과 처리 중 상태, 레트로의 결재 카드·메뉴, 테마 개수, 폴드 촬영 크기, 네 언어 및 1400/390 실제 배치. 사진은 아직 찍지 않았다.
- 정리드·촬영 담당: 미배포 기능이 이번 배포에 포함되고 화면 확인을 통과하는지 먼저 확인한다. 실패하거나 배포에서 빠진 기능의 문구와 사진은 뺀다. 촬영 후 네 언어·두 화면 폭에서 잘림과 글자 크기, 이미지 대체 경로를 확인한다. 이 문서는 디자인 제안이며 제품 코드는 수정하지 않았다.
