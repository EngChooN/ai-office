## 기능 1. 단체방 B안 + 자동 접힘 — 박패턴 구조 + 이디자 세부
| 쟁점 | 결정 | 이유 / 채택 안 한 안 |
|---|---|---|
| 방 목록 계산 | `useRoomEntries`를 하나 두고 목록(ChatSide)·띠·가로 탭이 같이 씀 (박) | 세 표현이 같은 규칙을 따르게 함 |
| `RoomTabs` | **남김**, 폰 비분할(가로 짧은 폰 `short:`)에서만 보임 (박) | 최가독의 삭제안은 가로 폰 머리에서 방 전환을 없앰(코드 확인: `split:hidden slim:hidden`만 숨김) |
| 56px 띠 | 새 파일 `ChatRoomRail.tsx` (박) | 최가독의 `ChatSide`에 `rail` 속성 추가는 그림·말풍선·겹침이 전혀 달라 한 컴포넌트 안에서 분기가 많아짐 |
| 머리 | `ChatPage` 안에서 바로 고침. 데스크톱 머리 함수만 새로 둠 (박) | `ChatHeader.tsx` 추출(최)은 250줄 이동이라 이번에는 미룸 |
| 접힘 상태 | `'auto' \| 'open' \| 'rail'` 3가지를 기기에 저장 (이디자=박) | 최가독의 '고정'만으로는 '직접 접음'을 표현 못 함 |
| 기준 | 방 목록+대화 행의 실제 폭. <840이면 띠, 다시 펴질 때는 ≥856 (세 안 공통 + 이디자·박 16px 여유) | 행 폭은 접어도 그대로라 되먹임 없음. 16px은 스크롤바 1~2px 흔들림 방지 |
| 얼굴 겹침(<560) | 별도 측정 없이 행 폭 − 목록 폭으로 계산 | 두 번째 관찰자 불필요 |
| 판정·요약 계산 | 순수 함수 `shared/chatRoomLayout.ts`(`roomListMode`, `summarizeRoomPeople`) + 시험 (박) | 경계값을 시험으로 고정 |
| 사전 키 | 이디자 키 이름, 꼬리표는 기존 `chat.room.groupTeams/Labs` 재사용 | 뜻이 같으면 새 키를 만들지 않음 |
| '기존 접힘 상태' | 폰 배치 변형 + 직원 칩 `+N명` (이디자 확인) — 둘 다 그대로 | |

## 기능 2. 휴대폰·PC 연결 1안 — 박패턴 구조 + 최가독 일부
| 쟁점 | 결정 | 이유 |
|---|---|---|
| 구조 | `shared/connectModel.ts`(순수, 시험) + `features/connect/ConnectSection.tsx` + 기존 조각 export (박) | 화면 판단을 시험할 수 있게 |
| 상태 읽기 | 중복 `useRemoteStatus`를 한 곳으로 (최·박 공통) | |
| 공유기 직접 | 기존 안내 창(`RemoteGuide`) 재사용 (박) | 포트·공유기 단계를 다시 쓰는 위험이 큼 |
| 휴대폰 마지막 접속 | `AuthGuard`에 메모리 필드 하나, 새 QR이면 비움, 요청마다 화면 알림 안 보냄 (세 안 공통) | 저장 구조 변경 없음 |
| 두 번째 휴대폰 | 같은 화면 안 확인 문장 (이디자·박) | `window.confirm`보다 설명이 분명 |
| 코드 복사 | 1회용 코드만 복사 (박) | 토큰·QR 주소는 클립보드에 남기지 않는 기존 원칙 |
| 사전 | 새 파일 `dict/connect.ts` + 기존 키는 값만 수정 (박) | 4개 언어 대조가 쉬움 |
| 안드로이드 '코드로 연결' | 이미 반영함(임안드, 빌드 통과) | 박패턴의 '후속' 안은 대표 요청으로 앞당김 |
