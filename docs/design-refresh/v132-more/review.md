## 필수 (revise)

### A1. 휴대폰에서는 '내가 내린 결재' 기록이 실시간으로 늘지 않는다 — ③
- `app/src/main/index.ts:310` 은 새 결재 기록을 PC 화면(IPC)으로만 보낸다. 휴대폰으로 가는 `remote?.publish`에는 없고, `HubEvent`(`remote/events.ts:9`)에도 `approvalRecord`가 없다. 그런데 휴대폰 쪽은 `remoteOffice.ts:77`에서 이 이벤트를 기다린다 → 영원히 오지 않는다.
- 결과: 휴대폰에서 [승인]을 눌러도 결재 탭 아래 기록은 그대로다. 탭을 다시 열어야 보인다. (위쪽 대기 카드는 snapshot으로 줄어서 맞게 보임)
- 고칠 방향: 허브에 `approvalRecord` 이벤트를 추가하거나, 더 간단히 `ApprovalTab`에서 `staff.approvals.length`가 줄 때 첫 쪽을 다시 불러온다(휴대폰·PC 모두 동작).

### A2. 결재 탭으로 열라는 기억(`staffTab`)이 지워지지 않는다 — ③
- `store.ts:134` `openStaffApprovals`가 넣은 `staffTab`을 `StaffPanel.tsx:339-342`가 읽기만 하고 비우지 않는다. 같은 구조의 `staffDraft`는 쓰고 나서 비운다(`StaffPanel.tsx:330`).
- `PanelBody`는 `key={staff.id}`(224행)로 직원이 바뀔 때마다 새로 만들어진다. 그래서 '확인하기'로 A를 열고 → B를 보고 → 다시 A를 누르면 대표가 요청하지 않았는데 결재 탭이 열린다. 패널을 닫았다 다시 열 때도 같다.
- 고칠 방향: 탭을 적용한 직후 `staffTab`을 null로(`staffDraft`와 같은 방식).

### A3. 보고서가 새 기록을 일정 시점부터 따라가지 못한다 — ④
- `ReportPage.tsx` 불러오기 효과가 `liveLogs.length`를 감시한다. 그런데 `store.ts:98,173`에서 `liveLogs`는 500개로 잘라 쓰므로 500개가 차면 길이가 더 안 변한다. 앱을 오래 켜 둔 날 '오늘' 보고서는 그 뒤 기록이 안 늘어난다.
- 같은 효과가 새 기록 1건마다 하루치 전체(도구 줄·첨부 포함)를 다시 읽는다. 지난 날짜를 보는 중에도 다시 읽는다. 늦게 온 앞 응답을 버리는 장치도 없어 날짜를 빠르게 넘기면 이전 날 결과가 덮어쓸 수 있다.
- 고칠 방향: 마지막 기록의 id/시각을 감시하고, 오늘일 때만 새로 읽기 + 요청 번호로 낡은 응답 버리기.

### A4. 휴대폰 화면 + 예전 PC에서 보고서가 '기록 없음'처럼 보인다 — ④(휴대폰 예전 PC 처리)

- 결재 탭은 `unknown_method`를 잡아 "PC를 업데이트해 주세요"를 보여 주는데(`ApprovalTab.tsx` `isOldPc`) 보고서는 같은 처리가 없다. (휴대폰에서 보고서 화면에 닿는 것은 `layout/pages.ts` 공용 목록으로 본 추정)
- 고칠 방향: 불러오기 실패를 잡아 안내(예전 PC면 업데이트 안내, 아니면 다시 시도) + 보고서 복사(`copyReport`)의 실패도 잡기.

## 권장

### B1. 팀 만들기 중간 실패 — 심각도: 중간(드물지만 흔적이 남음) — ②
- `OrgCreateDialog.tsx:60-62`는 팀 만들기 → 직원 한 명씩 옮기기 → 하는 일·리더 저장, 3단계를 따로 부른다. 가운데서 실패하면 (휴대폰 원격 호출 중 연결 끊김이 현실적) 팀은 만들어지고 일부 직원만 옮겨진 채 하는 일·리더가 비어 있다. 이미 옮긴 직원의 옛 팀 리더 자리는 비워졌다(`updateTeam` 설명).
- 대화상자는 열린 채 오류만 보이고 [만들기]가 다시 활성화돼, 다시 누르면 같은 이름의 팀이 하나 더 생긴다. 하는 일·리더는 맨 마지막 단계라 실패하면 제일 먼저 잃는다.
- 고칠 방향: main에서 한 번에 처리(`createTeam(name, color, {description, leadId, memberIds})`), 어렵다면 최소한 만든 팀 id를 기억해 재시도 시 재사용하고 실패 안내에 '팀은 만들어졌어요, 사람 바꾸기에서 이어 주세요'를 넣기.
- 같은 모양의 문제: `orgGroup.ts` `saveGroupPeople`(사람 바꾸기), `OrgDialogs.tsx`의 이름·색·일하는 곳 저장, 얼굴 메뉴의 옮기기·빼기 — 모두 오류 처리가 없어 실패하면 말없이 닫히거나 처리 안 된 오류가 된다.

### B2. 결재 기록이 모든 처리 지점에서 한 번씩만 남는가 — ③ (확인 결과)
- **중복 없음(읽어서 확인):** `decide`→`closeTextAsk`/`closeRestored`는 위임하고 바로 반환해 한 번만 남긴다. `answerQuestion`도 같다. `approveAlways`는 대상 결재마다 `decide`를 한 번씩 부른다. 자동결재(`autoDecide`)의 5개 갈래는 서로 배타적이다. 시험에서도 phone·pc·skipped 경우를 확인한다.
- **남기지 않는 곳(일관성):** `dropApproval`은 'canceled'로 남기는데 아래는 안 남긴다 — 새 지시로 카드가 철회·대체·퇴사로 닫힐 때(`closeCards`, `office.ts:1148`), 외부 직원 질문 넘기기(`decide`의 `watcher.release`), 복원 결재 만료(1825행 부근). 핸드오프가 정한 5지점은 모두 충족하므로 필수는 아니나, 사용자는 "내가 안 눌렀는데 카드가 사라졌다"를 기록에서 못 찾는다.

### B3. 걸러보기 '승인'에 자동 승인이 섞인다 — ③
- 뒷단 `db.ts` `approvalRecordsPage`는 `result='approved'`로 거르는데 자동결재·규칙 승인도 `approved`다. 줄 머리 딱지는 '자동'으로 보이므로(`approvalHistory.ts` `shownResult`) '승인' 칩에 '자동' 딱지 줄이 섞인다.
- 자동결재 시간대에는 도구를 부를 때마다 1줄이 쌓여 대표가 직접 누른 결재가 묻히고 90일치가 DB에 쌓인다.
- 고칠 방향: '승인' 걸러보기에서 `actor`가 auto/rule인 것을 빼기(`matchesApprovalFilter`도 같이), 필요하면 자동 도구 승인은 묶어서 한 줄로.

## Round 1 반영 (정리드)
- A1: 휴대폰 스트림에 원본 명령을 보내지 않는 원칙은 유지. `ApprovalTab`에서 대기 결재 수가 줄면 첫 쪽을 조용히 다시 받아 새 줄만 앞에 붙임(`mergeNewer`, 더 불러온 이전 기록 유지). PC는 기존 알림과 겹쳐도 id로 중복 없음. 한계: 휴대폰에서 카드 없이 끝나는 자동결재 줄은 탭을 다시 열 때 보임.
- A2: 탭 적용 직후 `clearStaffTab()`으로 비움.
- A3: 길이 대신 마지막 기록 id를 감시, 다시 읽지 않고 이날 범위의 새 기록만 붙임(`appendLive`). 불러오기에 요청 번호로 낡은 응답 버림, 받는 사이 들어온 기록도 합침.

- B1: 만든 팀 id를 기억해 재시도 시 재사용, 일부 실패 안내 문구 추가. (main 한 번 처리·다른 대화상자 오류 처리는 후속)

### Round 1 항목 해결 여부
- **A1 해결.** `ApprovalTab`이 대기 결재 수가 줄 때만 첫 쪽을 조용히 다시 받아 `mergeNewer`로 새 줄만 앞에 붙임. 기록은 카드 제거 알림보다 먼저 저장되므로(`recordApproval` → `patch`, office.ts:1475~1477) 건수 감소 시점엔 이미 DB에 있음. 요청 번호 확인·실패 무시·이미 더 불러온 이전 기록 유지 모두 맞음. 한계(휴대폰에서 카드 없는 자동결재 줄은 탭을 다시 열어야 보임)는 문서대로.
- **A2 해결.** 탭 적용 직후 `clearStaffTab()`.
- **A3 해결.** 마지막 기록 id 감시 + `appendLive`(이날 범위·새 id만) + `loadSeq` 요청 번호로 낡은 응답 버림, 받는 사이 들어온 기록도 합침. 시험 추가됨.
- **A4 해결.** `remoteOffice.timeline`이 `invalid_args`일 때만 시작 시각만 보내고 끝 시각 뒤를 PC 쪽이 아닌 폰에서 걸러냄. 그 밖 실패는 "불러오지 못했어요 + 다시 시도", 복사 실패도 표시.

### 이번 수정이 만든 문제 확인
- **closeCards 'canceled' 중복 없음.** 카드를 먼저 `s.approvals`에서 빼고 한 번만 기록. 이후 엔진 쪽 해제가 `dropApproval`·`decide`를 불러도 둘 다 `s.approvals`에서 카드를 찾아 처리하므로 이미 빠진 카드는 건너뜀. 연습 카드는 제외. 복원 만료(1828행)는 `closeCards`를 거치지 않는 별도 경로라 겹치지 않음.
- **ApprovalTab 조용한 재조회:** 걸러보기를 바꾸는 중이면 요청 번호로 버림(정상). 처음 불러오는 중이면 어차피 본 불러오기가 최신이라 문제 없음.

1. `ReportPage.tsx` 날짜를 넘길 때 `logs`를 비우지 않아, 응답이 오기 전 잠깐 전날 기록이 보임(어제→오늘로 갈 때는 그 사이 오늘 새 기록만 섞여 보일 수 있음). 응답이 오면 교체되므로 무해. 날짜 변경 시 `setLogs([])` 권장.
