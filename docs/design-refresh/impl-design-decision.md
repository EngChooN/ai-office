# 구현 설계 결정 — 모바일 1안 · 장비·프로필 카드형 (정리드, 2026-11-12)

비교한 안: `impl-design-choi.md`(최가독) · `impl-design-park.md`(박패턴)

## A. 모바일(폭 600 미만) 헤더·입력창 축소형
**채택: 박패턴의 분기 구조 + 최가독의 재사용 범위**
- 분기: `decideLayout`에 `isSlim`(폰 배치·세로·폭 600 미만, 분할·가로 폰 아님) → `<html data-slim>` → CSS 변형 `slim:` 하나. (박패턴)
  - 이유: 폴드(`data-split`)·데스크톱에는 속성 자체가 안 붙어 "안 바뀐다"가 구조로 보장되고, 판정을 순수 함수 표 시험으로 고정할 수 있다.
  - 최가독의 CSS 선택자만으로 만드는 `slim`(`[data-layout=phone]:not([data-split]):not([data-short])`)은 더 짧지만, 판정이 CSS에 숨어 시험·재사용이 어렵다 → 채택하지 않음.
- 새 요소는 표시용만 두 벌(`hidden slim:flex` / `slim:hidden`), 입력칸·메시지 목록은 한 벌. 고정 높이 대신 `min-h-`(글꼴 크게 대비). (박패턴)
- 방 목록·구성원·메뉴는 기존 `chatRoomHooks`·`PopMenu` 재사용, 새 부품은 한 줄 머리와 결재 띠 둘. (두 안 공통)
- 결재 띠의 한 줄 승인: **맨 앞 1건이고, 질문·다른 PC 변경 묶음·대기 사유(위험) 표시가 없을 때만**. 그 밖은 "보기"만. 순수 함수로 시험. (박패턴)
  - 이유: 한 줄에서 원문을 못 보고 위험한 건을 승인하는 일을 막는다.

## B. 장비·프로필 카드형
**채택: 최가독·박패턴 공통의 `levelOf`/`withLevel` 순수 함수(`shared/toolPolicyRows.ts`) + 박패턴의 파일 카드 안(나)**
- 3칸 [막기·결재 받기·결재 없이]은 기존 묶음을 행 단위로 감싼 순수 함수. 일부만 있거나 둘 다 있는 옛 값은 "직접 고름"으로 보이고, 칸을 누를 때만 정리한다. 저장 데이터·IPC 불변.
- **파일 수정 카드 = 2칸 [결재 받기 · 어디서든 결재 없이] + 프로필 결재 방식 상태 한 줄 안내.**
  - 확인 결과 `approvalMode`는 **고용·정식 채용 때만 정해지고 고용 뒤 바꾸는 경로가 없다**(프로필은 표시만, 원격도 막음). 최가독의 3칸(작업 폴더 안 = acceptEdits)은 새 IPC와 세션 재시작 처리가 필요한 새 기능이라 이번 범위를 넘는다 → 채택하지 않음.
  - 두 효과가 다르다는 점(acceptEdits = 작업 폴더 안·위험 경로는 물음, 장비 = 경로 무관·위험 경로도 안 물음)은 카드 안내 문구로 보여 준다. 실제로 장비 허용은 위험 경로 가드(PreToolUse 'ask')가 canUseTool 허용으로 통과되므로 '어디서든' 칸에 경고를 붙인다.
- 프로필 결재 방식 문구는 범위를 넣어 "작업 폴더 안 파일 수정은 결재 없이". (박패턴)
- 프로그램 실행이 '막기'면 '보기만 하는 실행' 행은 비활성 + 이유 한 줄. (박패턴)
- 카드 컴포넌트는 `features/` 안 한 곳에서만 쓰므로 `ui/`로 올리지 않는다.

## 대표 확인이 필요할 수 있는 것
- 고용 뒤 결재 방식(작업 폴더 안 자동)을 바꿀 수 있게 하는 기능은 새 기능이라 이번에 넣지 않았다. 원하시면 별도 업무로.
