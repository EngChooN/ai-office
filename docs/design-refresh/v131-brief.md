대표가 고른 두 시안을 1.3.1에 넣습니다. 푸시·배포 없음. 구현은 정리드가 직접 합니다. 설계자는 **각자 관점으로 따로** 설계안을 냅니다(서로 맞추지 않음).

## 1. 단체방 상단 = B안 '왼쪽 방 목록' (+ 자동 접힘)
- 시안: `docs/design-refresh/chat-header/chat-header.html`, `chat-header-b-light.png`·`chat-header-b-dark.png`
- 지금 4줄(제목·설명·방/팀/랩 칩 줄·직원 칩 줄) → 방 목록은 왼쪽 세로 칸, 상단은 방 이름(+팀/랩 꼬리표, ⓘ, 🔍) + 직원 줄('N명 · M명 일하는 중' + 일하는 사람 칩, 넘치면 +N).
- 시안 최종 추천: 대화 폭이 640px 아래면 방 목록을 56px 띠(머리 글자 아이콘·안 읽은 수 배지·결재 대기 점, ≡로 겹쳐 펼침, 📌 고정)로 자동 접기. 앱 사이드바 접기는 범위 밖.
- 유지 필수: 방 전환, 팀/랩 필터(묶음 제목 전체·팀·랩), 안 읽음 숫자, 대화 찾기(검색), 기존 접힘 상태, 회의실 진입, 폴드 와이드 분할에서 쓰던 ChatSide.
- 확인: 라이트·다크, 좁은 창(900·1100·1400), 직원 패널 열림.
- 관련 코드: `app/src/renderer/features/ChatPage.tsx`, `ChatSide.tsx`, `ChatSlimBar.tsx`, `chatRoomHooks.ts`

## 2. 휴대폰 연결 = 1안 '단계형'
- 시안: `docs/design-refresh/connect/connect.html`(1안 탭), `cn-a.png`, 인계 `connect-handoff.md`
- 설정 제목 '휴대폰·PC 연결' 하나. 세로 3단계: ① 어디서 쓰실 건가요?(같은 와이파이 / 밖에서도(추천, Tailscale) / 고급: 공유기 직접) ② 준비물 자동 확인(지금 3초 Tailscale 상태를 체크 표시로) ③ 무엇을 연결할까요? [휴대폰 | 내 다른 PC] → QR + 아래에 '코드로 연결' 코드(복사).
- 끝나면: '연결 켜짐 · …' 한 줄 + [끄기], '연결된 기기 N대' 목록, [+ 기기 추가], '고급 설정'(포트·공유기·지문·최근 접속) 접이식, '휴대폰 모두 끊기(새 QR)' 빨간 접이식.
- 용어: '원격'→'연결', 'QR을 못 찍을 때 코드' = '코드로 연결', '직원 보내는/불러오는 PC' → '이 PC 직원 빌려주기 / 다른 PC 직원 데려오기'. 4개 언어(ko·en·ja·zh) 같은 뜻.
- 관련 코드: `app/src/renderer/features/RemoteSection.tsx`, `PeerSection.tsx`, `SettingsPage.tsx`, `app/src/shared/i18n/dict/featuresB.ts`·`peer.ts`, `app/src/main/remote/service.ts`·`auth.ts`

### 정리드가 코드로 확인한 사실 (설계에 반영)
- 신규 기본 연결 방식은 이미 Tailscale(=밖에서도, 추천) — `service.ts:132`. 1안은 기본을 바꿀 필요 없음, 그대로 둠.
- 휴대폰 열쇠는 하나(`tokenHash`). QR은 첫 휴대폰이 붙으면 거둬짐(`isQrReady=false`) → 두 번째 휴대폰은 새 QR(rotate)이 필요하고 그때 첫 휴대폰은 끊김. 시안의 '휴대폰 모두 끊기(새 QR)' 표기가 맞음. 휴대폰 '기기 추가'는 이미 연결된 휴대폰이 있으면 "새 휴대폰을 연결하면 지금 휴대폰이 끊겨요" 안내가 필요.
- 기기 목록 정보: 다른 PC(피어 슬롯)는 이름·만든 시각·`lastSeenAt` 저장됨. 휴대폰은 마지막 접속 시각이 저장되지 않음(최근 접속 기록 `recentAccess`는 메모리·기기 구분 없음). '결재 2건 처리' 같은 횟수는 어디에도 없음 → 쓰지 않음. 휴대폰 마지막 접속 시각은 `AuthGuard`에 작게 추가할지 설계에서 판단.

## 설계안에 담을 것 (각 1~2쪽)
1. 컴포넌트 나누기(새 파일/기존 파일 수정), 상태 위치, 기존 함수·훅 재활용
2. 바뀌는 사전 키 목록 방향(새 키 vs 기존 키 문구 수정)
3. 자동 접힘 기준을 어떻게 재는지(창 폭 vs 대화 칸 실제 폭)
4. 위험한 지점과 검증 방법(시험 추가 여부, 타입 검사)
5. 구현 순서(같은 파일 충돌 없게)
