# 워크스페이스(다른 PC 화면 그대로 보기, PC 최대 3대) — 현재 구조로 가능한가

정리드 · 2026-11-12 · 코드 수정 없이 조사만

## 결론
**구조상 가능합니다.** 휴대폰 앱이 이미 "PC 화면을 원격으로 띄우는" 방식이라, 데스크톱에도 같은 방식을 붙일 수 있습니다. 다만 아래 두 가지가 설계를 가장 크게 묶습니다.
- PC 한 대의 휴대폰 연결 열쇠가 **1개뿐**입니다.
- 원격에서는 **PC 전용 기능이 막힙니다**.

## 시안에 영향을 주는 제약 (먼저 보세요)
1. **PC 한 대 = 휴대폰 공용 열쇠 1개.** 'QR 다시 만들기'를 누르면 그 PC에 붙은 휴대폰이 모두 끊깁니다. 그래서 "기기별 연결 해제"나 "지금 누가 붙어 있나" 목록은 **지금 구조로는 못 만듭니다**. 만들려면 열쇠 구조를 바꿔야 합니다(아래 ③).
2. **원격 화면에서 막히는 것**(지금 휴대폰과 같음)
   - 폴더·파일 고르기(경로 직접 입력으로 대체)
   - 휴대폰 연결 설정·QR·다른 PC 연결, 로그인, 연결된 서비스 직접 편집, 되돌리기
   - 바탕화면 비서, 화면 모드·색 테마, 직원 화면 찍기 허용
3. **원격에서 정할 수 없는 값**: 작업 폴더, 결재 방식(새 직원은 늘 '모두 결재'), 장비의 허용·금지 도구, 명령 실행 중 인터넷. 자동결재는 12시간 이하만 켤 수 있고 완전 자율은 안 됩니다.
4. 원격 응답에는 **비용·토큰이 빠집니다** → 원격 PC 화면의 비용 칸은 비워 두는 디자인이 필요합니다.
5. 결재·알림은 **PC마다 따로** 옵니다 → 모든 결재·알림에 **어느 PC인지 표시**가 필수입니다.
6. 원격 연결은 PC마다 기본으로 꺼져 있고, 연결 방식(같은 와이파이·밖에서·Tailscale)도 PC마다 다릅니다 → PC별 "연결 안 됨 이유" 상태 화면이 필요합니다.

## ① 휴대폰 앱의 원격 연결 구조와 '열쇠 하나' 제약
- 통신: 자체 인증서 HTTPS(인증서 지문 고정) + 열쇠(Bearer). `POST /v2/call`로 사무실 기능 전체를 부르고, `GET /v2/events`로 실시간 소식을 받습니다(`docs/specs/remote-protocol-v1.md`, `remote-protocol-v2.md`).
- 짝짓기는 QR, 또는 주소 + 12자리 코드입니다. 코드로 받아도 결국 **QR과 같은 공용 열쇠**를 받습니다(`app/src/main/remote/service.ts:197-200`).
- PC는 지금 쓰는 열쇠 1개(해시)와 폐기 목록만 보관합니다(`remote/auth.ts:68-74`). 다시 만들면 휴대폰만 모두 끊고, 다른 PC 연결은 그대로 둡니다(`service.ts:416-425`).
- 안드로이드는 연결 정보를 **한 칸**에 암호화해 저장합니다(`SecureStore.kt:23-24`). 앱 상태값과 백그라운드 확인(PollWorker)도 모두 연결 하나 기준입니다.
- 화면은 **APK에 들어 있는 모바일 빌드**입니다. PC가 화면을 내려주지 않습니다. `window.office`는 `mobile/remoteOffice.ts`가 대신하고, 흐름은 화면 → 브리지 → Kotlin → HTTPS → PC입니다(`WebShell.kt`, `mobile/install.ts:11-31`).
- **휴대폰에서 PC 3대(규모: 중간)**
  - 할 일: 저장 한 칸을 PC 목록으로 바꾸기, PC별 상태값 나누기, PC별 통신·소식 연결, 백그라운드 확인이 3대를 돌게 하기, PC를 바꿀 때 화면 다시 불러오기, 알림에 PC 이름 붙이기.
  - PC 서버와 프로토콜은 그대로 씁니다.

## ② 데스크톱이 다른 PC의 앱을 그대로 보여 주려면 (규모: 중~대)
- `remoteOffice.ts`는 브리지 하나만 있으면 `window.office` 전체를 원격으로 잇습니다. 그래서 **화면 코드는 그대로 다시 쓸 수 있습니다**.
- 할 일
  - 데스크톱 메인 프로세스에 브리지를 새로 만듭니다. 안드로이드 WebShell이 하는 일을 Node로 옮기는 일이고, 다른 PC 연결의 인증서 지문 고정 통신을 재사용합니다. **규모: 중간**
  - PC마다 창(또는 화면 영역)을 따로 띄웁니다. 화면 상태 저장소가 앱 전체에 하나라서 창을 나누는 편이 쉽습니다. **규모: 중간**
  - 열쇠: 다른 PC 연결용 열쇠로는 `/v2/call`을 부를 수 없습니다(`remote/handler.ts:106`). 그래서 휴대폰 공용 열쇠를 같이 쓰거나 새 '보기용' 열쇠 칸을 만들어야 합니다. **규모: 중간, 보안 리뷰 필요**
- 원격에서 안 되는 기능은 `remote/v2.ts:56-135`의 PC 전용 목록, 빠지는 값은 `v2.ts:245-276`에 있습니다.

## ③ PC 3대 동시 연결 때 결재·알림·보안 문제
- **결재·알림**
  - 각 PC의 결재는 그 PC의 실시간 소식으로만 옵니다.
  - 메뉴 막대 아이콘, 바탕화면 비서, 숫자 배지는 지금 **내 PC 것만** 셉니다. 3대를 합쳐 보이려면 새로 만들어야 합니다.
  - 같은 결재를 두 기기가 동시에 누르면 뒤에 누른 쪽은 '이미 처리됨'으로 막힙니다. 이 경우 안내 문구가 필요합니다.
- **권한**
  - 연결 열쇠를 가진 기기는 그 PC에서 **결재를 전부 처리할 수 있습니다**. 직원 고용, 지시, 커밋·PR 올리기도 됩니다. 단, 명령을 '항상 허용'하는 것과 자율 진행은 막혀 있습니다.
  - 기기별로 끊을 수 없어서, 열쇠 하나가 새면 다시 만들어야 하고 그러면 모두 끊깁니다.
  - → PC 3대를 오가는 구조라면 **기기별 열쇠**로 바꾸는 것을 권합니다. 다른 PC 연결용 칸(최대 8개, 하나씩 끊기 가능)에 '화면 보기' 권한을 더하는 방식이 가장 짧은 길입니다.
- **⚠ 발견한 보안 구멍 (확인 필요)**: 원격에서 설정의 '기본 작업 폴더'(`defaultCwd`)를 바꿀 수 있습니다(`v2.ts:276`). 원격 고용은 이 값을 작업 폴더로 씁니다. 그래서 "원격은 작업 폴더를 정할 수 없다"는 원칙이 우회됩니다. 워크스페이스와 상관없이 고칠 거리입니다.
- **연결**
  - Tailscale 방식은 Tailscale 주소에서 온 연결만, 같은 와이파이 방식은 바깥 연결을 막습니다. 그래서 PC마다 "같은 와이파이 → 밖에서" 순서로 붙어 보는 처리가 필요합니다.
  - 한 곳에서 동시에 열 수 있는 연결은 8개라 3대여도 충분합니다.

## ④ 기존 '직원 빌려주기·데려오기'는 어떻게
- **지금 방식**: B PC가 12자리 코드를 보여 주고 A PC가 입력하면 다른 PC 전용 열쇠 칸이 생깁니다. 그러면 B의 직원이 A 사무실에 원격 직원으로 앉고, 그 직원의 결재도 A 결재함으로 옵니다. 맡긴 일에서는 자동결재가 꺼집니다.
- **성격이 다릅니다**: 데려오기는 "직원 단위로 섞기", 워크스페이스는 "PC 화면을 통째로 보기"입니다.
- **권장**
  - 짝짓기(12자리 코드)와 열쇠 칸은 **하나로 합칩니다**. 이렇게 하면 기기별 열쇠 문제도 함께 풀립니다.
  - 화면은 "연결된 PC" 목록 하나에서 PC마다 **[화면 보기] · [직원 데려오기]**를 고르게 합니다.
  - 데려오기 기능은 당장 남겨 두고, 쓰임새를 보고 나중에 정리합니다.
  - **충돌 지점**: 같은 PC의 결재가 데려오기 결재 중계와 워크스페이스 양쪽에 두 번 뜰 수 있습니다. 하나로 묶는 규칙이 필요합니다.
