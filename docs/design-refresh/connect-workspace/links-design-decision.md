# 진짜 links 부품 최종 설계 결정 (정리드, 2026-11-17)

근거: `links-design-readable.md`(최가독), `links-design-pattern.md`(박패턴). 두 안은 서로 맞추지 않은 독립안이다.

## 결론
**연결 줄은 최가독 안(PeerManager 줄 함께 쓰기), 판단 규칙·실패 분류·인터페이스는 박패턴 안.**
허락 경로(저쪽 PC 허락 화면)는 두 사람 모두 "없으면 실제 시험이 멈춘다"고 짚어 이번 작업에 넣었다.

## 쟁점별 결정

| 쟁점 | 채택 | 이유 |
|---|---|---|
| 실시간 줄 | PC당 1줄, PeerManager 줄을 함께 씀 (최가독) | 허락된 열쇠는 그 줄로 이미 휴대폰과 같은 이벤트를 받는다. 화면용 줄을 따로 열면 같은 스냅샷을 두 번 받고, 열쇠당 2줄 한도에 딱 붙는다. 허락이 바뀌면 서버가 줄을 닫고 PeerClient가 다시 붙으므로 따로 줄 수명을 관리할 필요가 없다 |
| 판단 분리 | `linkModel.ts`(순수) + `workspaceLinks.ts`(연결·타이머·요청) (박패턴) | hello 변환·실패 분류를 표 시험으로 못박을 수 있다 |
| PeerManager 덧붙임 | `watch`(상태·이벤트 구독) + `http` 공개. 기존 흐름 무수정 | 두 안의 공통분모. 구독이 없으면 이전과 같다 |
| 프로토콜 기준 | 3 → **2**, 화면 보기를 아는지는 hello의 `permissions`로 가림 (박패턴) | 서버는 2를 준다. 번호를 올리면 휴대폰까지 번진다 |
| 426 | `selfOutdated`(이 PC 업데이트)로 분리, `http_426`을 다시 짝짓기에서 뺌 (박패턴) | 다시 짝지을 일이 아니다. 줄이 unpaired가 되면 hello로 사유를 가린다 |
| 무한 "연결하는 중" | hello 10초 시간 초과 → `unreachable`=끊김 + 다시 시도, 끊김 8초 시계 타이머 (두 안 공통) | 기다리는 단계마다 끝이 있다. 실패 8종을 시험으로 확인 |
| 허락 요청 | 추가할 때·'다시 요청' 때만 `requestView:true` (박패턴) | 거절 뒤 저쪽에 카드가 계속 뜨지 않게 |
| 저쪽 PC 허락 입구 | ① '다른 PC에서 이 PC를 보게 하기' 코드를 `view` 종류로 연다(그 PC 앞에서 코드를 연 것이 허락) ② 예전 짝은 요청 시 이 PC에 허락·거절 창(시스템 대화상자)을 띄운다 | 새 메서드·설정 화면 버튼(박패턴 제안)은 휴대폰 분류표까지 번진다. 대화상자는 main 한 곳만 바뀐다 |
| `WorkspaceLinks` 인터페이스 | `listen`(changed·message) · `ready` · `requestGrant` 추가 (박패턴의 onChange·onEvent·retryGrant를 하나로) | 상태가 바뀌면 목록·창에 알리는 길이 필요 |
| 올리기 | `postBytes`(POST) 추가 (박패턴) | 서버 `/v2/attachments`는 POST |
| 급한 패치의 '준비 중' | 이번에 제거 | 진짜 부품이 붙어 필요 없다. 되돌리기는 조립부 한 줄 |

## 채택하지 않은 주요 제안
- **화면용 줄을 PC당 따로 열기(박패턴):** 허락된 열쇠의 상태 줄도 같은 이벤트를 받으므로 같은 내용을 두 번 받는다. 박패턴이 짚은 "허락 전 2줄이 서로 밀어냄"은 줄을 하나만 쓰면 생기지 않는다.
- **설정 목록의 허락·거절 버튼 + 새 메서드(박패턴):** 이번 범위에서는 대화상자로 충분하다. 회수는 기존 '연결 해제'로 한다. 필요하면 다음에 붙인다.
- **hello 5초(최가독):** 느린 회선(Tailscale 중계)을 생각해 10초로 했다.

## 남은 것
- 실제 두 PC(맥·윈도우) 시험은 아직이다.
- 저쪽 PC 앱이 꺼졌다 켜지면 허락 대기가 사라져 '거절'로 보인다 → '다시 요청' 버튼으로 다시 묻는다.
