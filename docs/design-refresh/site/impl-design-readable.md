# 소개 사이트 개편 안 3 — 구현 설계 (최가독 · 가독성·단순함·재활용)

기준: `handoff-plan3.md`, 지금 `site/index.html`(1,368줄)·`build-langs.mjs`·`check-i18n.mjs`·`assets/screens/README.md`. 코드는 고치지 않았고, 이 문서는 설계안입니다. 아래 "확인 못 함"은 직접 못 본 부분입니다.

## 1. 고쳐 쓰기 vs 새로 짜기 → **고쳐 쓰기(본문만 교체)**
- 이유: 머리·메타·JSON-LD, 테마/언어 전환, 내 기기 감지·다운로드 버튼(`DOWNLOADS`·`dlButton`), 스크롤 등장(`.rv`)·확대(`#zoom`), 사진 모드 전환(`setShot`), 움직임 줄이기 규칙은 이미 동작하고 `build-langs`가 그 모양에 기대고 있음(`var D = DOWNLOADS, LANGS`, `version: '…'`, `<!--p-->`). 통째로 새로 짜면 이 연결이 깨질 위험만 큼.
- **남길 것**: `<head>` 전체, CSS 변수(색·글꼴), 테마·언어·OS 감지·다운로드·`.rv`·확대·`setShot` 스크립트, 꼬리의 버전·라이선스.
- **지울 것(칸)**: `how` `new` `secretary` `trust` `look`(견본칩·레트로) `screens` `limits` `faq`, BETA 표시·"지금은 베타" 문구. 안 3 순서(머리줄·체험·꾸미기·기능 7·다운로드·꼬리)에 없어서 지움. ※ `limits`·`faq`는 문서에 명시가 없어 지우는 쪽으로 읽었음 — 정리드 확인 요망.
- **지울 것(사전 키)**: 지운 칸의 키 전부. `check-i18n`이 "안 쓰는 키"를 오류로 잡으므로 4개 언어에서 함께 지워야 통과.
- **새로 넣을 것**: 시안 `#p3` 마크업·CSS 중 안 3에 쓰는 것만(`.demo` `.presets` `.lv` `.feat`). 안 1·2용 CSS는 가져오지 않음. 체험 스크립트는 시안 `play/drawStaff` 약 30줄을 거의 그대로 사용.

## 2. 4개 언어 데이터 구조
- 한 곳 원칙: **글은 전부 `I18N` 사전, 순서·종류(말풍선/상태 변경/카드)는 언어와 무관한 뼈대**.
  - `SCRIPTS = { a: [['me'],['st','dz','got'],['say','dz'],['appr','dz'],…] }` — 글 없음. 글이 필요한 단계(`me/say/sys/appr/plan`)는 나온 순서대로 `I18N[l]['demo.a']`(문자열 배열)의 n번째를 씀.
  - 직원 이름 4개 `demo.staff`(배열), 상태 이름 `demo.st.*`, 결재 카드 라벨 키, 레벨 이름 `lv.names`(배열 7), 열리는 것 `lv.unlock.*`.
  - 예시 버튼 라벨은 일반 `data-i18n` 키(`demo.p.a` 등). `@디자인팀` 같은 멘션은 키 값 안의 `<span class="mention">`(innerHTML 이미 사용 중).
- `build-langs` 관계: 이 스크립트는 **비어 있는 `data-i18n` 요소만** 정적으로 채움 → 제목·설명·버튼 라벨·레벨 기본값(Lv.7 이름/열리는 것)·기능 7줄·다운로드는 JS 없이도 4개 언어 정적 본문에 들어감. 체험 채팅 내용은 JS가 그림(검색엔진용 글은 설명 문장이 맡음). 버튼 안에 자식 요소가 있으면 채워지지 않으므로 **라벨을 `<span data-i18n></span>` 하나씩 따로** 둘 것.
- `check-i18n` 보강(작게): ① 배열 키는 길이가 ko와 같아야 함 ② 각 대본의 글 단계 수 = 배열 길이 ③ 지워야 할 낱말(`BETA`, `1.4.`) 본문 검색. `build-langs`의 `SHOTS`(JSON-LD 스크린샷)는 새 파일 이름으로 갱신.

## 3. 캡처 그림 → **미리 잘라 둔 파일**
- 이유: CSS 자르기는 2800px 원본(약 330KB)을 작은 칸에 통째로 받고 폭마다 비율 계산이 달라져 깨지기 쉬움. 미리 자르면 가볍고 `<img>` 하나로 끝남. 단점(다시 찍으면 다시 잘라야 함)은 자르기 표(핸드오프의 비율 4줄)를 **스크립트 하나(`site/scripts/crop-shots.mjs`, 도구는 정리드 판단)** 에 두어 막음.
- 이름·폴더(기존 규칙 그대로 확장): `assets/screens/<ko|en|ja|zh>/feat-chat.webp`, `feat-inbox`, `feat-secretary`, `feat-board`, `feat-ai`(06), `feat-dash`(08) + 각각 `-dark`. 07은 기존 `phone-chat(-dark)` 재사용. 16:10 비율, 1배 폭 약 720.
- 건물 7장은 언어 무관 → `assets/screens/common/lv1.webp … lv7.webp`(+`-dark`는 앱 외관이 모드에 따라 달라질 때만). `check-i18n`의 사진 검사에 "common 폴더" 한 줄 예외 추가.
- 안 쓰게 되는 기존 파일(office·staff-mix·theme·retro·phone-secretary·phone-inbox)은 검사가 참조 파일만 보므로 두어도 오류 없음 → 마지막에 정리.
- **캡처 방법(건물 7·06·08)**: 앱을 `AI_OFFICE_USER_DATA=<임시폴더>`로 따로 띄우고 CDP 9447로 화면 조작. 가상 직원·가상 업무만 넣고(실데이터 금지), 앱 언어를 4개로 바꿔 06·08은 언어별로 찍음. 건물은 레벨 1·3·6·10·14·18·20을 대표값으로. **확인 못 함**: 임시 데이터에서 레벨을 어떻게 올리는지(씨앗 파일인지 조작인지) — `docs/specs/office-iso-levels.md`를 구현자가 먼저 확인할 것. 실패하면 개발용 `exterior-N.png` 임시 유지, 06·08은 시안의 HTML 흉내 유지(기능 줄은 그림만 바뀌므로 분리 가능).

## 4. 움직임 줄이기·접근성
- `prefers-reduced-motion`: 체험은 **자동 재생·시간차 없이 선택한 대본의 끝 상태를 즉시 표시**(타이머 미사용). 기본 `.rv` 규칙은 이미 있음. 레벨 막대 전환 애니메이션도 끔.
- 체험 창: 머리에 "체험용 화면 · AI 사용 없음" 글자 필수. 채팅 영역은 `aria-live="off"`(자동 낭독이 길어짐), 예시 버튼은 `<button aria-pressed>`, 키보드로 모두 조작. 재생은 약 10초 후 스스로 끝나고 클릭 때만 다시 시작.
- 레벨 막대는 `<input type="range">` + `aria-valuetext`("Lv.7 · 벽돌 건물") + 7단계 버튼(키보드·터치 대체).
- 그림 `alt`는 `data-i18n-alt`, 포커스 표시 유지, 휴대폰 메뉴는 가로 스크롤(숨기지 않음), 라이트·다크 대비 4.5:1 확인.

## 5. 검증
- `node site/build-langs.mjs` → `node site/check-i18n.mjs` 통과(보강 항목 포함). `/en/ /ja/ /zh/` 정적 본문에 해당 언어 제목·버튼이 JS 없이 들어갔는지 grep.
- 화면 캡처 16장: 언어 4 × 모드 2 × PC 1280·휴대폰 390 전체 페이지. 추가로 폭 700/701 경계 2장, 움직임 줄이기 켠 체험 1장.
- 자동 확인(스크립트 한 번): 폭마다 가로 넘침 없음(`scrollWidth ≤ innerWidth`), 콘솔 오류 0, 이미지 404 0, 대본 4개 × 언어 4개 재생 후 마지막 카드 존재, 언어·모드 전환 중 재생 정리.
- 눈으로 볼 것: 영어·일본어의 긴 예시 버튼 줄바꿈, 레벨 20 캠퍼스 그림 잘림.

## 6. 위험·주의
1. `build-langs`의 `sub()`는 패턴이 없으면 예외 → 위 연결 문구(`var D = DOWNLOADS, LANGS`, `version: '…'`, I18N 끝 `\n});\n`)를 건드리지 말 것.
2. 한국어 `index.html`은 `build-langs`가 다시 써 줌(`<!--p-->` 표시) — 빌드 뒤 diff가 커 보이는 것은 정상.
3. 번역 4개 언어 문구(대본 4×약 8줄, 레벨 7, 기능 7줄)는 번역 담당 필요. 기능 문구는 CONTEXT·SPEC에 있는 것만 쓸 것("문서에 없는 기능 금지").
4. 건물·06·08 실캡처가 가장 큰 일정 변수. 기능 줄과 분리해 그림 교체만 나중에 해도 페이지가 완성되게 둘 것.
5. 사전의 `@멘션`·카드 HTML이 `innerHTML`로 들어가므로 키 값은 우리 글만(외부 입력 금지).
6. 지금 JSON-LD의 `?v=1.4.1`처럼 버전이 박힌 곳이 남았는지 검색(새 소식 1.4.x 제거 기준).
