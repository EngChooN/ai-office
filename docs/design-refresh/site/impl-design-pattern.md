## 1. 고쳐 쓰기 vs 새로 짜기

**추천: 같은 `index.html`을 고쳐 쓴다. 단, 본문 칸(hero~final)은 새로 쓰고 "틀"은 그대로 둔다.**

- 이유: build-langs·check-i18n이 index.html의 모양(`var I18N = {…\n};\n`, `data-i18n`, `data-shot`, `<!--p-->`, `PAGE_LANG` 끼움 자리, `assets/` 경로 규칙)에 직접 기대고 있습니다. 파일을 새로 짜면 이 약속이 조용히 깨지고 en/ja/zh 페이지가 틀어집니다. 틀을 두면 두 스크립트는 거의 수정 없이 돕니다.
- **남길 것(수정 금지)**: head·메타·JSON-LD, 화면 색 즉시 적용 스크립트, `DOWNLOADS`, 언어 고르기·`pickLang`, `render()`의 data-i18n/alt/version 채우기, `setShot`/`shotPath`(라이트·다크 사진 선택), 내 기기 감지·`dlButton`, 최신 버전 조회(`showVersion`), 확대 보기(`openZoom`), 스크롤 나타나기(`.rv`), 테마 토글.
- **지울 것(칸)**: 옛 hero, `#how`, `#new`(새 소식), `#secretary`, `#trust`, `#look`, `#screens`, BETA 표시·"지금은 베타" 문구. 사전에서는 이 칸 전용 키(`s1~s3.*`, `new.*`, `sec.*`, `trust.*`, `look.*`, `cap.*`, `alt.*` 중 옛 것, `beta.*`)를 같은 커밋에서 같이 삭제 — 그래야 check-i18n의 "안 쓰는 키" 검사가 깨끗합니다.
- **정할 것(정리드)**: 옛 `#limits`(한계 안내)·`#faq`는 안 3 순서표에 없습니다. 문서에 없는 칸을 넣지 않는다는 기준대로면 삭제지만, 한계 안내가 사라지면 오해 방지가 줄어듭니다. 추천: 순서표대로 삭제하되 꼬리 위에 한 줄 안내만 남길지 정리드가 판단. (대표 미확인)
- **CSS**: 옛 칸 전용 규칙은 칸과 함께 지우고, 새 칸 규칙은 `/* ── 체험 ── */` 같은 구간 주석으로 묶어 칸별로 한 덩어리씩 둡니다. 시안 CSS(1~550줄)를 통째로 붙이지 말고, 사이트의 기존 변수(`--accent` 등)에 매핑해 변수 이름이 둘로 갈라지지 않게 합니다. 기준 폭은 700px 하나만 씁니다.
- **JS 분리 이득**: 체험 코드는 index.html 안의 별도 `<script>` 블록 하나(`/* 체험 */`)로 두고, 사전·테마·다운로드 코드와 서로 호출하지 않습니다. 접점은 둘뿐: `render(lang)` 끝에서 `Exp.setLang(lang)` 호출, 테마 변경 때 건물 그림 갱신. 파일을 따로 빼는 것(외부 .js)은 추천하지 않습니다 — 이 사이트는 단일 HTML 배포이고 build-langs가 인라인 `var I18N`을 읽으므로 외부 파일은 이득보다 경로 복잡도(`../`)만 늘립니다.

## 2. 4개 언어 데이터 구조

**원칙: 말(문구)은 전부 I18N 사전, 흐름(누가·언제·무슨 종류)은 언어와 무관한 뼈대 한 벌.**

- 뼈대(`EXP_FLOW`, 코드 안 상수): 대본 a~d별로 `[종류, 직원, 상태 또는 문구키]` 배열. 시안 SCRIPTS에서 문장만 빼고 종류·순서·상태만 남긴 것입니다. 문장은 키로만 가리킵니다 (예: `['say','dz','exp.a.2']`).
- 사전 키 규칙(점 표기, 기존 `s1.t` 방식과 동일):
  - `exp.<대본>.<순번>` 대화·카드 문구(`<span class="mention">` 포함 HTML 허용 — 기존 사전도 innerHTML 사용)
  - `exp.staff.<id>` 직원 이름 4개, `exp.st.<상태>` 상태 5종, `exp.tag.*` 결재/기획 확인 같은 카드 꼬리표, `exp.badge`(체험용 화면 · AI 사용 없음), `exp.preset.<a~d>`·`exp.preset.<a~d>.sub`(버튼 글과 "팀에게" 등)
  - `lv.name.1..7`, `lv.unl.<휴게|강당|대표실>`, `lv.note`
- **build-langs 관계**: 이 스크립트는 "비어 있는 `data-i18n` 요소"만 정적으로 채웁니다. 체험은 JS가 그리므로 정적 본문에 자동으로 안 들어갑니다. 따라서 **JS 없이도 보여야 하는 것만 정적 요소로 둡니다**: 제목·설명·예시 버튼 4개(`data-i18n`)·"체험용 화면" 배지·레벨 칸의 처음 값(Lv.7 이름·열리는 것)·기능 7줄 글. 대화 창 안은 비워 두거나, 첫 번째 대본의 첫 말풍선 1개만 정적으로 둡니다(검색엔진·JS 꺼짐 대비, 추정: 필수는 아님).
- 레벨 이름은 7개 단계의 이름만 사전에 두고, 레벨→단계 매핑(1~2, 3~5, 6~9, 10~13, 14~17, 18~19, 20)은 코드 상수 한 곳(`LV_STAGES`)에 둡니다. 숫자 경계가 문서(`office-iso-levels.md`)와 한 곳에서만 맞으면 됩니다.
- **check-i18n 보강(작게 2가지)**:
  1. "안 쓰는 키" 예외 정규식에 `^(exp\.|lv\.)`를 추가 — 동적으로 쓰는 키는 `data-i18n` 속성에서 안 보이기 때문입니다.
  2. 대신 빈틈을 막는 검사를 추가: `EXP_FLOW`와 `LV_STAGES`가 가리키는 키가 4개 언어 모두에 있는지. (index.html에서 `EXP_FLOW`를 I18N처럼 vm으로 읽어 오려면 한 줄 표식 `/*EXP*/…/*EXP-END*/`가 필요.) 이게 없으면 번역 하나만 빠져도 체험 도중 `undefined`가 화면에 찍힙니다.
- 번역 수량: 대본 4개 × 약 6~9줄 + 레벨 7 + 기타 ≈ 70키 × 3언어. 길이는 ko보다 en·ja가 길어 말풍선·버튼이 넘칠 수 있으니 시험에서 확인합니다.

## 3. 캡처 그림

**추천: 미리 잘라 둔 파일을 쓴다(CSS 자르기 안 함).**
- 이유: CSS로 자르면 2800×1770 원본(약 300KB)을 칸 하나 보여 주려고 통째로 받습니다. 4개 언어×라이트·다크로 7줄이면 낭비가 큽니다. 잘라 둔 파일은 칸 크기만 받고, `<img>` 크기 고정으로 화면 밀림도 없습니다. 비용: 파일이 늘고 캡처가 바뀌면 다시 잘라야 함 → **자르는 방법을 스크립트 한 파일로 남겨** 재현 가능하게 합니다.
- 규칙(기존 `screens/` 규칙에 그대로 얹음 — `setShot`·check-i18n 수정 없이 동작):
  - 위치·이름: `assets/screens/<ko|en|ja|zh>/feat-<이름>.webp` + `feat-<이름>-dark.webp`. 이름: `feat-approve`(03), `feat-plan`(04), `feat-secretary`(05), `feat-ai`(06), `feat-dash`(08), `feat-board`(09). 07은 기존 `phone-chat` 재사용(새 파일 없음).
  - 마크업은 `<img data-shot="feat-approve" …>` 하나로, 라이트·다크·언어 폴백이 기존 로직을 그대로 탑니다.
  - 크기: 비율 16:10, 1x 약 760×475에 2x 파일(1520×950), 장당 120KB 이하(기존 330KB 한도 안).
- **자르기**: 원본은 이미 있는 PC 캡처(2800×1770, 4개 언어). 핸드오프 비율(왼쪽·위·오른쪽)로 `x=left×2800, w=(right−left)×2800, h=w×0.625`. `dwebp`로 PNG를 풀고 `cwebp -crop x y w h -q 82` (새 의존성 없음, README에 이미 cwebp 명시). 자르기 값표와 명령을 `assets/screens/crop-features.sh`에 두고 README에 한 줄 추가. 자른 결과가 16:10에서 어긋나면 값만 고치면 됩니다.

## 4. 움직임 줄이기 · 접근성

- 움직임 줄이기: `matchMedia('(prefers-reduced-motion: reduce)')`일 때 **자동 재생 안 함**. 대본은 단계 간격 없이 **마지막 상태를 즉시 그리고**, 버튼을 누르면 즉시 최종 상태로 갈아 끼웁니다(내용은 같고 움직임만 뺌). 상태 점 깜빡임·`.rv` 나타나기·레벨 그림 전환도 CSS `@media (prefers-reduced-motion: reduce)`에서 끕니다. 설정이 중간에 바뀌면 `change` 이벤트로 반응.
- 체험 창: `aria-live="polite"` 영역은 **대화 목록 하나**에만 두고(너무 시끄러우면 `off` + 버튼 눌렀을 때만 알림), 위쪽 상태 줄과 아래 자리 4칸은 장식이라 `aria-hidden`으로 중복 읽기를 막습니다. "체험용 화면 · AI 사용 없음" 배지는 텍스트로 항상 노출.
- 예시 버튼은 `<button aria-pressed>`(시안 방식 유지), 키보드로 이동·실행 가능, 포커스 표시 유지. 타이머는 눌러서 다시 시작할 때 이전 것을 모두 `clearTimeout`(시안은 이미 함), 탭이 안 보이면(`visibilitychange`) 멈춰 불필요한 작업을 줄입니다.
- 레벨 막대: `<input type=range>` + `aria-valuetext`("Lv.7 · 벽돌 건물")를 언어별로, 단계 버튼은 `<button>`. 건물 `<img>`는 `alt`를 사전 키로.
- 휴대폰 메뉴 가로 스크롤: 숨기지 않고 `overflow-x:auto`, 스크롤 가능한 영역이라 `tabindex=0`·`aria-label`. 색 대비: 라이트·다크 둘 다 본문 4.5:1(시안의 연한 벽돌 그라데이션 위 글자 색 확인).

## 5. 검증 방법

- **자동(매번)**: `node site/build-langs.mjs` → `node site/check-i18n.mjs`(키 4개 언어 동일·빈 문구 없음·사진 파일 존재·위 2번의 흐름 키 검사). 지운 사전 키가 남지 않았는지는 "안 쓰는 키" 검사가 잡습니다. 추가로 `git status`로 build-langs가 index.html(한국어 정적 본문)·en/ja/zh을 바꾼 결과가 의도한 것인지 확인.
- **정적 검사 추가 1개**: en/ja/zh 생성 파일에서 `assets/` 상대 경로가 `../assets/`로 바뀌었는지 grep(JS 안 문자열 포함 — 4번 위험 참고), `undefined`·`data-i18n` 빈 요소가 없는지 grep.
- **화면(필요한 만큼만, 총 약 10장 + 동작 확인)**:
  - 한국어: 라이트 PC / 다크 PC / 라이트 휴대폰(390) / 다크 휴대폰 = 4장(첫 화면 + 전체 한 쪽씩 긴 화면).
  - en·ja·zh: 라이트 PC 1장씩 + 가장 긴 문구인 언어(추정 ja·en) 휴대폰 다크 1장 = 약 4장.
  - 700px 경계: 699·701px 한 번씩(배치 전환).
  - 동작(CDP, 사진 아님): 대본 a~d 각 재생 후 마지막 상태 DOM 확인(직원 상태 5종·카드 개수), 레벨 막대 1·7·20과 단계 버튼 7개 클릭, 언어 바꿈 도중 재생 중 타이머가 새 언어로 다시 시작되는지, reduced-motion 켠 상태에서 즉시 최종 상태인지.
- **그림 검사**: 건물 7장 크기 동일, feat 사진의 비율 16:10, 용량 한도, 시험용 이상한 글이 안 찍혔는지(README 기존 주의) 눈으로 1회.
- 안 하는 것: 배포·푸시(지시대로).

## 6. 위험·주의점

1. **정적 본문과 동적 본문의 이중 구조**: build-langs는 `data-i18n` 요소만 채웁니다. 체험을 `data-i18n` 없이 JS로만 그리면 en/ja/zh 페이지 정적 HTML은 비어 보입니다(JS 켜지면 정상). 정적으로 보여야 할 것을 2번대로 구분하세요.
2. **JS 속 경로**: build-langs의 `../` 변환은 `src|href="assets/`와 `'assets/`(작은따옴표)만 잡습니다. 새 JS에서 건물 그림 경로를 백틱·큰따옴표·문자열 조합(`'asse'+'ts'`)으로 쓰면 `/en/` 페이지에서 그림이 깨집니다. 기존 `shotPath`처럼 `'assets/…'` 작은따옴표 리터럴로 쓰고, 검증 5번 grep으로 확인.
3. **정규식 약속**: `var I18N = {…\n};\n` 끝 모양과 `vm`으로 읽을 수 있는 순수 객체(함수·변수 참조 금지)를 지킬 것. 키를 `exp.a.1`처럼 점 표기로 늘리면 전부 한 줄 문자열이어야 합니다. `<!--p-->` 구간 안 문구에 `<!--` 금지.
4. **`SHOTS`(build-langs JSON-LD screenshot)**: 옛 5장(`office, staff-mix, chat, inbox, board`) 목록이 새 사진과 어긋나면 존재하지 않는 파일을 가리킵니다. 사용하는 사진으로 갱신하되(`office`는 첫 화면에서 빠지므로 존재하는 `chat`·`inbox`·`board`·`feat-*` 중 선택) check-i18n의 사진 검사는 `data-shot` 기준이라 JSON-LD 목록은 검사하지 않음 — 사람이 확인.
5. **옛 사진 파일 정리**: `office·staff-mix·theme·retro·phone-secretary·phone-inbox`가 더 안 쓰이면 4개 언어 폴더에서 지워 용량을 줄이되, README 파일 목록도 같이 고칠 것(안 지우면 무해하지만 README가 거짓이 됨). 외부에서 직접 링크했을 수 있어 `office.webp`는 og/공유 용도가 아닌지 확인 후 삭제.
