# 첫 실행 안내 줄이기 — 구현 기록 (정리드 · 2026-11-16)

전달 문서: `../handoff.md` (A+B 섞기). 커밋·배포 안 함. 버전 번호 미정이라 변경 이력·업데이트 소식은 아래 문구만 준비.

## 정리드가 정한 것 (설계 판단)
| 쟁점 | 결정 | 이유 |
|---|---|---|
| 옛 보드 연습(a1~a7) | **삭제, 단체방 흐름 하나로 통일** (디자인 추천안과 같음) | 지시대로 '업무 보드 연습'을 없앰. 대본이 둘이면 문구·시험이 두 벌 |
| 연습 단체방 | **전체 방**에 연습 글을 올림. 글에 `isPractice` 표시 | 연습 팀은 방이 없는 구조(`roomTeams`)라 새 방을 만들지 않음 |
| 지시 받기 | `sendChat` 맨 앞에서 `tutorial.takeChat()` — 지시 단계이고 **연습 리드를 @로 부른 말만** 연습으로 받음 | 연습 중에도 진짜 직원에게 한 지시는 그대로 감. AI 호출 없음 |
| 다시 켰을 때 | 올린 글 id를 저장(`chatIds`)해 같은 글을 두 번 올리지 않음 | 엔진 규칙(효과는 여러 번 해도 같은 결과) 유지 |
| 연습 정리 | 정리 때 `isPractice` 글을 지움(`db.deletePracticeChats`), 화면 목록에서도 뺌 | 직원 글만 지우던 기존 정리는 '내가 보낸 지시'가 남음 |
| 힌트 기록 저장 위치 | **앱 설정** `seenHints: string[]`·`isHintsOff: boolean` (원격 허용 목록에 추가) | PC와 휴대폰 원격 화면이 같은 기록을 봄 |
| 기존 사용자 | 설정에 힌트 기록이 없고 `isOnboarded: true`면 5개 모두 본 것으로 시작(`initialSeenHints`) | ⑤-2. 안내 도중이던 사람(`false`)은 새 사용자처럼 |
| 고용 창 힌트 자리 | 3단계 '어디서 일할까요?' 칸 아래(창 안 한 줄 상자) | 고용 창이 3단계라 폴더 칸이 3단계에 있음 |
| 첫 실행 연습 중 앱 종료 | 다시 켜면 환영부터, 남은 연습 안내는 접음 | 대본 규칙 '처음부터' |
| 실제 첫 업무 코드 | `useFirstTask`·실패 표·관련 문구 77개 삭제. `hasDoneFirstTask`(예전 기록 읽기)만 남김 | ⑤-4 규칙에 필요 |

설계 단계에서 최가독·박패턴 두 안 비교는 생략했습니다(전달 문서가 화면·흐름을 이미 확정, 토큰 절약 지시). 한리뷰·오큐에이 위임도 하지 않았습니다.

## 연습 직원 자동 정리 — 확인 결과
- 코드: `office.hire()`가 실제 직원을 처음 추가할 때 남은 연습 회사를 먼저 지움(이미 있던 동작).
- 개발 앱(새 사용자 데이터)에서 연습 → 끝 화면 → 직원 추가(김기획)까지 한 뒤 DB 확인: 직원은 김기획만, 연습 카드 0, 연습 단체방 글 0. 단체방 화면에도 연습 글이 사라짐.
- 그래서 끝 화면 작은 글은 시안 문구 "연습 직원과 기록은 첫 직원을 추가하면 저절로 정리돼요."를 씀(`onboarding.finish.cleanupNote`).
- 참고: 이미 직원이 있는 사람이 `?`에서 연습하면, 연습 직원은 다음 실제 고용 때나 설정 › 안내 › 연습 회사 정리로 지워짐.

## 확인한 것 (개발 앱, 캡처는 이 폴더)
- 새 사용자: 환영(1) → 계정 확인 → P1(3) → P2 단체방 보내기(4) → 리드 답·기획안 카드(5) → 결재함 승인, 상자는 버튼 아래(6) → 결과 보고 '완료로 옮기기'(7) → 끝 화면 보상 줄(8) → 고용 창 폴더 힌트(9) → 업무 보드 힌트(10) → 회의실 힌트(11) → `?` 서랍(12). 연습 뒤 단체방 힌트는 안 뜸(연습을 해 봄).
- 기존 사용자(예전 연습용 회사 데이터 복사본): 첫 안내 안 뜸, 업무 보드 힌트 안 뜸, `?`만 보임.
- 레트로·업무 모드: `?` 서랍(14), 처음 힌트 다시 보기 후 업무 보드 힌트(15), 둘러보기 수가 12곳으로 줄어듦. 영어 환영·연습·Esc → 끝 화면(16~18), 일본어·중국어 끝 화면 넘침 없음(19), 언어를 바꿔도 끝 화면 유지.
- 라이트: 업무 보드 힌트 짙은 상자(20). 휴대폰 폭(390) 미리보기: `?`가 아래 시트로(22).

## 확인 못 함
- 휴대폰 폭에서 힌트·연습 안내 상자 실제 모습(미리보기 페이지의 다른 안내 창이 안 닫혀 캡처 실패. 코드는 서랍과 같은 `phone:` 규칙).
- 로그인이 안 된 상태의 '계정은 나중에 · 연습 먼저 하기' 버튼(이 맥은 두 계정 다 로그인돼 있음) — 영·일 두 줄 깨짐 여부 포함.
- 결재함 첫 힌트(진짜 결재가 와야 뜸), 회의 연습을 `?`에서 끝까지.
- 11개 색 테마 전부, 윈도우 배율, 태블릿 실기, 맥·윈도우 빌드, 실제 소요 시간(환영의 "약 2분").

## 남은 작은 차이
- 회의실 힌트 문구의 "? › 회의 연습"과 실제 `?` 메뉴 이름 "회의 열기"가 다름(전달 문서 문구 그대로 넣음). 맞추려면 문구 수정 필요.

## 휴대폰에서 연습 막기 (대표 결정 2026-11-16)
대표 결정: 휴대폰(원격 화면·휴대폰 앱)에서는 업무·회의 연습과 연습 안내 상자를 막고, 처음 힌트와 `?` 도움말만 남긴다. 판정은 `IS_REMOTE_SCREEN`(휴대폰 앱·다른 PC 원격 창 모두 해당).

휴대폰에서 연습이 뜨던 경로(코드 확인)와 처리
| 경로 | 처리 |
|---|---|
| PC에서 연습이 진행 중이면 스냅샷 `tutorial`이 휴대폰에도 가서 안내 상자·위 막대 칩·축하 화면·연습 버튼(단체방 '완료로 옮기기', 회의 '할 일로 올리기', 기획안 연습 표시)이 뜸 | `store.setSnapshot`에서 `remoteTutorialSnapshot`(`shared/tutorial.ts`)으로 진행 단계를 지운다. 해 본 기록(`completed`)·`hasPractice`는 남김. 한 곳에서 막아 화면별 조건을 따로 두지 않음 |
| `?` 도움말 › 연습 2종 · 처음 안내 다시 보기 | 연습 제목·항목과 '처음 안내 다시 보기'를 숨기고, 맨 아래에 "업무 맡기기·회의 열기 연습은 PC 앱에서 할 수 있어요." 한 줄 (`helpMenu.practicePcOnly`) |
| 첫 실행 안내(연습 단계·끝 화면의 회의 연습·'진짜로 해 보기'로 이어지는 흐름) | 휴대폰에서는 `Onboarding`을 그리지 않음. AI 계정 확인도 PC 일이라 안내 전체를 PC로 (PC에서 '처음 안내 다시 보기'를 눌러도 휴대폰에는 겹쳐 뜨지 않음) |
| 설정 › 안내: 처음 안내 다시 보기·연습 해 보기(→ 연습 고르기)·연습 회사 정리 | 휴대폰에서 숨김. 둘러보기·힌트 다시 보기는 남김 |
| 직원 0명 띠의 '처음 안내 다시 보기' | 휴대폰에서 숨김 |
| 회의실 처음 힌트 "? › 회의 열기 … 연습" | 휴대폰은 연습 안내 없는 문구 `firstHint.meeting.remote` (4개 언어) |
| 원격 프로토콜 `tutorialStart`·`tutorialAct`·`tutorialCleanup` | R → P(`open_on_pc`). 예전 휴대폰 화면 묶음이 불러도 PC가 거절 |

판단: 화면마다 `IS_REMOTE_SCREEN` 조건을 붙이는 대신 스냅샷을 받는 곳 한 곳에서 진행 단계를 지움 → 안내 상자·칩·축하 화면·'진짜로 해 보기'·화면 속 연습 버튼이 함께 사라지고, 새 연습 화면이 생겨도 휴대폰에 새지 않음. 입구(버튼)만 화면에서 숨김.
남은 점: 휴대폰은 PC가 연습 중일 때 연습 직원·연습 카드 자체(‘연습’ 꼬리표)는 그대로 보임(PC 데이터라 숨기지 않음). `?` 서랍 '지금 화면 · 사무실' 설명의 "⌘+스크롤" 문구는 휴대폰에서도 그대로(기존 문구, 이번 범위 밖).
시험: `scripts/tutorialRemote.test.mts`(5건), `remote-v2.test.mts` 분류 수(R 102·P 34). 미리보기 가짜 셸에 `?tut=1`(PC 연습 중)·`?onb=0`·`?hints=1` 추가.
캡처: `23-phone-help.png`(휴대폰 폭 390 `?` 시트). 휴대폰 폭에서 `?tut=1&onb=0`로 열어 안내 상자·대화상자·'연습 중' 칩이 없는 것을 확인(값으로 측정).
확인 못 함: 휴대폰 회의실 힌트 실제 모습(미리보기에서 회의실로 넘어가는 자동 클릭이 안 됨 — 문구 교체는 시험으로만 확인), 안드로이드 실기, 다른 PC 원격 창.
