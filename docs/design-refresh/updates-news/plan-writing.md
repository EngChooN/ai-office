# 업데이트 소식 '작성 규칙' 기획

작성: 김기획 (2026-11-12) · 요청: 정리드 · 근거: brief.md, 루트 CHANGELOG.md(읽기만, 수정 안 함)

## 1. 새 작성 규칙

### 1-1. 버전 구조

```
## [버전] - 날짜
### 한눈에 보기        ← 새 맨 위 요약 (3~5줄)
- 새 기능 · …
- 개선 · …
- 수정 · …
(필요할 때만) > PC 앱 전용: …   ← 기기 안내 한 줄
### 새 기능           ← 상세
### 개선
### 버그 수정
```

- '한눈에 보기'는 파서가 새 섹션 종류(`summary`)로 읽는다. **정리드 확인 필요:** 파서(`changelogParse.ts`)·시험(`changelog.test.mts`)에 `summary` 종류 추가, 화면은 요약만 펼쳐 두고 상세는 접기. 기존의 섹션 앞 "기기별 차이:" 본문은 위 '기기 안내 한 줄'로 대체(다른 한 줄 `>` 인용이면 파서가 'other'로 읽는 현행 방식 그대로 사용 가능).

### 1-2. 핵심 요약 ('한눈에 보기')

| 항목 | 기준 |
|---|---|
| 줄 수 | **3~5줄** (6줄 이상 금지. 변경이 많으면 가장 큰 것만) |
| 줄당 길이 | **공백 포함 35자 이내**, 한 문장, 마침표 없음 |
| 줄 시작 | `새 기능 · ` / `개선 · ` / `수정 · ` 중 하나 (종류가 눈에 보이게) |
| 문장 | "사용자가 이제 무엇을 할 수 있나"로 쓴다. 끝은 "~해요/~돼요" |
| 순서 | 새 기능 → 개선 → 수정. 가장 눈에 띄는 것부터 |
| 한 줄에 한 가지 | "A하고 B도 돼요"로 묶지 말 것(묶어도 같은 화면 안에서의 한 덩어리만) |
| 수정 | 사용자가 겪던 불편이 큰 것만 요약에 올린다 |

### 1-3. 상세 항목

- 항목 하나는 **1~2문장, 100자 안팎**(최대 120자). 지금처럼 3~8문장 금지.
- 버전당 **새 기능 5개 이하, 개선 4개 이하, 버그 수정 4개 이하**. 넘치면 같은 화면의 것을 한 항목으로 합친다.
- 항목 첫 문장 = 달라진 점. 둘째 문장 = 쓰는 곳·방법 한 가지만(예: 왼쪽 위 'PC 바꾸기').
- 기술 이름·파일 경로·영어 약어 금지(기존 규칙 유지). 단계 수·최대 개수 같은 세부 숫자는 꼭 필요한 것 하나만.
- 설명서가 되지 않게: 사용법 전부는 앱 안 안내·매뉴얼에 맡긴다.

### 1-4. 넣지 않는 것

| 넣지 않음 | 이유 / 대신 |
|---|---|
| 내부·개발 사정(구조 정리, 시험, 빌드, 도구 변경) | 사용자 눈에 달라진 게 없음. `SPEC.md`·`docs/changelog-dev.md`로 |
| 기기별 사소한 차이 | 못 쓰는 기능이 있을 때만 **기기 안내 한 줄**(40자 이내). 나머지는 생략 |
| 같은 버전 안의 재수정 | 이 버전에서 새로 넣은 기능의 버그는 '수정'에 쓰지 않는다. 앞선 버전부터 있던 문제만 수정으로 |
| 보안 허점을 적는 방식 | "~허점을 막았어요"·방법·조건 설명 금지. 쓰려면 "연결 보안을 강화했어요"처럼 결과만 한 줄. 새 기능에 딸린 보호는 쓰지 않는다 |
| 사소한 문구·간격·색 조정 | 사용자가 알아채기 어려움 |
| 내부 용어·일정·담당자 | 사용자에게 무의미 |

### 1-5. 새 기능 / 개선 / 수정을 나누는 기준

- **새 기능**: 전에는 **할 수 없던 일**을 이제 할 수 있다. (질문: "이 버전 전에는 불가능했나?" 예 → 새 기능)
- **개선**: 전에도 할 수 있던 일이 **더 쉽거나 빠르거나 보기 좋아졌다**. 문구 쉬워짐, 화면 정리 포함.
- **수정**: 전에 **잘못 동작하던 것**이 바로잡혔다. 이 버전에서 만든 것의 오류는 제외.
- 헷갈리면: 새로 배워야 하면 새 기능, 아는 걸 더 편하게면 개선, 원래 되어야 할 게 안 됐던 거면 수정.

## 2. 1.3.0 새 규칙 초안 (한국어)

> 루트 CHANGELOG.md는 김버전 소유 — 아래는 제안 초안이며 이 문서에만 적었습니다.

```markdown
## [1.3.0] - 2026-11-12

### 한눈에 보기
- 새 기능 · 내 PC 여러 대를 연결해 오가요
- 새 기능 · 매뉴얼을 말·예시·직접 쓰기로 만들어요
- 새 기능 · 결재 카드가 할 일을 한 줄로 알려요
- 개선 · 설정과 매뉴얼 문구가 쉬워졌어요
- 수정 · 메시지 속 링크가 다시 열려요

> PC 앱 전용: PC 연결과 매뉴얼실 새 화면

### 새 기능
- 다른 PC를 연결하면 그 PC의 사무실·직원·대화·결재를 지금 PC에서 보고 일을 시킬 수 있어요. 왼쪽 위 'PC 바꾸기'로 전환하고, 최대 3대까지 연결해요.
- 새 매뉴얼을 말로 설명하기(AI 초안), 예시 7개에서 고르기, 직접 쓰기 중 골라 만들어요. 저장하면 '쓸 수 있게 하기'에서 쓸 직원·팀·랩을 정해요.
- 결재 카드에 "무엇을 하는지"가 한 줄로 보이고, 삭제·덮어쓰기처럼 위험한 동작은 먼저 알려 줘요. AI가 판단한 줄은 'AI 추정'으로 표시돼요.
- 세로 폰에서 기다리는 결재가 1건이고 간단하고 안전해 보이면 한 줄 띠에서 바로 승인해요.
- 직원 장비 탭이 일 종류별 카드가 되어, 각각 '막기·결재 받기·결재 없이' 중에서 골라요.

### 개선
- 설정 화면을 쉬운 말로 정리하고, 자주 쓰는 설정만 펼쳐 두었어요. 나머지는 '더 보기'에 있어요.
- 매뉴얼 문구를 쉽게 바꿨어요. "교육"은 "쓸 수 있게 하기", 단계 진행 매뉴얼은 "여러 명이 이어서 하는 업무"로 불러요.
- 매뉴얼에 한글 표시 이름을 붙일 수 있고, 매뉴얼이 하나도 없을 때는 무엇부터 하면 되는지 안내해 줘요.

### 버그 수정
- 직원이 보낸 메시지의 링크가 안 열리던 문제를 고쳤어요. 이제 기본 브라우저로 열려요.
- 대화방의 '매뉴얼'·'/ 명령' 버튼을 누르면 직원 고르는 창이 먼저 뜨던 문제를 고쳤어요.
```

**줄 수 대조(기존 → 초안):** 새 기능 5줄(3~8문장)·개선 4줄·수정 5줄+기기별 문단 → 요약 5줄 + 상세 5·3·2줄(각 1~2문장).
**뺀 것:** 매뉴얼 이름 칸 잠금·AI 초안 누락 처리(이번 버전 새 기능의 재수정), 다른 PC의 작업 폴더 변경 차단(보안 허점 서술 + 새 기능에 딸린 보호), 휴대폰 링크 열기를 본 창·펫 창별로 나눠 적은 설명, 기기별 차이 문단(→ 기기 안내 한 줄), 결재 카드 효과 줄 2차의 세부 목록.

## 3. 1.2.0 이하 옛 버전 처리 — 추천

**추천: 다시 쓰지 않고 그대로 둔다. 단 화면에서 옛 버전은 접힌 상태로 보이게 하고, 직전 버전 1.2.0만 '한눈에 보기' 요약을 덧붙인다.**

| 선택지 | 판단 |
|---|---|
| 전부 새 규칙으로 다시 쓰기 | ✗ 55개 버전 × 4개 언어. 번역·시험 갱신 비용이 크고, 오래된 소식을 다시 읽는 사람이 거의 없음. 사실 오기재 위험도 |
| 요약만 전부 덧붙이기 | △ 비용은 줄지만 여전히 4개 언어 × 55개. 효과는 최신 몇 개에 몰림 |
| **그대로 두기 + 1.2.0만 요약 추가** | ✓ 새 규칙은 1.3.0부터 적용되는 걸 분명히 하고, 최근 버전만 통일감 확보 |

- **요약이 없는 버전의 화면 처리(정리드 확인):** 요약이 없으면 상세를 접어 두고 제목줄에 "새 기능 N · 개선 N · 수정 N"처럼 항목 수만 보이게. 요약이 필요한 시험은 "1.3.0 이후 버전에 한해 요약 필수"로.
- 1.2.0 요약 제안은 필요하면 따로 쓰겠습니다(이번 요청 범위 밖).

1. 파서·시험·화면에 `summary` 섹션 추가(접기 포함), 1.3.0부터 요약 필수.
2. 위 초안을 김버전에게 전달해 CHANGELOG(4개 언어)·release-notes 반영 — 번역 en·ja·zh는 이번 범위 밖.
3. 규칙 문구는 CHANGELOG.md 머리말 '쓰는 규칙'에 이식 필요(김버전 소유).
4. 요약 줄 길이(35자)는 영·일·중 번역에서 다를 수 있어 언어별 상한 확인 필요.
