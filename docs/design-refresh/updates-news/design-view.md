# 업데이트 소식 — 보여 주는 방식 (디자인 결정)

작성: 이디자 · 2026-11-12 · 요청: 정리드 · 코드·CHANGELOG 수정 없음
시안: [`updates-news.html`](updates-news.html) — 위 막대에서 테마 10종 × 라이트·다크, 상황 4가지(새 버전 있음 / 건너뜀 / 여러 버전 밀림 / 최신·휴대폰), '상세 펼친 모습'을 바꿔 볼 수 있습니다. PC(768px)와 폰 세로(375px)를 나란히 그렸습니다.
캡처: `shot-next-light.png`, `shot-multi-dark.png`, `shot-skipped-mono.png`, `shot-open-candy-dark.png`

같은 폴더의 김기획 `plan-writing.md`(작성 규칙), 박패턴 `design-pattern.md`·최가독 `design-readable.md`(기술안)를 읽고 맞췄습니다. 요약 섹션 이름(`한눈에 보기`/`핵심`/`요약`)과 데이터 경로는 그쪽에서 정하고, 이 문서는 **화면에 어떻게 보일지**만 정합니다.

## 1. 페이지 구조 (위에서 아래로)

1. 제목 "업데이트 소식" + 설명 "지금 버전 v1.3.0. 버전마다 무엇이 바뀌었는지 볼 수 있어요."
2. **새 버전 카드**: 설치하지 않은 새 버전이 있을 때만 보입니다.
3. **지금 버전 카드**
4. 구분선 "지난 버전"
5. **지난 버전 줄**: 한 줄로 접혀 있고, 누르면 펼쳐집니다.

- 강조 테두리(`border-primary`)는 맨 위 카드 하나에만 둡니다. 새 버전 카드가 있으면 지금 버전 카드는 보통 테두리(`border`)로 바뀝니다. 보라 테두리 두 개가 겹치면 어느 쪽이 중요한지 흐려지기 때문입니다.
- 카드 사이 간격 12px, 최대 폭 768px(`max-w-3xl` 그대로)

## 2. 버전 카드

### 2-1. 카드 안 순서
```
v1.3.0  [지금 버전]  11월 12일                ✦5  ⬆4  🐞5   ← 머리줄 (오른쪽은 종류별 항목 수)
[✦ 새 기능] 내 PC 여러 대를 연결해 오가요                     ← 요약 3~5줄
[✦ 새 기능] 매뉴얼을 말·예시·직접 쓰기로 만들어요
[⬆ 개선  ] 설정과 매뉴얼 문구가 쉬워졌어요
[🐞 수정  ] 메시지 속 링크가 다시 열려요
PC 앱 전용: PC 연결과 매뉴얼실 새 화면                         ← 있을 때만, 작은 회색 한 줄
› 바뀐 점 14가지 모두 보기                                    ← 접기 버튼
```
- 머리줄: 버전 18px 굵게, 칩, 날짜는 `fmtDate`로 짧게 표시(예: "11월 12일"), 오른쪽에 종류별 개수(아이콘 14px + 숫자, `text-xs text-muted-foreground`)
- 요약 줄: 배지 + 문장 한 줄(14px, 줄높이 22px, 줄 사이 7px). 배지 폭은 최소 66px로 맞춰 문장 시작점이 세로로 맞습니다.
- 요약 줄 맨 앞의 종류 말(`새 기능 · ` 또는 `**새 기능**`)을 뽑아 배지로 바꿉니다. 종류 말이 없는 줄은 배지 없이 문장만 그립니다.
- '기기별 차이' 문단(kind `other`)은 **상세 안 맨 아래**, 회색 상자(`bg-muted`, 12px)에 넣습니다. 요약 아래에는 김기획 규칙의 "PC 앱 전용: …" 한 줄만 둡니다.

### 2-2. 접기 문구와 기본 상태
| | 접힘 | 펼침 |
|---|---|---|
| ko | 바뀐 점 {n}가지 모두 보기 | 간단히 보기 |
| en | See all {n} changes | Show less |
| ja | 変更点{n}件をすべて見る | 簡単に表示 |
| zh | 查看全部 {n} 项变更 | 收起 |

- 모양은 기존 `MoreToggle`과 같습니다(`text-primary`, 꺾쇠 › 가 펼치면 ⌄로 바뀜, 13px 굵게). 다만 글자가 달라 `MoreToggle`에 문구를 넘기는 방식이 필요합니다.
- `{n}`은 상세 항목 수의 합입니다(1.3.0이면 14).
- **처음부터 펼쳐 두는 것:** 새 버전 카드와 지금 버전 카드는 **요약만** 보입니다. 상세는 모든 카드에서 **접혀** 있습니다.
- **요약이 없는 옛 버전**(1.2.0 이하 중 요약을 넣지 않은 것): 접을 요약이 없으므로 펼치면 상세가 바로 보입니다. 지금 버전 카드가 옛 형식이면 상세를 처음부터 펼쳐 둡니다. 내용이 비어 보이지 않게 하려는 것입니다.
- 펼침 상태는 화면을 떠나면 초기화합니다(저장 안 함).
- 상세 안의 섹션 제목도 같은 배지에 개수를 붙입니다. 예: `[✦ 새 기능 5]`. 지금의 색 글자 제목을 대신합니다.

### 2-3. 지난 버전 줄
- 높이 44px 이상. 내용은 `v1.2.0  11월 11일 ··· ✦5 ⬆2 🐞1  ›`
- 누르면 그 자리에서 펼쳐집니다. 요약이 있으면 요약과 '모두 보기'가, 없으면 상세가 바로 보입니다.
- 줄 전체가 버튼입니다(`aria-expanded` 사용).

## 3. 새 기능 / 개선 / 수정 구분

| 종류 | 배지 글자 (ko/en/ja/zh) | 아이콘 | 색 토큰 (KIND_STYLE 재사용) |
|---|---|---|---|
| 새 기능 | 새 기능 / New / 新機能 / 新功能 | 듀오톤 `new` (기존) | `--status-working` |
| 개선 | 개선 / Better / 改善 / 改进 | 듀오톤 **`improve` (새로 필요)**: 둥근 네모 + 위 화살표 | `--primary` |
| 수정 | 수정 / Fixed / 修正 / 修复 | 듀오톤 `bug` (기존) | `--status-waiting` |

- **배지 모양:** 높이 22px, 모서리 6px, 좌우 여백 5·7px, 글자 11.5px semibold. 배경은 `color-mix(토큰 12%, card)`, 아이콘은 토큰색, **배지 글자는 본문색(`card-foreground`)** 입니다.
  - 글자까지 토큰색으로 칠하면, 라이트 모드 다섯 테마(라벤더·블루·테라코타·세이지·로즈)에서 '개선' 글자의 대비가 3.8~4.1:1이 됩니다. 4.5:1 기준에 못 미칩니다(이디자가 index.css 20개 조합으로 계산).
  - 글자를 본문색으로 바꾸면 모든 테마에서 기준을 넘습니다. 아이콘은 토큰색 그대로 두면 3:1 이상이라 괜찮습니다.
- **모노 테마:** `--primary`가 검정·흰색이라 '개선' 배지가 회색으로 보입니다. 아이콘 모양과 글자로 구분되므로 그대로 둡니다(`shot-skipped-mono.png`).
- **아이콘을 새로 그려야 하는 이유:** 지금은 `iconText.ts`에서 🔧도 `bug`로 바뀝니다. 그래서 개선과 버그 수정에 **같은 벌레 아이콘**이 나옵니다. `improve`를 새로 추가하는 것을 제안합니다(경로 데이터는 시안 HTML의 `ICON.improve`에 있습니다).
  ```
  improve: [{ t:'rect', x:3.5, y:3.5, w:17, h:17, rx:4.5, fill:true }, { t:'path', d:'M12 16.5V8M8.3 11.5 12 7.8l3.7 3.7' }]
  ```
- 사전의 `updates.kind.*`(✨ 새 기능 등 이모지가 붙은 섹션 제목)는 상세 배지에 계속 쓰고, 요약 배지에는 위 표의 짧은 말을 씁니다. 새 키가 필요합니다. 예: `updates.badge.feature|improve|fix`

## 4. 새 버전 카드 (아직 설치하지 않은 버전)

### 4-1. 기본 모습: 새 버전 1개
```
┌ (보라 테두리 1.5px, 위쪽 96px만 primary 7% 물들임) ─────────┐
│ [새 버전] 아직 설치하지 않았어요                              │
│ v1.3.0  11월 12일                          ✦5 ⬆4 🐞5        │
│ (요약 3~5줄) · › 바뀐 점 14가지 모두 보기                     │
│ ──────────────────────────────────────────────────────────── │
│ [지금 업데이트]  지금 v1.2.0 → 설치하면 v1.3.0                │
└──────────────────────────────────────────────────────────────┘
```
- 지금 버전 카드와 다른 점: 맨 위 위치, `[새 버전]` 칩(채운 primary), 굵은 테두리와 위쪽 물들임, 아래 업데이트 줄
- **업데이트 버튼을 둡니다.** 소식을 읽고 바로 설치하는 흐름이 가장 자연스럽기 때문입니다.
  - `canInstall`일 때: [지금 업데이트]. 기존 `InstallButton`을 그대로 써서 내려받는 진행률이 버튼 안에 차오르고, 누르면 기존 `InstallConfirm`(앱이 꺼진다는 확인 창)이 뜹니다.
  - 설치할 수 없을 때: [내려받기]. 기존 `update.download`를 쓰고 브라우저가 열립니다.
  - 기술안 두 개는 "기존 안내 창(`openNotice`) 열기"를 제안했습니다. 그렇게 해도 되지만, 그 창이 같은 요약을 한 번 더 보여 주므로 한 단계 늘어납니다. 아래 갈림길 G2에서 고릅니다.
- 이 화면에는 [나중에] 버튼을 두지 않습니다. 건너뛰기는 알림을 끄는 일이라 안내 창에서만 합니다.

### 4-2. 건너뛴 버전 ('나중에'를 누른 버전)
- 카드는 **그대로 보이고 힘만 뺍니다.**
  - 테두리를 점선 `border`색 1.5px로 바꾸고 물들임은 없앱니다.
  - 칩은 `[건너뛴 버전]`(muted)으로, 옆 문구는 "알림만 껐어요. 원하면 언제든 설치할 수 있어요."로 바꿉니다.
  - 버튼은 outline으로 바꾸고 문구는 [v1.3.0로 업데이트]로 합니다.
- 강조 테두리는 아래 지금 버전 카드로 넘어가지 않습니다. 그 카드는 보통 테두리를 유지합니다.
- 사이드바 배지와 안내 창은 지금처럼 뜨지 않습니다(기존 `shouldNotify` 규칙).

### 4-3. 여러 버전을 건너뛰었을 때 (예: 1.1.5 → 1.2.0·1.3.0)
- **카드 하나로 묶습니다.** 설치는 어차피 한 번에 최신으로 되기 때문입니다.
  - 칩은 `[새 버전 2개]`, 옆 문구는 "업데이트하면 한 번에 받아요"
  - 최신 버전(1.3.0)은 머리줄과 요약, '모두 보기'를 보여 줍니다.
  - 그 아래 "함께 받는 이전 새 버전" 소제목을 두고, 1.2.0을 **지난 버전 줄과 같은 한 줄**로 둡니다. 누르면 펼쳐집니다.
  - 업데이트 버튼은 카드 맨 아래 하나만 둡니다. 문구는 "지금 v1.1.5 → 설치하면 v1.3.0"
- 이전 새 버전이 5개를 넘으면 한 줄짜리를 4개까지만 보이고 "그 전 새 버전 N개 더 보기"로 접습니다.
- 기술안에서 목록을 10개로 자르는 경우, 잘린 버전은 맨 끝에 "더 이전 소식은 GitHub에서 보기" 링크로 알립니다. 조용히 자르지 않습니다.
- 묶음 안에서 일부 버전만 건너뛴 상태여도 묶음은 하나입니다. 가장 높은 버전이 건너뛴 버전이면 4-2처럼 힘을 뺀 모양을 씁니다.

### 4-4. 카드가 없는 경우
- 최신 버전을 쓰는 중, 확인 실패, 오프라인, 휴대폰 앱(업데이트 통로 없음)이면 새 버전 카드를 그리지 않고 오류 문구도 내지 않습니다. 이때 지금 버전 카드가 맨 위에 오고 강조 테두리를 받습니다.

## 5. 좁은 화면 (폰 세로 360~430px)

시안 오른쪽 375px 화면을 보세요.
- 페이지 좌우 여백 12px, 카드 안 여백 14px, 카드 사이 간격 10px
- **머리줄:** 버전·칩·날짜가 한 줄입니다. 종류별 개수는 **둘째 줄 왼쪽**으로 내립니다.
- **요약 줄:** 배지 글자를 그대로 둡니다. 375px에서 문장 칸이 약 250px 남아 김기획 규칙(35자 이내)이 두 줄 안에 들어갑니다. 배지와 문장 간격은 8px, 글자는 13.5px입니다.
- **접기 버튼과 지난 버전 줄:** 누르는 높이를 44px 이상으로 합니다.
- **업데이트 줄:** 버튼을 폭 전체·높이 44px로 하고, "지금 → 설치하면" 문구는 버튼 아래로 내립니다.
- 상세 목록은 들여쓰기 18px를 그대로 둡니다. 긴 항목은 줄바꿈합니다.
- 휴대폰 앱에는 새 버전 카드가 없습니다(4-4). 다만 폴드나 원격 화면처럼 PC 소식이 좁은 폭에 뜨는 경우를 위해 같은 규칙을 둡니다.

## 6. 함께 바뀌는 곳 (참고)
- `WhatsNew`(업데이트 직후 뜨는 "새 소식" 창)도 `ReleaseNotes`를 씁니다. 같은 요약과 접기가 들어가므로 창이 짧아집니다. 창 안에서는 상세를 접은 채로 시작합니다.
- 업데이트 안내 창(`AppUpdate`)의 평문 요약은 이번 범위에서 뺍니다. 기술안 두 개와 같은 판단입니다.

## 7. 대표 확인이 필요한 갈림길

| # | 갈림길 | 선택지 (추천은 ①) |
|---|---|---|
| G1 | 지난 버전의 기본 모습 | **① 한 줄로 접기** (버전·날짜·종류별 개수만, 누르면 펼침) · ② 지난 버전도 요약까지 펼쳐 두기 (스크롤이 길어짐) |
| G2 | 새 버전 카드의 버튼 | **① 카드에 [지금 업데이트]**: 앱이 꺼진다는 확인 창만 거침 · ② [업데이트]가 기존 안내 창을 열어 그 안에서 설치 (한 단계 더, 구현은 가장 작음) · ③ 버튼 없이 소식만 (설치는 안내 창·설정에서) |
| G3 | 건너뛴 버전 | **① 보이되 점선·회색 칩으로 힘을 뺌** · ② 소식 화면에서도 숨김 (알림을 끈 뜻을 더 강하게 따름. 대신 다시 설치하려면 설정에서만 가능) |
| G4 | 여러 버전을 건너뛰었을 때 | **① 카드 하나로 묶기**: 최신은 요약, 이전은 한 줄 · ② 버전마다 새 버전 카드를 따로 (각 버전 요약이 다 보이지만 업데이트 버튼이 어디 붙는지 헷갈림) |

## 8. 개발 전달 요약 (확정 후 정리드에게)
- 새로 필요한 것
  - 듀오톤 아이콘 `improve` 1종
  - 요약 배지용 사전 키 3개
  - 접기 문구 사전 키 2개(`{n}` 포함)
  - 새 버전 칩·문구 키: 새 버전 / 새 버전 {n}개 / 건너뛴 버전 / 아직 설치하지 않았어요 / 업데이트하면 한 번에 받아요 / 알림만 껐어요… / 함께 받는 이전 새 버전 / 지금 v{a} → 설치하면 v{b} / v{v}로 업데이트
