단체방 상단 정리 — 3안 비교

목표: 처음 본 사람도 지금 어느 방인지 · 누구와 얘기하는지 · 누가 일하는지를 바로 알게. 네 화면 모두 같은 상황(클로드 오피스 전담 랩 방, 13명 중 정리드 1명이 일하는 중, 다른 방 안 읽은 글 74개, 앱 팀에 결재 대기)이다. 방 바꾸기·팀/랩 고르기·멘션·결재 대기 표시는 세 안 모두 그대로 남는다.

지금 — 4줄

제목 · 설명 문장 · 방 칩 9개 · 직원 칩 6개+7명. 방 칩과 직원 칩이 둘 다 동그란 알약 모양이라 무엇이 방이고 무엇이 사람인지 헷갈린다.

A안 — 한 줄 머리 추천

세로 폰 한 줄 머리(ChatSlimBar)를 데스크톱에도 맞춘다. [방 이름 ▾] [일하는 사람 얼굴 · 1명 일하는 중] ⓘ 🔍 한 줄.

B안 — 왼쪽 방 목록

메신저처럼 방 목록을 왼쪽에 항상 둔다(분할 화면용 ChatSide 재사용). 상단은 제목 + 인원 요약 + 일하는 사람만.

C안 — 두 줄 정리

지금 구조를 크게 안 바꾼다. 1줄 제목·요약, 2줄 [전체 | 팀 ▾ | 랩 ▾] 묶음 + 일하는 사람 칩만.

지금 화면 (대표 스크린샷 기준 재구성)

어려워 보이는 이유 4가지를 노란 표시로 붙였다.

문제

  1. 제목 중복 — "클로드 오피스 전담 랩 랩 방". 랩 이름이 이미 '랩'으로 끝나 '랩 랩'이 된다.
  2. 설명이 늘 펼쳐져 있다 — 두 문장(약 70자)이 매번 보인다. 처음 한 번만 읽으면 되는 내용이다.
  3. 방과 사람이 같은 모양 — 방 칩 9개와 직원 칩 6개가 모두 알약 모양이라 줄이 4줄로 보인다. '팀'·'랩' 회색 글씨 구분은 눈에 잘 안 띈다.
  4. 쉬는 사람까지 다 보인다 — 일하는 사람은 정리드 1명인데 '대기' 칩 5개가 같은 크기로 늘어서 있다.

A안 — 한 줄 머리 추천

세로 폰에 이미 있는 한 줄 머리와 같은 순서·같은 말로 맞춘다. 데스크톱·폴드·폰이 같은 모양이 되어 한 번 익히면 어디서나 같다.

방 이름 ▾ 를 누르면

얼굴 묶음을 누르면

한 줄 구성 (왼쪽부터)

  1. 방 이름 ▾ — 색 점 + 방 이름 + 작은 꼬리표(랩/팀). 제목의 '랩 방' 반복을 없앤다. 다른 방의 안 읽은 글 합계(빨강)와 결재 대기 점(노랑)을 ▾ 옆에 붙여 방을 바꿀 이유를 알려 준다.
  2. 얼굴 묶음 — 일하는 사람 얼굴 최대 3개 + "1명 일하는 중"(초록) + "· 13명". 누르면 이 방 사람 전체가 '일하는 중 → 확인 필요 → 쉬는 중' 순으로 나온다. 일하는 사람이 없으면 "13명 · 모두 쉬는 중".
  3. ⓘ — 방 설명. 문장 대신 3줄 요약(누가 받나 · @부르는 법 · 결과가 오는 곳).
  4. 🔍 대화 찾기 — 지금 자리 그대로.

ChatSlimBar와 같은 점 / 다른 점

  • 같음: 방 ▾ 안 = ChatSide 목록, 얼굴 3개, "N명 일하는 중", ⓘ, 🔍.
  • 다름: 데스크톱은 상단 앱 바가 있으므로 결재 대기 🔔·비서 ✨는 앱 바에 둔다(머리에 중복으로 넣지 않음).
  • 제안: 슬림에도 안 읽은 합계 배지와 팀/랩 꼬리표를 같이 넣으면 완전히 같아진다.

줄어드는 것

  • 머리 높이 약 150px → 50px. 대화가 세 줄쯤 더 보인다.

대가

  • 다른 방으로 가려면 한 번 더 누른다. 대신 안 읽은 합계·노란 점이 ▾ 옆에 남아 놓치지 않는다.

B안 — 왼쪽 방 목록

방 고르기를 상단에서 빼서 왼쪽에 세로로 둔다. 분할 화면(폴드 와이드)에서 이미 쓰는 왼쪽 칸(ChatSide)을 넓은 창에도 쓰는 안이다.

구성

  • 왼쪽 칸 — '전체' / '팀' / '랩' 묶음 제목 아래 방 목록. 안 읽은 글(빨강)·결재 대기(노랑 점)는 줄 끝. 회의실 들어가기도 여기.
  • 상단 1줄 — 방 이름 + 랩 꼬리표 + ⓘ + 🔍.
  • 상단 2줄 — "13명 · 1명 일하는 중" 요약 + 일하는 사람 칩만(지금 하는 일 한 줄). 나머지는 '+12명'으로 접고, 누르면 A안과 같은 사람 목록.

좋은 점

  • 방이 몇 개든 한눈에 보이고, 다른 방 새 글을 바로 본다. 익숙한 메신저 모양.

대가

  • 대화 칸이 200px 좁아진다. 직원 패널(기본 380px)까지 열면 창 1100px에서 대화가 342px밖에 안 남는다 → 아래 '보완'에서 해결.
  • 세로 폰에는 들어갈 자리가 없어 결국 A안처럼 ▾ 메뉴가 된다 → 배치마다 모양이 다르다.
  • 왼쪽 칸 아래의 '지금 하는 일' 목록과 상단 칩이 겹친다(둘 중 하나만 두어야 함).

B안 보완 — 방 목록 + 대화 + 직원 패널을 모두 열었을 때

앱의 실제 폭으로 그린 뒤 절반쯤(47%)으로 줄였다: 앱 왼쪽 메뉴 176px(Sidebar w-44) · 방 목록 200px(ChatSide) · 직원 패널 기본 380px(StaffPanel, 최소 320). 창이 1000px보다 좁으면 지금도 직원 패널이 대화 위에 겹쳐 뜬다(compact 규칙). 데스크톱 앱 창의 최소 폭은 1024px이라 900px은 데스크톱에서는 나오지 않지만, 비교를 위해 함께 그렸다. 가운데 화살표가 대화 영역의 실제 너비이고, 그림을 그린 뒤 브라우저에서 잰 값이다(테두리 1px씩 빠짐). 900px에서는 대화 칸이 B안 그대로 522px · 접힘 666px이지만 직원 패널이 덮어 화살표에는 보이는 폭만 적었다.

접힌 상태 — 실제 크기

왼쪽은 마우스를 올린 모습, 오른쪽은 띠 맨 위 ☰을 눌러 목록을 잠깐 펼친 모습이다. 펼친 목록은 대화를 밀지 않고 위에 겹쳐 뜨며, 방을 고르거나 바깥을 누르면 다시 접힌다.

56px 띠 구성

  • ☰ 맨 위 — 누르면 목록을 겹쳐 펼친다. 길게 고정하려면 목록 안의 📌.
  • 방 아이콘 36px — 팀 색 바탕 + 첫 글자(전·프·PO·디…). 랩은 랩 색으로, 지금 방은 보라 테두리 + 왼쪽 막대.
  • 안 읽은 글 빨간 숫자는 오른쪽 위(99+까지), 결재 대기 노란 점은 오른쪽 아래. 펼친 목록과 같은 정보.
  • 묶음은 제목 대신 얇은 선(전체 | 팀 | 랩). 회의실은 맨 아래.
  • 마우스 올림 — 방 이름 + 안 읽은 수 말풍선.

대화 머리도 함께 줄인다

  • 대화가 560px보다 좁으면 2줄의 사람 칩을 A안처럼 얼굴 + "1명 일하는 중 · 13명"으로 줄인다. 누르면 같은 사람 목록.

자동 접힘 규칙

  • 접는 때 — 직원 패널 열기, 패널 폭 넓히기, 창 줄이기로 대화 폭이 640px 아래가 될 때. 직원 패널을 열면 바로 접히는 셈이고(1100px 기준), 넓은 창(1400px)에서는 접히지 않는다.
  • 펴는 때 — 대화 폭이 다시 640 + 144 = 784px 이상 확보될 때(직원 패널 닫기 등). 경계에서 깜빡이지 않게 펴는 기준을 접는 기준보다 크게 둔다.
  • 사람이 정한 것 우선 — 직접 ☰으로 접거나 📌으로 고정했으면 자동으로 바꾸지 않는다.
  • 먼저 줄이는 순서 — ① 방 목록(띠) → ② 머리 사람 칩(얼굴 묶음) → ③ 직원 패널 겹치기. 대화와 직원 패널은 마지막까지 지킨다.
  • 확인 필요 앱 왼쪽 메뉴(176px)도 아이콘 띠로 접으면 +120px을 더 얻지만, 단체방만의 일이 아니라 앱 전체 배치라 이번 범위에서 뺐다.
최종 추천: B안 + 자동 접힘 — 1400px에선 B안 그대로, 직원 패널로 대화가 640px 아래가 되면 방 목록을 56px 띠로 접어 1100px에서도 대화 486px(342px → 486px)를 지킨다.

C안 — 두 줄 정리

지금 구조(위 제목, 아래 방 고르기)를 살리고 덜어 내기만 한다. 바뀜이 가장 적다.

구성

  • 1줄 — 방 이름 + 랩 꼬리표 + "13명 · 1명 일하는 중" + ⓘ 🔍.
  • 2줄 왼쪽 — [전체 | 팀 ▾ | 랩 ▾] 세 칸 하나. 팀 7개·랩 1개는 ▾ 안으로. 칸마다 그 묶음의 안 읽은 합계와 결재 점.
  • 2줄 오른쪽 — 일하는 사람 칩만 + '+12명'.

좋은 점

  • 지금 쓰던 사람에게 가장 익숙하다. '전체'로 바로 돌아가기 쉽다.

대가

  • 여전히 두 줄. 방 고르기와 사람 칩이 같은 줄이라 폭이 좁으면 사람 칩이 밀려난다.
  • '팀 ▾'를 눌러야 어느 팀 방인지 고르므로, 지금 어느 방인지는 1줄 제목을 봐야 안다(두 군데를 본다).

기능 대응표 — 지금 있는 것이 어디로 가는지

없어지는 기능은 없다. 말이 바뀌는 곳만 굵게 적었다.

정해야 할 것

  • 확인 필요 꼬리표의 '랩' — 앱 전체에서 '랩'을 쓰므로 그대로 두었다. '프로젝트'처럼 바꾸려면 앱 전체 용어 결정이라 기획 확인이 필요하다.
  • 확인 필요 ⓘ 요약의 "랩장 정리드가 받아요" — 랩장·팀장이 없는 방은 지금 문구처럼 "알맞은 한 명이 받아요"로 바꿔야 한다(입력칸 받는 사람 문구와 같은 규칙).
  • '전체' 방에서 얼굴 묶음은 지금처럼 일하는 중·확인 필요·오류인 사람만 센다("13명" 대신 "고용 직원 N명").
