## 0. 한 줄 방향
**"이름표 붙은 값(토큰)을 새 테마 `retro`로 갈아끼우고, 모양은 새 CSS 파일 한 장에 모은다. 화면 파일 약 400곳은 건드리지 않는다."**
앱은 이미 카드·버튼·창이 `--shadow-soft`, `--radius-card`, `--focus-ring` 같은 값만 읽습니다(**확인**: `card.tsx`, `dialog.tsx`, `button.tsx`). 그래서 값만 바꿔도 모양의 대부분이 따라옵니다. 남는 일(글꼴·아이콘·직접 쓴 둥근 모서리)만 따로 처리합니다.

참고: 요청서는 "기존 테마 13종"이라 했지만 코드의 목록은 **10종**(기본 6 + 그라데이션 4, `UI_THEME_GROUPS`)입니다(**확인**). 색 블록도 10×2=20개입니다.

## 2. 색·테두리·그림자·버튼·아이콘·글꼴 — 파일과 방식

### 2-1. 새 파일 한 장: `renderer/retro.css` (읽는 사람이 "도트는 여기만 보면 된다"가 되게)
`index.css`에는 `@import './retro.css';` 한 줄만 더합니다(이유: `index.css`가 이미 1,000줄 넘고 v1.3.2가 같은 파일을 건드릴 수 있어 합칠 때 충돌이 납니다. 별도 파일이면 충돌 0). 안에 순서대로:
1. `@font-face` (3~4개)
2. 색 변수 `[data-theme='retro'][data-mode='light'|'dark']` — 시안 A의 값을 기존 토큰 이름으로 옮김
3. 모양 변수(테두리·그림자·모서리) — 두 모드 공통 한 블록
4. "토큰으로 안 되는 것" 덮어쓰기(아래 2-5)
5. 움직임 줄이기

### 2-2. 색 변수 (이미 있는 이름표에 값만)
시안 A 값 → 기존 토큰 대응(**확인**: 토큰 이름은 `index.css` 라벤더 블록 86~124줄과 시안 `--bg/--card/--fg…`를 대조해야 함, 정확한 1:1 표는 구현 첫날 표로 작성):
`--background`←bg, `--card`←card, `--foreground`←fg, `--muted-foreground`←muted, `--border`←line-soft, `--input`←input-line, `--primary(-foreground)`←pri, `--destructive`←bad, `--ring`←sel-line 등.
시안에만 있는 값(`--hi`밝은 줄, `--lo`어두운 줄, `--drop`그림자색, `--out`외곽선색, `--tile-a/b`바닥 타일)은 새 변수 `--px-hi/--px-lo/--px-drop/--px-out/--tile-a/--tile-b`로만 추가합니다.
- 그라데이션 변수(`--grad-primary`, `--grad-dialog-glow`, `--spark-from/to`)는 **단색으로**(`--grad-primary: var(--primary)`처럼) 덮어씁니다. 시안 규칙이 "그라데이션·번짐 없음"이고, 버튼·대화상자가 이 변수를 읽으므로 변수 4~5개만 바꾸면 끝입니다.
- 사무실(Phaser) 캔버스 색은 이 변수와 무관(**확인**: `index.css` 주석)이라 영향 없음.
- 창 배경 `WINDOW_BG`(`shared/uiTheme.ts`)는 모드별 2색만 있어 지금도 라벤더 근사입니다. 레트로 라이트(`#e8c79a`)·다크(`#1d1a2a`)와 달라 창 가장자리가 잠깐 라벤더로 보일 수 있습니다(**추정**). 1차에서는 그대로 두고, 거슬리면 `WINDOW_BG`를 테마별로 넓히는 일을 2차에 합니다.

### 2-3. 테두리·그림자 (시안의 "귀퉁이 한 칸 빠짐"을 값 하나로)
시안은 `box-shadow`를 네 방향 2px로 겹쳐 귀퉁이를 비웁니다. 이걸 **변수 하나**로 만듭니다:
```
--px-edge: 2px 0 0 0 var(--px-out), -2px 0 0 0 var(--px-out), 0 2px 0 0 var(--px-out), 0 -2px 0 0 var(--px-out);
--shadow-soft:   var(--px-edge), inset 2px 2px 0 0 var(--px-hi), inset -2px -2px 0 0 var(--px-lo), 4px 4px 0 0 var(--px-drop);
--shadow-dialog: (위와 같되 그림자 6px)
--shadow-primary:(위 + 버튼용 아래 받침)
--focus-ring:    0 0 0 2px var(--background), 0 0 0 4px var(--ring);   /* 도트 폭, 번짐 없음 */
```
카드·대화상자·기본 버튼이 이미 `shadow-(--shadow-soft)` 류를 읽으므로 **파일 수정 없이** 모양이 바뀝니다(**확인**).
- 시안은 그림자 6px + 바깥 여백(`margin 2px 6px 6px 2px`)으로 자리를 비웠지만, 실제 화면은 `overflow-hidden`·스크롤 칸 안에서 잘립니다(**추정**). 그래서 **4px로 줄이고 여백은 시안처럼 넣지 않습니다**. 잘리는 곳은 1차 검증에서 찾아 칸 안쪽 패딩으로 처리.
- 기존 `border`(1px, 약 `border` 클래스 다수)와 겹쳐 이중선이 되지 않게 `--border`를 외곽선과 같은 색 계열로 두고, 레트로에서만 `.border`류를 2px로 맞춥니다(2-5의 규칙 1개). 도트 칸이 2px 배수라는 원칙(`notes.md` 0장)을 지키기 위함입니다.
- 가로 줄(`border-b` 등 구분선)은 2px 실선, 점선은 4px 간격 — 시안 `.tool`·`.set-row` 그대로.

### 2-4. 버튼 — `button.tsx` 한 줄만
눌리는 버튼(받침 4px → 누르면 2px 내려감)은 `:active` 때문에 CSS로 충분하지만, 종류(기본·위험·테두리·보조·투명)마다 모양이 달라 **종류를 CSS가 알아야** 합니다. 지금 `Button`은 `data-slot="button"`만 있고 종류 표시가 없습니다(**확인**).
- 해결: `Button`에 `data-variant={variant}` 한 속성만 추가(모든 테마에 무해). 레트로 CSS는 `[data-slot=button][data-variant=default]` 같은 선택자로 모양을 줍니다.
- 안 하는 것: 버튼 클래스(cva)를 레트로용으로 갈라 `retro:` 변형을 400곳에 넣지 않습니다.
- 나머지 `ui/*`: `card`·`dialog`는 토큰만으로 해결. `input`·`select`·`textarea`는 `border`+`rounded-[var(--radius)]`라서 `--radius:0`이면 각지고, 테두리는 2-3 규칙으로 맞춤. `switch`·`badge`는 둥근 `rounded-full`을 쓰므로 2-5 규칙. 체크·선택 표시 `▶`는 2차(재미 요소)입니다.

### 2-5. 직접 쓴 둥근 모서리 처리 (약 400곳을 안 건드리는 법)
실제 사용을 센 결과(**확인**, `renderer/` 전체): `rounded-full` 130, `rounded-lg` 113, `rounded-md` 65, `rounded-xl` 62, `rounded-2xl` 8, `rounded-[…px]` 약 15, 그 밖 소수.
- `rounded-sm/md/lg/xl`은 `@theme inline`에서 `--radius`에서 계산한 값(**확인**: `index.css` 580~583줄)이라 레트로 블록에서 `--radius: 0px` + `--radius-sm/md/lg/xl: 0px`, `--radius-pill/card/hud/dialog: 0px`만 쓰면 **약 240곳이 자동으로 각집니다**.
- 남는 것은 값을 안 읽는 `rounded-full`(130), `rounded-2xl`(8), `rounded-[Npx]`(약 15). `retro.css`에서 `[data-theme='retro'] :is(.rounded-full, .rounded-2xl, [class*='rounded-[']) { border-radius: 0 }` **한 규칙**으로 처리합니다(스타일시트 규칙이 클래스 유틸보다 앞서므로 `!important` 불필요, **추정** — 구현 첫날 확인). 점·상태등·아바타가 네모가 되는 것은 시안(`--r-dot:0`)과 같습니다.
- 예외: 정원이어야 의미가 있는 것(스피너 등)은 `data-keep-round`를 달아 규칙에서 `:not()`으로 뺍니다. **처음부터 예외를 만들지 않고**, 1차 검증에서 깨진 것만 추가합니다.

### 2-6. 아이콘 — 두 갈래, 구현 크기가 다름
- **`DuoIcon`(자체 아이콘 21개, `DUO_ICON_DATA`, 24칸 선 그림)**: 시안의 10×10 도트 아이콘을 `duo-icon-data.ts`와 같은 모양의 새 데이터 `pixel-icon-data.ts`(`Record<DuoName, 10줄 문자열>`)로 만들고, `DuoIcon`이 레트로일 때만 이 데이터를 `<rect>` 격자로 그립니다. 판단은 `useStore(s => s.settings.uiTheme === 'retro')`(이미 있는 스토어 값, 설정을 바꾸면 즉시 반영). 이 컴포넌트는 `DuoName`이 **정해진 21개**라 데이터를 완전히 대체할 수 있고, 이모지→아이콘 자동 변환(`splitLeadingIcon`)도 그대로 씁니다.
- **lucide(약 75개 파일에서 import, 확인)**: 파일을 고치지 않고 CSS로 **"도트 느낌"만** 냅니다 — `[data-theme='retro'] svg.lucide { stroke-linecap: square; stroke-linejoin: miter; shape-rendering: crispEdges; stroke-width: 2 }` (lucide는 기본 `lucide` 클래스를 붙임 — **추정**, 구현 때 확인). 진짜 10×10 도트는 아닙니다. 자주 보이는 상위 ~10개(보내기, 닫기, 설정 등)만 2차에 `DuoIcon` 도트판으로 교체합니다.
- 이유: 75개 파일을 한꺼번에 도트로 바꾸면 v1.3.2 변경과 충돌하고 효과 대비 변경량이 가장 큰 항목입니다.

### 2-7. 글꼴 — 4번 참고(크기·소스), 5번 참고(대체 순서)
`--font-sans`(`index.css` 596줄 사용)를 레트로 블록에서 갈무리 우선으로 덮어쓰면 `body` 전체가 따라옵니다.

## 3. 글꼴 라이선스·용량

**라이선스**: 갈무리는 SIL OFL 1.1(**확인**: `fonts/OFL.md`, 저작권 Lee Minseo 2019–2025). 앱에 넣어 배포·판매되는 소프트웨어에 포함하는 것은 허용입니다. 지킬 것 3가지:
1. 저작권·라이선스 전문을 같이 배포 → `OFL.md`를 `app/` 안 글꼴 폴더에 그대로 두고, 앱의 오픈소스 고지 화면(있으면)에 이름·링크 추가. 고지 화면 위치는 **(미확인)**.
2. 글꼴 자체를 따로 파는 것은 금지(해당 없음).
3. 파일을 **수정(예: 부분 추출)하면 파생물**이라 이름 제한·같은 라이선스 유지가 따릅니다. 이 문서의 OFL 머리말에 "예약 글꼴 이름" 선언 줄은 보이지 않았지만(**확인**: 머리말 7줄 외 정의만 있음) 법적 확인은 안 했습니다 → **1차는 받은 파일 그대로**(수정 안 함).

**넣을 파일 (3개, 약 1.24MB)**
| 파일 | 크기(확인) | 쓰임 |
|---|---|---|
| `Galmuri14.woff2` | 565KB | 본문 15px(대화·긴 글·이름) |
| `Galmuri11.woff2` | 505KB | 라벨·버튼·표시 12px, 24px(제목) |
| `Galmuri11-Bold.woff2` | 167KB | 강조·버튼·제목 12/24px |
| ~~`Galmuri9.woff2`~~ | 430KB | **넣지 않음**(시안 A가 안 씀, 9는 12px보다 작아져 읽기 기준에 어긋남) |
→ 시안 폴더 4개(1.67MB) 대신 **약 1.24MB**. 앱 전체 설치 파일 크기 대비 비율은 현재 설치 파일 크기를 못 봐서 **(미확인)**.
- 14에는 굵은 글씨 파일이 없습니다. 앱에는 `font-medium/semibold` 클래스가 많아 그대로 두면 브라우저가 **가짜 굵게**를 만들어 도트가 번집니다. 레트로에서 `font-synthesis: none`을 걸고, 15px 본문은 굵게 쓰지 않으며 강조는 갈무리11 굵게(12/24px)로 합니다.
- 글꼴은 `@font-face`가 쓰일 때만 내려받습니다(기본 테마 사용자는 로딩 0, **추정**). 파일은 `renderer/assets/fonts/galmuri/`에 두고 CSS에서 상대 경로로 참조하면 빌드가 해시 이름으로 묶어 줍니다(데스크톱·원격·모바일 빌드 공통, **추정**).
- `font-display: swap`: 첫 페인트에 시스템 글꼴 → 도트로 바뀌는 깜빡임이 있을 수 있어, 첫 부팅 때 도트 테마라면 `<link rel=preload as=font>` 두 개(11, 14)만 추가를 권합니다(부팅 스크립트와 같은 이유).
- 부분 추출(예: 한글 2350자 + 영문)은 용량을 절반 이하로 줄일 수 있지만 위 3번 때문에 2차 이후 선택입니다.

## 4. 읽기 편한 글자 크기 · 대비 · 움직임

### 4-1. 12 / 15 / 24px 만 쓰는 방법 (화면 파일을 안 고치고)
지금 앱의 글자 크기 사용(**확인**): `text-xs`(12px) 약 572회, `text-sm`(14px) 약 213회, `text-[11px]` 167회, `text-[10px]` 72회, 그 밖 `text-[13px]` 6·`[14px]` 2·`[15px]` 1·소수점 크기 3, `text-base` 13, `text-lg` 8, `text-xl/2xl` 14.
- 타일윈드 글자 크기는 변수(`--text-xs`, `--text-sm`…)를 읽습니다(타일윈드 4 기본 동작, **추정** — `@theme inline`은 색·모서리에만 쓰였고 글자 크기는 해당 없음). 레트로 블록에서 이름표만 바꿉니다:
  `--text-xs: 12px` · `--text-sm: 15px` · `--text-base: 15px` · `--text-lg: 24px` · `--text-xl: 24px` · `--text-2xl: 24px`(+각 `--text-*--line-height`).
- `text-[10px]`·`[11px]`·`[9.5px]`·`[10.5px]`·`[11.5px]`(약 240곳)은 12px로, `[13px]`·`[14px]`는 15px로 올리는 속성 선택자 규칙 몇 줄(`[data-theme='retro'] [class*='text-[11px]']`…). 12px 미만으로 남기지 않습니다.
- 12px 올림으로 **좁은 칸 줄바꿈·잘림이 생깁니다**(직원 카드 보조줄, 배지 등). 이것이 가장 큰 화면 확인 대상입니다(7번 위험).
- 글꼴 배정: 12px·24px → 갈무리11(+굵게), 15px → 갈무리14. 크기에 따라 글꼴을 가르려면 `font-size` 선택자가 필요하므로, 본문 `font-family`는 **갈무리14 기본, `.text-xs`류(12px 변수 사용처)만 갈무리11**로 가르는 규칙 2개로 시작합니다. 갈무리14를 12px로 쓰면 도트가 어긋나기 때문입니다(`notes.md` 4장).
- 긴 글(대화·보고서, `components/markdown.tsx`): 레트로에서 `line-height: 1.75`, 단락 간격 크게. 코드 칸·표는 갈무리11 12px 고정.

### 4-2. 기존 '글자 크기' 설정과의 관계
앱 전체 글자 크기 설정은 **없습니다**(**확인**: 글자 크기는 직원 패널의 "업무 기록·지시 입력" 5단계 `LOG_FONT_SIZES=[12,13,14,16,18]`뿐, `StaffPanel.tsx:110`, 저장 키 `office:logFontSize`).
- 레트로일 때 이 선택지를 `[12, 15, 24]` 3단계로 바꾸고, 저장값(픽셀)이 목록에 없으면 가장 가까운 값으로 맞춥니다. 이미 `indexOf`로 못 찾으면 기본값으로 가는 구조(`StaffPanel.tsx:117`)라 3줄 정도의 변경입니다. 이 파일은 v1.3.2 수정 중이므로 개편 이후.
- 즉 "글자 크기 설정이 도트와 충돌"하는 범위는 이 한 곳입니다. 그 밖 화면에는 사용자가 고르는 크기가 없어 충돌이 없습니다.

### 4-3. 대비 4.5 기준
- 시안의 6가지(3안×라이트·다크)는 본문·보조·버튼·배지·알림이 4.6 이상으로 **자동 계산됐다고 문서에 기록**돼 있습니다(`notes.md`; 계산 화면 `?view=contrast`). 이 값을 구현에서 그대로 쓰되, 아래를 **자동 검사**로 못 박습니다:
  - `app/scripts/`에 있는 기존 시험 파일(`*.test.mts` 방식, **확인**)처럼 `retroContrast.test.mts`를 만들어 `retro.css`의 색 쌍(본문/바탕, 보조/바탕, 버튼 글자/버튼 바탕, 배지, 경고, 링크, 선택 행)을 읽어 4.5 미만이면 실패. 이유: 색 하나만 고쳐도 조용히 깨지는 값이라 눈 확인으로는 놓칩니다.
- 시안이 이미 밝힌 약점: 다크는 테두리와 카드의 대비가 1.5~1.8로 낮습니다(**확인**: `notes.md`). A는 안쪽 밝은 줄(`--px-hi`)로 경계를 보강. 구현 후 실제 화면에서 경계가 구분되는지 눈으로 확인.
- 비텍스트(테두리·포커스)는 3:1 목표. 포커스 링은 바탕 2px + `--ring` 2px의 이중 선이라 어느 바탕에서도 보입니다.

### 4-4. 움직임 줄이기
- 지금 앱은 **시스템 설정**(`prefers-reduced-motion`)을 읽고(**확인**: `lib/reducedMotion.ts`, 맥 '동작 줄이기'·윈도우 '애니메이션 끄기') 앱 자체 스위치는 없습니다. 이 방식을 그대로 따릅니다. 새 설정을 만들지 않습니다.
- 레트로의 움직임은 3가지뿐이라 `retro.css` 끝에 `@media (prefers-reduced-motion: reduce)`로 모두 끕니다: ① 직원 말 `▼` 깜빡임 ② 버튼 눌림 이동 `transition` ③ (있다면) 선택 `▶`의 흔들림. 정지 상태에서도 의미(선택됨, 눌림)는 색·받침 변화로 남게 둡니다.
- 깜빡임은 1초에 1번(`steps(1)` 1s)으로 "초당 3회 이하" 기준 안에 둡니다.

## 5. 영어·일본어·중국어 — 도트 글꼴에 글자가 없을 때

**현재 상태**: 갈무리는 한글·영문이 있는 것은 확인되지만(시안이 한글 화면을 그림), **일본어 가나·한자, 중국어 간체·번체 한자가 얼마나 들어 있는지는 확인하지 못했습니다**(**미확인**; 이 PC에 글꼴 분석 도구(fontTools)가 없어 목록을 뽑지 못함. `notes.md`도 같은 한계).

**대체 순서 (글자 하나 단위로 빠진 글자만 다음 글꼴로 넘어감, 브라우저 기본 동작)**
- 공통: `Galmuri14`(또는 11) → 언어별 시스템 글꼴 → `sans-serif`
- 한국어: → `Apple SD Gothic Neo`(맥) / `Malgun Gothic`(윈도우) / `Noto Sans KR`(안드로이드)
- 일본어: → `Hiragino Sans`·`Hiragino Kaku Gothic ProN`(맥) / `Yu Gothic UI`·`Meiryo`(윈도우) / `Noto Sans CJK JP`(안드로이드)
- 중국어(간체): → `PingFang SC`(맥) / `Microsoft YaHei UI`(윈도우) / `Noto Sans CJK SC`(안드로이드)
- 영어: 갈무리 라틴 → 같은 시스템 기본 글꼴(`-apple-system`, `Segoe UI`)
- 언어별 순서는 `:lang(ja)`·`:lang(zh)` 선택자로 갈라야 같은 한자가 일본식·중국식으로 맞게 보입니다. 앱이 `<html lang>`을 언어 설정에 맞춰 바꾸는지는 **(미확인)**(첫 시도에서 파일 검색이 실패해 못 봄). 안 바꾼다면 `lib/uiTheme.ts` 근처에서 `documentElement.lang = settings.language` 한 줄을 더해야 합니다.
- 번체(zh-TW)는 앱 언어에 없어 보임(`names.ts`/dict에 ko/en/ja/zh 4개, **확인**) → 간체만.

**구현 전 확인(필수, 반나절)**: 임시 폴더에서 `python3 -m venv` + `pip install fonttools brotli`로 세 글꼴의 지원 글자 목록을 뽑고, i18n 사전 전체(ko/en/ja/zh 문자열)에 쓰인 글자와 대조해 **빠진 글자 수·목록을 언어별로 표로 남깁니다.** 빠진 글자가 거의 없으면 위 순서는 안전망일 뿐이고, 많으면(특히 zh) **그 언어에서는 본문을 시스템 글꼴로 두고 도트는 숫자·라벨에만**이라는 조건부 규칙(`:lang(zh)`)이 필요합니다. 이 결과를 보고 정하는 것이 맞아서, 지금 결정은 "순서까지"만 확정합니다.
- 한 줄 안에서 도트와 시스템 글꼴이 섞이면 높이·폭이 어긋납니다. `font-size-adjust` 없이 허용하고, 사용 빈도 높은 문장(버튼·메뉴 라벨)에서 빠지는 글자가 없는지가 합격 기준입니다.

## 6. 플랫폼별 적용 범위 · 윈도우 배율

| 대상 | 적용 | 근거·비고 |
|---|---|---|
| **맥 (데스크톱 창)** | 그대로 | 가장 기준. 레티나 배율 2배라 2px 도트가 4px 정수 → 선명 |
| **윈도우 (데스크톱 창)** | 그대로 + 아래 배율 처리 | `<html data-platform="win32">`로 구분(**확인**), 신호등 대신 창 버튼 겹침(`main/index.ts:246`) 위치는 도트와 무관 |
| **안드로이드 앱 / 원격 웹 화면** | 같은 CSS를 씀 | `remote.html`, `mobile.html`이 같은 `renderer/main.tsx` 진입을 씀(**확인**: `remote/main.tsx`, `mobile/main.tsx`가 `../main`을 임포트). 그래서 `retro.css`가 자동으로 같이 들어갑니다. 이유: 별도 파일 복사 불필요 |
| 폰 크기(`data-layout=phone`) | 같은 규칙 + 점검 | 12px 올림·본문 15px로 폭이 좁아져 **폰에서 줄바꿈이 가장 위험**. 폰 전용 점검 필요 |
| 사무실 지도(Phaser) | **변화 없음** | 캔버스 색은 이 토큰과 무관 |
| 바탕화면 비서 창(`.pet-panel`) | 토큰 상속, 점검 필요 | 같은 CSS 변수 사용(`index.css` 622줄 부근, **확인**), 작은 글자가 많아 4.5 점검 |

- 원격 CSP는 `font-src 'self' data:`(**확인**: `remote.html`, `mobile.html`). 글꼴이 같은 출처의 번들 파일이면 허용입니다 → **외부 CDN 주소는 쓰지 않습니다**(시안 HTML은 jsdelivr 폴백이 있지만 앱에는 넣지 않음). 원격 서버가 글꼴 파일을 정적으로 같이 내보내는지는 **(미확인)**, 1차 검증 항목.
- 모바일 앱(안드로이드 설치 파일)은 글꼴 약 1.24MB가 번들에 늘어납니다.
- 원격에는 uiTheme를 바꿀 권한이 없고 PC 값을 따라가므로(**확인**) 폰에서 켜고 끄는 UI는 만들지 않습니다.

**윈도우 배율 125% / 150%** (추정 — 실제 윈도우 화면 확인은 못 했음)
- 문제: 2px가 2.5·3 기기 픽셀이 됩니다. 테두리(`border`)는 Chromium이 정수 기기 픽셀로 맞춰 주지만 `box-shadow`로 그린 외곽선은 맞춰 주지 않아 가장자리 굵기가 들쭉날쭉하거나 흐릴 수 있습니다.
- 처리: **도트 1칸을 변수 `--dot`으로** 두고 시안의 모든 `2px`를 `calc(var(--dot) * 1)`로 씁니다. `--dot`은 `lib/uiTheme.ts`에서 `round(2 × devicePixelRatio) / devicePixelRatio`로 계산해 `<html>`에 설정(125% → 3기기px = 2.4 CSS px, 150% → 3기기px = 2 CSS px, 100%·200% → 2 CSS px). 모니터를 옮겨 배율이 바뀌면 `matchMedia('(resolution: …)')`로 다시 계산. 코드는 10줄 내외이고, 값 하나로 모든 도트 폭을 정수 기기 픽셀에 맞추는 가장 단순한 방식입니다.
- 글자는 CSS px 크기를 못 바꾸므로(12px → 125%에서 15기기px는 갈무리11의 정수배가 아님) **윈도우 125·150%에서는 갈무리 글자가 조금 부드럽게(흐리게) 보일 수 있습니다. 이건 막을 수 없는 한계로 기록**하고, 실제 윈도우 화면에서 눈으로 읽을 수 있는지가 기준입니다. 맥은 정수배라 해당 없음.
- 2차에 "도트 글꼴만 끄기"(8번)가 있으면 윈도우 125%에서 불편한 사용자의 출구가 됩니다.

## 8. 이 안의 한계 (단순함의 비용)
- **CSS 한 장으로 직접 쓴 클래스를 덮는 방식**은 "왜 이 화면만 이렇게 보이지?"를 추적하기 어렵게 할 수 있습니다(예: 속성 선택자 `[class*='text-[11px]']`). 규칙마다 한 줄 주석(어떤 클래스를 겨냥하는지)을 달고, 선택자는 15개 이내로 유지합니다.
- 속성 선택자·유틸 클래스 덮어쓰기는 앞으로 새 클래스(`text-[12.5px]`)가 생기면 빠집니다. 그래서 4-1의 "허용 크기 전수 점검 스크립트"를 시험에 넣는 것이 중요합니다(검증 가능성).
- 이 안은 `button.tsx`·`DuoIcon` 외 화면 파일을 거의 수정하지 않는 대신, **되돌리기 쉽고 한눈에 읽히는 대신 도트 완성도(귀퉁이 처리 균일성, lucide 아이콘)는 시안보다 약간 낮습니다.** 완성도 100%가 필요하면 2차에서 화면별 도트 전용 클래스(`retro:`)를 선택적으로 늘리는 방식이 필요합니다.
- 글꼴 라이선스 고지의 적정성, 모바일 번들 용량 영향은 확인하지 못했습니다.
