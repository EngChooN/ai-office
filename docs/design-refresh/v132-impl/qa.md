## 결론
**실패 3건, 확인 못 한 것 6건, 나머지 통과.** 코드는 건드리지 않았습니다.

## 환경·한계 (정직하게)
- 개발 앱: `qa-start.sh start ocue --cdp 9461 --vite 5191`, 마지막에 stop.
- **스크린샷은 못 찍었습니다.** 이 셸은 화면 접근이 막혀 있습니다(`screencapture`는 "could not create image from display", CDP `Page.captureScreenshot`은 응답 없음). 그래서 `qa-shots/`에는 그림 대신 화면 글자·배치 수치 기록(`dom-scan-words-overflow.txt`)과 조작 스크립트(`scripts/`)를 넣었습니다. **색(노랑·빨강 버튼, 배지 색)과 눈으로 보는 모양은 확인 못 했습니다.**
- 폭 1400/1100/900은 CDP 창 크기 흉내(Emulation)로 봤습니다. 라이트·다크는 `data-mode`를 바꿔 봤고, 실제 설정 화면으로 바꾼 건 아닙니다.
- 시험용 데이터는 `~/claude-office-qa-ocue`의 기존 직원 17명(내 직원 7명·다른 창 직원 10명). 확인 기다림·오류·일하는 중인 내 직원이 없어서 해당 상태 시험은 코드로만 봤습니다.

## 실패 상세와 재현
1. **팀 구성 제목 "조직도"** — 직원 → [팀 구성] → 맨 위 제목. 원인 추정: 사전 키 `org.title`이 아직 '조직도'(`shared/i18n/dict/featuresB.ts:1053`). 시안 용어는 "팀 구성".
2. **카드의 "지금 하는 일: 작업 중"** — 직원 목록에서 "다른 창 직원" 카드(예: pc-2311001-36, 일하는 중). 원인 추정: 다른 창 직원의 활동 글이 `external.working`('작업 중')이고 `nowLine`이 그 글을 그대로 보여 줌(`shared/staffCard.ts`의 `clip(staff.activity)`). 기대: 쉬운 말 문장.
3. **사무실 "작업 중 3"** — 사무실 화면 위쪽 숫자 줄. 사전 키 `map.stat.working`('작업 중'). 앱 전체 상태 이름 표에서 '일하는 중'으로 가야 하는지 정리드 확인 필요.

## 그 밖에 발견한 것
- 소개 탭 "결재 방식" 아래 문구 "일마다 결재를 받을지는 **장비** 탭에서 정해요." — 탭 이름이 '도구'로 바뀌어 문구가 틀림(남은 옛 말).
- 업무 지침 저장 안내 "지금까지의 대화는 이어져요"는 코드(저장 → 다음 지시 때 같은 대화를 새 설정으로 이어서 열기)와 맞음. 그런데 `design-final.md`는 "대화를 새로 시작"이라고 적혀 있어 **설계 문서 쪽이 어긋남**(화면은 맞음).
- 상점 화면 1곳(1400·1100·900), 대화 화면 900폭에서 2곳에 "글자가 칸 밖으로 넘치는 요소"가 있음. 영향은 눈으로 못 봄(`dom-scan-words-overflow.txt`). v1.3.1에서도 있었는지는 모름.
