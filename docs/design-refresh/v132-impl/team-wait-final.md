# 리더 '팀원 일 기다리는 중' — 정리드 최종 결정 (2026-11-13)

입력: `team-wait-choi.md`, `team-wait-park.md`. 두 안의 뼈대(상태는 idle 그대로 + 화면용 보조 칸, 판정은 `shared/delegation.ts` 순수 함수, `checkStall`도 같은 함수 사용, `liveStaff`에서 채움, 새 status·hired.ts 수정·프로토콜 변경 안 함)가 같아 그대로 채택.

## 채택
| 쟁점 | 결정 | 이유 |
|---|---|---|
| 칸 모양 | 박: `awaitingTeam?: boolean` | 화면은 있음/없음만 쓴다. 건수는 겹쳐 세어져 믿기 어렵다(최 안도 "있음/없음이 핵심") |
| 판정 함수 | 박: `hasOpenDelegation(input)` + 공용 `isAwaitingTeam(staff)` | 판정 한 곳. 화면은 `isAwaitingTeam`만 부른다 |
| 기획안 결재 대기 | 두 안 같음: 넣지 않음 | 대표 결재 표시가 따로 있다 |
| 집계·필터 | 최: '일하는 중'으로 셈, `countByStatus`·`matchesStaffFilter`·지도 숫자 모두 같은 함수 | 카드는 '기다리는 중'인데 요약은 '쉬는 중'이면 같은 화면에서 말이 갈린다(제보의 핵심). 필터도 같이 바꿔 어긋남 없음 |
| 상태 점·글자 | 최: renderer `statusMetaOf(staff)` 한 함수(일하는 중 색 + '팀원 기다리는 중') | 카드·패널·대화방 목록이 같은 말 |
| 책상 그림 | 박: 장면에 넣을 때 working으로 바꿔 넣음(자리에 앉아 일하는 모습 재사용), 말풍선 정보창은 '팀원 기다리는 중' | 장면 안 `status==='idle'` 10여 곳을 하나씩 고치지 않음. 돌아다니거나 다른 층에 놀러 가지 않음 |
| team 도구 | `idle` 뒤에 "(팀원 일 기다리는 중)" | 실제 상태(idle)는 그대로 알려 주고 사정을 덧붙임 |
| 라우팅·멘션 정렬·큐 | 그대로 idle | 리더는 실제로 쉬는 중이라 새 지시를 받을 수 있다 |

## 채택하지 않은 주요 제안
- 최: `waitingOn` 건수 — 위 이유.
- 최: 책상에서 앉아만 있고 일하는 모습은 안 함 — 장면 판정이 흩어져 있어 고칠 곳이 많아짐.
- 박: 집계 합산 안 함(권장안) — 요약과 카드가 갈림.

## 남는 한계
- 휴대폰 앱은 이번에 표시하지 않음(칸은 넘어가지만 앱이 아직 읽지 않음).

## 구현 중 바꾼 점 (한리뷰 검토 반영, 정리드)
- **'맡긴 카드' 기준을 좁힘**: 팀원 담당 카드 전부 → *리더 업무의 하위 업무(parentId)* 만. 대표가 보드에서 팀원에게 직접 준 카드가 남아 있으면 리더가 영영 '기다리는 중'으로 보이던 문제. 팀원 업무 줄(taskQueue) 개수도 같은 이유로 빼고 카드 판정에 맡김(줄 선 카드도 todo 카드). `checkStall` 독려도 같은 함수라 같이 좁아짐 — 대표가 직접 준 카드는 리더 독려를 막지 않음.
- **성능**: 맡길 사람·다른 PC 일이 없는 직원은 카드를 훑지 않음.
- **이모트**: 리더 차례가 끝날 때 ✅가 안 뜨고, 팀원 일이 끝나 '대기'로 돌아올 때 뜸 — 리더 일이 실제로 끝나는 시점이라 그대로 둠.
- **같은 기준 추가 적용**: 대화방 머리 'n명 일하는 중'(summarizeRoomPeople), 바탕화면 비서 'n명 일하는 중'(petWorkingCount).
