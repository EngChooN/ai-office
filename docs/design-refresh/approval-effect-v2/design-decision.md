# 최종 설계 결정 — 결재 카드 '효과 줄' 2차 (정리드, 2026-11-12)

> 비교 대상: 설계안 A `design-readable.md`(최가독), 설계안 B `design-pattern.md`(박패턴). 구현은 정리드가 한다. 1차 결정 `../approval-effect-decision.md`의 원칙(애매하면 만들지 않는다, 허용 판정에는 쓰지 않는다, 경로는 자르지 않는다)은 그대로 둔다.

## 확인한 사실 (두 안의 '미확인' 정리)
- 원격 웹(`remote.html`·휴대폰 화면)은 데스크톱과 같은 React 앱이고, 스냅샷의 `staff.approvals`를 `InboxPage`→`ApprovalSummary`로 그린다. 그래서 **원격 웹은 `ApprovalSummary`를 고치면 같이 바뀐다.**
- `protocol.ts approvalDecision`(`/v1/decisions`)은 안드로이드 앱 전용 옛 API다. 효과 줄을 보이려면 Kotlin 화면도 고쳐야 해서 이번 범위에서 뺀다(임안드 후속 후보).
- 비서 패널(`SecretaryChat`)에는 결재 카드가 없다(B 확인). 변경하지 않는다.
