# 매뉴얼 이름 분리(한글 표시 이름) 가능성 조사

- 작성: 정리드 · 2026-11-12
- 방법: 코드만 읽음. 수정·커밋 없음.
- 결론: **분리할 수 있다.** 내부 이름(영문 슬러그 = 스킬 폴더명 = `name`)은 지금 그대로 키로 쓰고, 한글 표시 이름은 SKILL.md 프론트매터에 추가 필드로 둔다. 기존 매뉴얼은 표시 이름이 없으면 슬러그를 그대로 보여 주면 되므로 옮겨 쓰기(마이그레이션)가 필요 없다. 직원 0명 AI 초안도 main 쪽 몇 줄만 고치면 된다.

---

## 1. 표시 이름을 어디에 저장할까

### 지금 구조
- 매뉴얼 = `~/.claude/skills/<name>/SKILL.md` 또는 `<프로젝트>/.claude/skills/<name>/SKILL.md` (`main/manuals.ts`).
- 프론트매터: `name`, `description`, (여러 명 업무면) `kind: process`. 단계는 본문 끝 `office-process` JSON 블록.
- `parse()`는 프론트매터를 키-값으로 다 읽지만 `name·description·kind`만 꺼낸다. `name`이 없으면 폴더명을 쓴다.
- 이름 규칙 `^[a-z0-9][a-z0-9-]{1,62}$`이 세 곳에 있다: `main/manuals.ts:11`, `renderer/features/ManualsPage.tsx:20`, `shared/staffPack.ts:32`.

### 후보 비교

| 후보 | 장점 | 단점 | 판단 |
|---|---|---|---|
| **A. 프론트매터 최상위 `title:`** | 파서 수정 1줄, 읽기 쉬움 | 스킬 표준(Agent Skills) 필드가 아님. Claude Code·Codex는 모르는 키를 무시하므로 동작은 문제없음 | **추천** |
| B. 프론트매터 `metadata:` 아래 `display-name:` | 표준이 허용하는 확장 자리 | 지금 파서는 들여쓴 하위 키를 못 읽음(정규식이 `^키:`만 봄) → 파서 확장 필요 | 대안 |
| C. `description` 맨 앞에 붙이기 | 파일 형식 변경 0 | 직원이 언제 쓸지 판단하는 문장이 오염됨, 다시 떼어 내는 규칙이 깨지기 쉬움 | 기각 |
| D. 앱 DB에 따로 저장 | 파일 안 건드림 | 프로젝트 매뉴얼은 git·기기 간 동기화(`main/peer/sync`)로 파일째 옮겨 다니는데 DB 값은 안 따라감. 다른 PC·휴대폰에서 이름이 사라짐 | 기각 |

→ **A 추천.** 파일과 함께 다니고, 파서·저장 함수 수정이 가장 적다. 값은 `description`처럼 `JSON.stringify`로 감싸 따옴표·콜론을 안전하게 저장한다. 표준 준수가 꼭 필요하다고 판단되면 B로 바꿔도 나머지 설계는 같다.

### 기존 매뉴얼 호환
- `Manual`·`ManualInput`에 `title?: string` 추가(선택 필드).
- 읽을 때 `title`이 없으면 화면은 `name`(슬러그)을 보여 준다 → 기존 매뉴얼은 손대지 않아도 그대로 동작.
- 기존 매뉴얼을 고쳐 저장할 때도 `title`이 비어 있으면 프론트매터에 쓰지 않는다(쓸데없는 파일 차이 방지).

### 내부 이름(슬러그) 만드는 규칙
- 사용자는 한글 표시 이름만 입력. 슬러그는 "고급(자세히 설정)"에서만 보이고 고칠 수 있다.
- 만드는 순서: ① AI 초안이면 초안이 주는 `name`(지금도 영문 슬러그를 돌려줌) ② 표시 이름에 영문·숫자가 있으면 그걸 소문자·하이픈으로 ③ 그 외(한글만)는 `manual-<짧은 무작위 6자>`.
  - 한글→로마자 변환은 라이브러리·규칙 부담에 비해 이점이 작아 넣지 않는다. 직원이 스킬을 고르는 근거는 이름보다 `description`이다.
- 중복: 저장 직전에 같은 폴더가 있으면 `-2`, `-3`… 붙임. 지금 `saveManual`은 중복이면 오류를 던지므로, 자동 생성한 슬러그일 때만 번호를 붙이는 함수를 `manuals.ts`에 둔다(사용자가 직접 고친 슬러그는 지금처럼 오류).
- **이름 바꾸기 = 표시 이름만 바꾸기.** 슬러그는 고정. 지금은 이름을 바꾸면 폴더가 옮겨지는데, 직원 장비(`equipment.skills`)·랩/팀 `manuals`가 옛 이름을 그대로 들고 있어 **교육 연결이 끊기는 기존 결함**이 있다(`office.saveManual`이 참조를 갱신하지 않음). 분리하면 일반 사용자는 슬러그를 바꿀 일이 없어 이 문제가 사실상 사라진다. 고급에서 슬러그를 바꾸는 경우를 위해 참조 갱신을 같이 넣을지 결정 필요(아래 4. 위험).

## 3. 직원 0명일 때 AI 초안이 막히는 조건

### 막히는 곳 (두 군데)
1. 화면: `ManualsPage.tsx:177` `{staff.length > 0 && (...)}` — 직원이 없으면 초안 상자 자체를 그리지 않는다.
2. main: `office.ts:3171 draftManual(staffId, …)` — `this.hired.get(staffId)`가 없으면 `'직원을 찾을 수 없어요.'`로 실패. 직원의 `cwd`·`model`·`name/role/systemPrompt`를 프롬프트에 쓴다. `recordUsage(staffId, r)`로 직원 사용량에 기록.

### 풀 수 있다 — 근거
- `askOnce`(`main/ai/index.ts:38`)는 직원 없이도 부를 수 있다. 이미 직원 없이 부르는 곳이 있음: 비서 자동 판정(`secretary.ts:699`, `cwd: userData`, 사용량은 `SECRETARY_ID`로 기록), 명령 설명 번역(`office.ts:1220`, `cwd: os.homedir()`).
- 수정안: `staffId`를 빈 문자열 허용(시그니처는 그대로 `string` → 타입·원격 `R('s s s')`·비서 도구 인자 형식 변경 없음).
  - 직원이 있으면 지금과 같다.
  - 없거나 `''`이면: `cwd: os.homedir()`, `model` 생략(앱 기본), 시스템 문구는 "회사 매뉴얼 작성 도우미", 사용량은 `db.insertUsage(SECRETARY_ID, …)`처럼 비서 몫으로 기록.
  - 직무 목록(`roles`)이 비면 "기획자·디자이너·개발자·리뷰어·QA" 같은 기본 직무 예시를 넣는다(지금은 빈 문자열이 들어가 단계 role이 엉망이 될 수 있음).
- 화면: 초안 상자를 항상 보이게, 직원 선택은 "자세히"로 내리고 기본값 "앱이 바로 만들기(직원 없이)".
- 초안 JSON에 `title`(한글 표시 이름)도 달라고 요청 → 3갈래 중 "말로 설명해서 만들기"와 바로 연결된다.
- 사용량 귀속: 비서 몫으로 잡을지, 별도 "앱" 항목을 둘지는 작은 정책 결정(추천: 비서 몫, 이미 있는 방식).

### 위험
1. **원격 허용 필드 누락** — 가장 조용한 실패(휴대폰에서 저장 시 표시 이름 사라짐). 원격 테스트(`scripts/remote-v2.test.mts`)에 `title` 통과 확인 추가로 막는다.
2. **고급에서 슬러그를 바꿀 때 교육 연결 끊김** — 지금도 있는 결함. 선택지: (a) 슬러그 변경 시 장비·랩·팀 참조를 새 이름으로 바꿔 주기(`office.saveManual`에 10줄 내외), (b) 이미 만든 매뉴얼은 슬러그를 못 바꾸게 하기. **추천 (b)** — 단순하고 실행 중인 업무(`ProcessRun.manualName`)까지 신경 쓸 필요 없음.
3. **진행 중인 워크스페이스 작업과 충돌** — 지금 `remote/v2.ts`·`ManualsPage.tsx`·i18n 사전이 수정 중(커밋 전). 구현은 그 작업이 커밋된 뒤 시작해야 한다.
4. **Claude Code 쪽 표시** — Claude Code 자체 스킬 목록(`/` 메뉴 원본)은 프론트매터 `name`(슬러그)을 쓴다. 앱 메뉴는 우리가 표시 이름으로 바꾸지만, 터미널에서 직접 Claude Code를 쓰면 슬러그로 보인다. 받아들일 만함.
5. **표시 이름 중복** — 같은 한글 이름 둘이 생길 수 있음(슬러그는 다름). 목록에서 헷갈리지 않게 슬러그를 작은 글씨로 함께 표시하면 충분.
