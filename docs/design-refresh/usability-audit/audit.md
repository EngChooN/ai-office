# 비개발자 사용성 정밀 분석

- 작성: 김기획 (PM) · 2026-11-12
- 배경: 대표 의견 — 비개발자는 아직 앱이 어려워 모든 기능을 못 쓴다.
- 범위: 매뉴얼 화면 상세 분석 + 주요 8개 화면 진단. 설정·장비 탭은 `../settings-simplify/`에서 이미 다뤄 제외.
- **확인 방법: 전부 "코드로만 확인"이다.** 앱을 직접 실행해 보지 않았고, 화면 코드(`app/src/renderer/features/*.tsx`)와 한국어 사전(`app/src/shared/i18n/dict/*.ts`)만 읽었다. 실제 사용 빈도·막힘 지점은 데이터가 없어 "확인 필요"로 둔다.
- 코드는 수정하지 않았다.

## 1부. 매뉴얼 화면 정밀 분석

대상: `ManualsPage.tsx` (목록 → 매뉴얼 추가·수정 창 `ManualEditor` → 교육 창 `TrainDialog`)

### 1-1. 화면 흐름 순서대로 본 막힘 지점

| # | 흐름 | 비개발자가 막히는 지점 | 근거 | 심각도 |
|---|---|---|---|---|
| 1 | 매뉴얼실 첫 진입 | 매뉴얼이 뭔지 설명이 "직원이 일하는 순서를 적은 문서(AI 쪽 이름: 스킬)" 한 덩어리 문단뿐이다. 빈 목록은 "아직 없어요." 한 줄이라 **다음에 뭘 누를지 안내가 없다.** 다른 화면에 있는 빈 화면 안내(GuideHint)가 여기엔 없다. | `manuals.description`, `manuals.empty`; 파일에 `guideHint` 사용 없음 | 높음 |
| 2 | 상단 버튼 두 개 | "+ 개인 매뉴얼" / "+ 단계 진행 매뉴얼" — **둘의 차이를 버튼 앞에서 알 수 없다.** 설명은 페이지 설명문 속에만 있다. "단계 진행"은 업무 용어가 아니고, 개인·단계진행이 "한 사람 vs 여러 사람 릴레이"라는 구분이 처음 사용자에게 안 보인다. 단계 진행(주 버튼)이 먼저 눈에 띄는데 더 복잡한 쪽이다. | `manuals.kind.*`, 버튼 2개 | 높음 |
| 3 | 새 매뉴얼 창 열림 | 창 하나에 **항목 7개 이상이 한꺼번에** 나온다: 초안 → 이름 → 저장 위치 → 언제 쓰는지 → 공통 안내/절차 → 단계(반복) → 저장. 위계 구분 없이 모두 필수처럼 보인다. | `ManualEditor` 전체 | 높음 |
| 4 | "✨ 직원에게 초안 맡기기" | 말로 설명하면 AI가 만들어 주는 **가장 쉬운 길이 창의 첫 칸이긴 하지만 눈에 안 띈다**(회색 상자, 작은 글씨 `text-xs`, 높이 h-8). 직원 선택 드롭다운이 먼저 나와 "누구에게?"를 고르게 한다. **직원이 0명이면 이 상자가 통째로 사라진다**(`staff.length > 0`일 때만 표시) — 신규 사용자는 대부분 직원이 없거나 한두 명이라 가장 필요한 순간에 도구가 없다. 초안 버튼 이름도 "초안"이라 누르면 아래가 덮어써진다는 경고가 없다(`update({...d})`로 입력한 내용을 덮어씀). | `staff.length > 0`, `handleDraft` | 높음 |
| 5 | **이름 입력** | "이름 (영문 소문자·숫자·-)" — **한글로 쓰면 글자가 전부 `-`로 바뀐다**(`replace(/[^a-z0-9-]/g,'-')`). 예: "버그 리포트" → `------`. 비개발자에게 가장 큰 벽. 오류 문구도 없이 저장 버튼만 비활성이다. 이 제한은 파일명·AI 호출명 때문이지 사용자 가치가 아니다. | `nameLabel`, `NAME_RE`, onChange | **매우 높음** |
| 6 | 저장 위치 | "내 계정 (모든 프로젝트에서 사용)" vs "프로젝트 · {경로}" + "폴더…" 버튼. 비개발자는 "프로젝트", 경로, 계정 범위가 무슨 뜻인지 모른다. 기본값이 `projectDirs[0]`(첫 직원 폴더)라 **의도 없이 특정 프로젝트 폴더에 저장**될 수 있다. 맞는 답이 대부분 "전부에서 쓰기"인데 기본이 아니다. | `emptyInput`, `location*` | 높음 |
| 7 | "언제 쓰는지 (설명)" | 라벨은 쉬우나 왜 필수인지 모른다("직원이 이 설명을 보고 판단해요"는 placeholder라 입력하는 순간 사라진다). 비어 있으면 저장이 막히는데 이유 표시 없음. | `descriptionLabel/Placeholder`, `isValid` | 중 |
| 8 | "공통 안내(선택)" / "절차·주의점" | 개인은 **마크다운 번호 목록을 직접 쓰게** 한다(placeholder `1. …`, 고정폭 글꼴). "공통 안내"가 단계 진행에선 무엇인지 예시가 없다. | `bodyProcess/Personal` | 중 |
| 9 | 단계 행(단계 진행) | 한 줄에 단계 이름 + **"맡을 역할"(자유 입력)** + 위/아래/삭제 + 지시문 + 체크박스 + 드롭다운 + 숫자까지 **단계당 입력 5개 이상.** 단계 3개면 15개 이상. "역할"이 무엇을 입력해야 하는지(직무? 직원 이름?)가 placeholder 예시(리뷰어)뿐이고, 목록은 이미 고용된 직원 직무에서만 제안된다. 직원이 없으면 제안도 비어 있다. 맞지 않는 역할을 입력했을 때 어떻게 되는지 화면에서 알 수 없다(**확인 필요**). | `steps`, `stepRolePlaceholder`, `datalist` | 높음 |
| 10 | "끝나면 내 확인 🙋" | 의미는 직관적이지만 "누구 확인 → 어디에 뜨는가(결재함 '매뉴얼 단계 진행 확인')"가 연결되지 않는다. 체크 기본값 꺼짐 — 중요 단계에서 안 켜면 사람이 못 끼어든다. | `needsMyCheck`, `inbox.section.runs` | 중 |
| 11 | **"수정 필요하면 [되돌리지 않음 ▾]" + "최대 N번"** | 가장 어려운 항목. "되돌린다"가 **검토자가 반려하면 앞 단계로 다시 보낸다**는 뜻이라는 설명이 없다. 첫 단계는 선택지가 "되돌리지 않음" 하나뿐이라 의미 없는 드롭다운이다. 선택하면 "최대 [2] 번" 숫자칸이 갑자기 나타나 무엇의 횟수인지(수정 왕복 횟수) 모른다. 기본값 2·1~5 제한 이유도 안 보인다. | `onRevise`, `maxLoops*` | 높음 |
| 12 | 저장 | 비활성 이유가 없다(이름 규칙·설명·단계 이름/역할/지시 모두 필수 — 조건 5개). 어디가 비었는지 표시가 없어 "눌러도 안 되는 버튼"이 된다. 저장 후 "이제 교육해야 쓸 수 있다"는 다음 단계 안내가 없다. | `isValid`, `onClose` | 높음 |
| 13 | 교육(TrainDialog) | **"교육"이라는 개념이 가장 낯설다.** 매뉴얼을 만들어도 직원(또는 랩·팀)에게 교육하지 않으면 쓰이지 않는데, 목록 카드의 버튼 "🎓 교육 0"에서만 알 수 있다. 개인은 "직원"을 고르고 단계 진행은 "랩·팀"을 골라 **대상 유형이 달라 혼란**. 칩(둥근 버튼)이 선택/해제 토글이라는 표시가 테두리 색뿐이다. 이 창의 완료 버튼은 "교육하기"인데 해제도 같은 버튼으로 저장된다. | `train.*`, `trainedCount` | 높음 |
| 14 | 목록 카드 | 이름이 고정폭 영문 슬러그(`bug-report`)로만 나와 한글 업무명이 없다. 범위 라벨 "내 계정"/폴더 약칭이 작은 글씨 칩. 삭제는 `window.confirm`(브라우저 기본창). 편집·삭제는 아이콘뿐(툴팁은 aria-label). | 카드 마크업 | 중 |
| 15 | 휴대폰 화면 | 내 계정 매뉴얼은 PC에서만 고칠 수 있고, 위치 선택에서 "내 계정"이 비활성. 이유는 설명하지만 작은 글씨. | `IS_REMOTE_SCREEN` | 낮음 |

### 1-2. 용어 정리표

| 현재 | 문제 | 제안 |
|---|---|---|
| 매뉴얼(스킬) / "AI 쪽 이름: 스킬" | 괄호 설명이 오히려 개념을 늘림 | 화면에서 '스킬' 언급 삭제 (settings-simplify 용어집과 동일) |
| 단계 진행 매뉴얼 | 업무 용어 아님 | **"여러 명이 이어서 하는 업무"** / 개인 매뉴얼은 **"한 명이 하는 업무"** |
| 개인 매뉴얼 | "개인용"으로 오해(내 것 vs 직원 것) | "한 명이 하는 업무" |
| 맡을 역할 | 직무인지 사람인지 모호 | "누가 하나요? (직무)" + 직무 칩 선택 |
| 수정 필요하면 [되돌리지 않음] | 누가 판단하는지 없음 | "검토 후 고쳐야 하면 → [앞 단계로 다시 보내기]" |
| 최대 N번 | 무엇의 횟수인지 모름 | "다시 보내는 건 최대 N번까지" |
| 교육 | 무슨 효과인지 모름 | "쓸 수 있게 하기 / 누가 쓰나요?" |
| 저장 위치 / 프로젝트 · 경로 | 개발자식 | "어디서 쓰나요? — 모든 일에서(추천) / 특정 폴더 일에서만" |
| 이름 (영문 소문자·숫자·-) | 한글 불가 | **표시 이름은 한글 자유 + 파일명은 앱이 자동 생성** |

### 1-3. 입력 부담 계산 (단계 진행 매뉴얼, 3단계 기준)

- 필수 입력: 이름, 설명, 단계 3×(이름 + 역할 + 지시) = **11칸** (+ 선택 항목 약 10칸).
- 개인 매뉴얼: 이름·설명·절차 = 3칸이지만 절차는 번호 목록을 직접 작성.
- AI 초안을 쓰면 11칸이 한 번에 채워지지만, 이 길이 접근성이 낮다(위 4번).

### 1-4. 개편안

**원칙: "만드는 방법"을 3갈래로 바꾸고, 지금의 폼은 '직접 만들기'로 내린다.**

1. **진입 화면 분리 (가장 큰 효과)** — "+ 새 매뉴얼" 버튼 하나 → 아래 세 카드 중 선택
   - ✨ **말로 설명해서 만들기 (추천, 맨 앞)** — 한 칸 입력("예: 버그 신고 받아서 수정하고 확인하는 흐름") → AI가 종류·이름·설명·단계까지 초안. 직원이 없어도 쓸 수 있어야 함(앱 기본 AI 사용; 담당 직원 선택은 '자세히'로 이동).
   - 📋 **예시에서 고르기** — 템플릿 6~8개(글 쓰고 검토받기, 버그 접수→수정→확인, 보고서 작성→결재, 자료 조사→요약…). 고르면 폼이 채워진 상태로 열림.
   - ✍️ **직접 만들기** — 현재 편집 창.
2. **종류는 AI가 판단, 사용자는 질문으로 확인** — "한 명이 하나요, 여러 명이 이어서 하나요?" 한 문장 질문. 버튼명 대신 쉬운 질문.
3. **폼 기본/고급 분리**
   - 기본(항상 보임): 매뉴얼 이름(한글 가능), 언제 쓰는지, 단계(이름·누가·지시).
   - 고급(접힘, "더 자세히 설정"): 저장 위치(기본 "모든 일에서"), 파일 이름, 공통 안내, **수정 시 돌아갈 단계·최대 반복·내 확인**은 단계 카드 안 "이 단계 설정 ⌄"으로 접음. HireDialog에서 이미 쓰는 "자세히 설정/간단히 보기" 패턴 재사용(코드로 확인: `guideHint.hire.more/less`).
4. **단계 작성 마법사** — 단계를 한 번에 한 개씩: ① 무엇을 하나요 ② 누가 하나요(직무 칩) ③ 끝나면 내가 확인할까요(예/아니오) ④ 다음 단계 추가/완성. "수정 시 돌아가기"는 '검토 단계'를 만들 때만 "고칠 게 있으면 어느 단계로 다시 보낼까요?"로 노출. 완성 후 한 줄 흐름 미리보기(A → B → C ↩︎).
5. **저장 실패 이유 표시** — 비활성 대신 빠진 항목 목록("이름·단계 2의 지시가 비어 있어요") 또는 비어 있는 칸 강조.
6. **저장 직후 다음 단계 연결** — "저장했어요. 누가 쓰게 할까요?" → 교육 창으로 바로 이동(기본값: 모든 직원/랩). 교육 용어는 "쓸 수 있게 하기".
7. **빈 화면 안내** — 매뉴얼실 첫 화면에 한 줄 정의 + 예시 카드 3개 + "말로 설명해서 만들기" 큰 버튼.
8. **목록 카드** — 표시 이름(한글)을 제목, 파일명은 작은 글씨. 삭제는 앱 내 확인 창.

### 1-5. 매뉴얼 개편 우선순위

| 순위 | 항목 | 영향 | 난이도 | 비고 |
|---|---|---|---|---|
| 1 | 한글 이름 허용(표시 이름/파일명 분리) 또는 한글 입력 시 자동 변환 안내 | 매우 큼 | 중 | 저장 포맷·`NAME_RE`·AI 호출명 영향(확인 필요) |
| 2 | 저장 불가 사유 표시 + 직원 0명에서도 초안 기능 | 큼 | 하 | 화면 코드만 수정 |
| 3 | 진입 3갈래(말로/예시/직접) + 예시 템플릿 | 매우 큼 | 중 | 템플릿 문구 기획 필요 |

| 5 | 저장 위치 기본값 "모든 일에서" + 문구 | 중 | 하 | 기본값 변경 정책 확인 필요 |
| 6 | 저장 후 교육 창 연결, '교육' 용어 교체 | 큼 | 하 | |
| 7 | 단계 작성 마법사 | 큼 | 상 | 3·4가 먼저 되면 필요성 재평가 |

## 2부. 주요 화면 진단 (같은 관점)

관점: ① 처음 보고 이해되는가 ② 용어 ③ 빈 화면 안내 ④ 실수 방지. **모두 코드·사전으로만 확인.**

### 채용 — `HireDialog.tsx`
- 이미 "자세히 설정 ⌄"로 접혀 있어 기본 노출은 이름·직무·AI뿐 — **구성이 좋은 편.** "안 바꿔도 기본값으로 바로 일해요" 안내도 있음.
- 남은 문제: "AI" 라벨 단독(무엇을 고르는지 불명), "모델(성능 등급)", "결재 방식", "업무 지침"이 접힘 안에 있으나 용어가 어렵다(settings-simplify 용어집 적용 필요).
- "고용한 뒤에는 AI를 바꿀 수 없어요"가 선택 전에 보이지만 작은 글씨 — 되돌릴 수 없는 선택이므로 선택 옆 강조 필요.
- 직무 선택에서 "직접 입력" 시 어떤 직무가 효과 있는지 안내 없음. 이름 placeholder "김코드"는 개발자 느낌 → 직무별 예시 이름.
- 직원 마켓·파일 가져오기가 맨 위에 있어 처음엔 오히려 헷갈릴 수 있음(확인 필요).

### 업무 보드 — `BoardPage.tsx`
- 칸 4개(할 일·진행 중·검토·완료)와 칸별 힌트("담당자를 고르고 시작을 누르면 지시돼요")는 좋다.
- **카드 만들기→담당자 지정→시작** 3단계가 분리되어 있어 "카드만 만들고 안 시작하는" 실수가 생김. 카드를 올려도 일이 안 시작된다는 점이 설명문 한 줄에만 있음.
- "하위 업무", "기획 확인 대기", "취합 중", "매뉴얼 단계 진행"등 팀장 기획 용어가 카드 상태에 그대로 노출(채용 직후 사용자에겐 낯섦).
- 버튼 10종 이상(시작/모두 시작/멈추기/기획 멈추기/다시 진행…) — 멈추기·되돌리기는 확인창이 있어 실수 방지는 양호.
- 빈 보드에서 "무엇을 적으면 되는지" 예시 카드 없음(확인 필요 — 빈 화면 코드 미확인).

### 대화방(단체방) — `ChatPage.tsx`
- 메뉴 이름은 "단체방"인데 화면·사전은 "대화방/전체 방" — **이름 불일치.**
- 입력창 placeholder에 `@이름·@팀·@랩·@전체 로 지시 · 이미지 붙여넣기`를 모두 담아 길고 기호 중심. 멘션이 없으면 "알맞은 직원 한 명이 받아요"처럼 **누가 받는지 모르는 채 보낼 수 있다**(안내 문구는 있으나 작게 표시).
- "+" 메뉴가 "첨부·예약·매뉴얼·명령" 4개 묶음 — 명령/매뉴얼이 무엇인지 설명 없음(툴팁 문구가 길고 어려움).
- 직원이 "작업 중이에요 · 끝나면 보내거나 지금 끼어들 수 있어요"는 좋은 안내. 첫 대화에서 보낼 예시 문장 제안이 없음(확인 필요).
- 파일 약 900줄로 기능이 많음 — 처음 사용자는 기능의 절반을 못 볼 가능성.

### 결재함 — `InboxPage.tsx`
- 빈 화면 안내가 가장 잘 되어 있다("결재할 건이 없어요 🎉" + 왜 올라오는지 설명 + 직원이 없으면 별도 안내).
- 문제: "승인/반려/모두 승인"에서 **"모두 승인"의 위험 안내 부족** — 파일 수정·명령 실행을 한 번에 승인. 명령 내용이 비개발자에게 코드로 보임(개발 명령어 표시 — 해석 보조 필요, 확인 필요).
- 섹션명 "회의 결정 요청", "기획 확인", "매뉴얼 단계 진행 확인"이 서로 다른 종류의 판단인데 구분 설명 없음.
- "반려"는 일상어가 아님 → "거절/다시 하기"(사전 일관성 확인).

### 회의 — `MeetingPage.tsx`
- 설명문이 "2명 이상 불러 주제를 던지면 돌아가며 발언, 끝나면 회의록과 할 일 카드"로 결과까지 알려 주어 좋다.
- "발언 바퀴", "알아서 정해", "위임 · 결정자 기록 없음" 등 회의 내부 용어가 어렵다. "발언 바퀴"는 "몇 번 돌아가며 말하게 할지"로 풀어야 함.
- 직원이 없으면 "고용한 직원이 있어야 회의를 열 수 있어요"로 막히지만 **채용 버튼 연결은 확인 필요.**
- "발언할 때마다 AI 사용량이 든다" 안내는 있으나 바퀴 수 선택 옆 예상 사용량 표시 없음 → 실수 방지 약함.
- 최소 인원 2명 규칙은 안내됨.

### 지식(지식 창고) — `KnowledgePage.tsx`
- 메뉴 이름 "지식 창고" vs 버튼 "지식 남기기" — 개념은 좋으나 **비개발자가 직접 써야 할 이유**가 약함(직원이 배운 점을 자동 쌓는 게 핵심).
- 빈 화면 문구는 어떻게 쌓이는지 설명(양호). "대표 피드백·기획 피드백" 설명 필요.
- 편집창의 "참고 문서에 두고 연결하면 토큰을 아낄 수 있어요" — **토큰**, "전체 파일 위치", "태그(쉼표로 나눠요)" 용어 어려움. 지식 종류 구분("종류")이 무엇이 다른지 예시 없음(확인 필요).

### 상점 — `ShopPage.tsx`
- "직원이 일할수록(토큰 1만 = ₩10만) 회사 자금(게임 속 돈)이 쌓여요" — **토큰·₩가 섞여 실제 돈으로 오해**할 수 있음(괄호로 게임 속 돈 표기는 있음).
- 구매 외에 "직원에게 쓰게 하기", "서랍", "놓기", "레벨 N부터 잠김" 등 **게임 개념이 한꺼번에** 등장. 업무와 무관한 선택 기능임을 처음에 밝히지 않음.
- 구매는 확인 필요(확인창 존재 여부 코드 미확인). "지금 살 수 있는 것만" 필터는 좋음.
- 우선순위는 낮음(업무 기능 아님).

### 온보딩 / 코치 투어 — `Onboarding.tsx`, `CoachTour.tsx`, `Tutorial.tsx`
- 5단계(환영→로그인→폴더→첫 업무→준비 완료)와 "준비 점검 n/3", 진행 점 표시, 건너뛰기 가능 — **구조는 좋다.**
- 첫 업무 시나리오("이 폴더에 뭐가 있는지 3줄로", "AI Office로 맡길 만한 일 추천")는 폴더 없이도 가능해 비개발자 친화적. 비용 안내("사용량이 조금 쓰여요")도 좋음.
- 문제: 폴더 단계 설명 "프로젝트 폴더", "기본 작업 폴더"는 개발자 용어. 이후 **채용·매뉴얼·결재 개념은 카드 3장(고용·지시·결재)만** 보여 줌 — 매뉴얼·회의·지식은 온보딩에서 한 번도 안 나옴.
- 튜토리얼(연습 회사, 토큰 안 씀, 1분)은 훌륭하나 **온보딩 안에서 부가 버튼("연습 튜토리얼 해 보기")**로만 보여 놓치기 쉬움.
- 코치 투어는 "n장 · 이름 / 다음 / 이 장 건너뛰기 / 그만 보기" 구성. 재실행 위치는 "설정 › 안내"(설정 화면이 복잡해 찾기 어려움).

## 3부. 전체 개선 우선순위 표 (영향 × 난이도)

영향·난이도는 코드 읽기 기반 추정이며 실제 사용 데이터·구현 견적 검증 필요.

| 순위 | 화면 | 개선 | 영향 | 난이도 | 점수 |
|---|---|---|---|---|---|
| 1 | 매뉴얼 | 저장 불가 이유 표시 + 직원 0명에서도 AI 초안 | 큼 | 하 | ★★★ 빠른 승리 |
| 2 | 매뉴얼 | 한글 이름 허용(표시 이름/파일명 분리) | 매우 큼 | 중 | ★★★ |
| 3 | 매뉴얼 | 진입 3갈래 + 예시 템플릿, 직접 만들기 폼에서 고급 접기 | 매우 큼 | 중 | ★★★ |
| 4 | 매뉴얼 | "교육" 개념 용어 교체 + 저장 후 바로 연결 | 큼 | 하 | ★★★ |
| 5 | 전체 | 빈 화면 안내(매뉴얼실·업무 보드·대화방·지식) 한 줄 정의 + 첫 행동 버튼 | 큼 | 하 | ★★★ |
| 6 | 결재함 | "모두 승인" 경고, 명령 내용 쉬운 설명 | 큼 | 중 | ★★ |
| 7 | 온보딩 | 폴더·프로젝트 용어 완화, 매뉴얼·회의 개념 카드 추가, 연습 튜토리얼 눈에 띄게 | 중 | 하 | ★★ |
| 8 | 업무 보드 | 카드 생성 후 "시작" 유도, 팀장 기획 상태 용어 풀이, 예시 카드 | 중 | 중 | ★★ |

| 13 | 지식 | 토큰·태그·종류 용어, 쌓이는 원리 설명 | 낮음 | 하 | ★ |

### 공통 패턴 (개선 한 번에 여러 화면 해결)
1. **빈 화면 안내 표준화** — 결재함 방식(무엇 / 언제 생김 / 다음 행동 버튼)을 매뉴얼실·보드·대화방·지식에 복제.
2. **자세히 설정 접기 패턴 확대** — HireDialog 패턴을 매뉴얼 편집, 회의 개설, 지식 편집에 재사용.
3. **용어집 일괄 적용** — `../settings-simplify/glossary.md`의 용어(토큰→사용량, 스킬 삭제, MCP→연결된 서비스)를 모든 화면에 적용, 4개 언어 사전 동시 수정.
4. **저장·시작 버튼 비활성 시 이유 표시** — 매뉴얼 저장, 회의 개설, 업무 시작 등.

### 확인 필요 / 한계
- 앱을 실제로 열지 않았다. 실제 첫 사용자 관찰(5명 내외) 필요.
- 역할이 고용 직원 직무와 일치하지 않을 때의 동작, 직원이 0명일 때 초안 기능 대체 가능 여부(백엔드 `draftManual` 필요 조건)는 코드 미확인.
- 업무 보드 빈 화면, 상점 구매 확인창, 회의의 채용 연결은 일부 코드만 보고 판단했다.
- 영향·난이도 추정은 기획자 판단이며 개발팀(정리드) 견적 필요.

### 제안하는 다음 단계
1. 우선순위 1·2·3·4번(매뉴얼)을 한 묶음으로 설계 → 이디자(진입 3갈래·접기 시안), 정리드(이름 분리 가능성 조사).
2. 5번(빈 화면 안내 표준화)은 별도 작은 업무로 분리.
